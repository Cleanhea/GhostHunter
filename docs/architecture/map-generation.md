## 1. 시스템 개요

### 1.1 시스템 목적

맵 생성 시스템은 고정된 집 구조 안에서 방과 일부 오브젝트를 랜덤하게 구성하여 같은 맵을 반복 플레이하더라도 매 판 다른 공간 구성을 제공하고자 하는 시스템이다.

집 전체의 구조와 방의 위치, 이동 동선은 레벨 디자이너가 미리 제작한 형태를 그대로 사용하고자 한다. 이를 통해 플레이어의 이동 동선, 귀신 등장 연출, 추격 상황 등 주요 레벨 디자인을 의도한 형태로 유지한다.

대신 각 방에는 해당 방 카테고리에 맞는 여러 종류의 방 프리셋 중 하나가 랜덤으로 배치된다.

예를 들어 하나의 집이 아래와 같이 구성되어 있다고 가정해보자,

- 거실 1개
- 주방 1개
- 욕실 2개
- 침실 3개
- 창고 1

⇒ 각 침실 자리에는 준비된 프리셋 중 랜덤으로 선택되어 배치된다

ex)

```
침실 슬롯 1 → 침실 프리셋 B
침실 슬롯 2 → 침실 프리셋 E
침실 슬롯 3 → 침실 프리셋 A
```

따라서 집에서 플레이어가 전체적으로 이동할 수 있는 구조는 동일하지만, 실제 각 공간의 모습과 일부 플레이 환경은 매 판 달라지게 설계하고자 한다.

또한 방 내부의 벽, 문, 대형 가구 등 방의 기본적인 형태를 구성하는 요소는 각 방 프리셋에 고정하여 배치한다.

반면 쓰레기통, 쿠션, 박스, 협탁 등의 소형 오브젝트와 일부 게임 콘텐츠(귀신, 청소)는 방 내부에 지정된 위치 중 랜덤하게 생성하고자 한다.

> **목표 플레이 경험**
>
> 이를 통해 다음과 같은 플레이 경험을 제공하는 것을 목표로 한다.
>
> - 집 전체 구조는 고정이어서 익숙해질 수 있지만, 각 방의 내부 모습은 매 판 달라지게 하여 다른 판이라고 인식하게 한다.
> - 청소해야 하는 공간과 오브젝트의 구성이 달라진다.
> - 같은 집을 반복 플레이하더라도 탐색 과정에 일정 수준의 변화를 제공한다.
> - 고정 맵의 레벨 디자인 장점과 랜덤 생성의 반복 플레이성을 동시에 확보한다.

## 2. 맵 구성 구조

### 2.1 맵 구성 단위

#### House

하나의 집 전체를 House라고 정의하고자 함.

ex) `House_01`

#### Room Slot & Room Pool

집 안에 어떤 종류의 방이 들어갈 지 미리 자리를 지정해놓은 것을 Slot이라고 정의하고자 함.

Bedroom의 3가지 버전을 만들었다고 가정한다면, 이 버전을 모아놓은 목록을 BedRoom Pool이라고 정의함.

예를 들어, 집에 침실이 3개 필요하다고 가정해보면

> **[House]**
>
> Bedroom Slot 01
> Bedroom Slot 02
> Bedroom Slot 03

이렇게 나타낼 수 있음. 즉 침실이 들어갈 자리 3개의 슬롯

Pool의 예시로는 침실로 사용할 수 있는 디자인이 5개 있다면

> **[Bedroom Pool]**
>
> - Bedroom_A
> - Bedroom_B
> - Bedroom_C
> - Bedroom_D
> - Bedroom_E

#### Room Preset

방의 기본 단위. ex) Bedroom_A, Bedroom_B, Bedroom_C

프리셋은 제작 후 그림으로 첨부할 예정.

- 공간 구성: 거실 1 / 주방 1 / 욕실 1 / 침실 2 / 창고 1

| 공간 | 도면 (가로 × 세로) | 도면 높이 | 도면 기준 구현값 | 실제 크기 (평면 ×2) |
|---|---|---|---|---|
| 침실1 | 3.8m × 3.6m | 2.4m | 3.8 × 3.6 ✔ | **7.6 × 7.2** |
| 침실2 | 3.4m × 3.2m | 2.4m | **3.8 × 3.6** — 슬롯은 프리셋 치수로 통일 | **7.6 × 7.2** |
| 주방 | 3.6m × 3.2m | 2.4m | 4.93 × 3.6 — 침실 두 칸을 뺀 나머지 흡수 | 9.86 × 7.2 |
| 거실 | 5.0m × 4.5m | 2.6m | 8.07 × 4.21 | 16.14 × 8.42 |
| 욕실 | 2.4m × 2.2m | 2.3m | 2.4 × 2.32 | 4.8 × 4.64 |
| 창고 | 2.2m × 1.8m | 2.2m | 2.4 × 1.8 ✔ | 4.8 × 3.6 |

높이는 전 구역 **2.5m 단일값**이다(도면은 방마다 2.2~2.6m로 다르지만 프로토타입은 통일).
평면 배율을 올려도 높이는 그대로다.

**집 세로가 도면보다 짧은 이유(10.4 → 8.0m, 실제 16.0m)** — 서비스 열(욕실+창고)을 도면대로
남쪽 외벽까지 다 쓰면 창고가 4.8 × 8.4m, 폭보다 두 배 가까이 긴 복도 같은 방이 된다.
창고 세로를 도면값(1.8m)으로 지키고 **남쪽 외벽을 창고 남쪽 벽선에 맞춰 끌어올렸다.**
그래서 밑 벽은 거실과 창고를 가로질러 한 줄로 이어지고, 줄어든 몫은 전부 거실 깊이에서 빠졌다.
집 실루엣에 남는 홈은 도면의 남서쪽 L자 하나뿐이다.

`OuterSouth`는 그래서 도면값이 아니라 **창고 남쪽에서 역산한 값**이다
(`BathroomSouth - 벽두께 - 창고 세로`). 검증도 상수와 실제 벽 위치를 맞대 보는 방식이라
남쪽 벽을 옮기면 기대값이 같이 움직인다.

도면의 방 치수를 다 더하면 외곽 12.8m × 10.4m 가 되지 않는다(도면 자체가 맞지 않는다).
프로토타입은 **가로 12.8m 와 침실 슬롯 3.8 × 3.6m 를 고정값으로 잡고**, 나머지 방이
남는 면적을 가져가게 했다. 벽 두께는 0.18m, 좌표는 전부 벽 중심선 기준이다
(`Assets/Scripts/Editor/HousePrototypeBuilder.cs` 상단 상수).

### 평면 배율 (`HousePrototypeBuilder.MapScale`)

씬에 들어가는 집은 도면 **평면(X·Z)에만 ×2**를 먹인 크기다. 외곽 25.6 × 16.0m,
침실 슬롯 7.6 × 7.2m, 주방 9.86m 폭, 거실 16.14 × 8.42m. 같은 크기의 가구를 더 넓은 방에서
던져 보려고 넣은 값이다.

| 배율을 받는 것 | 배율을 받지 않는 것 |
|---|---|
| 벽 중심선 좌표, 방 크기, 바닥 슬래브, 걸레받이 길이 | 벽 높이 2.5m, 벽 두께 0.18m |
| 문·창·붙박이·계단의 **자리** | 문 폭(1.2 / 0.9 / 1.4 / 1.5m)과 높이 2.04m, 창 크기 |
| 조명 사거리·밝기(각 ×2) | 조명 높이, 붙박이·계단·가구 치수 |
| | 플레이어, 이동/점프, 투척 사거리 |

- **트랜스폼 스케일은 쓰지 않는다.** 그룹에 스케일을 주면 개구부 폭과 벽 높이까지 같이 늘어난다.
  배율은 상수 정의부에서 **좌표에만** 곱한다 — `MapScale`이 붙은 상수가 평면 좌표,
  안 붙은 상수가 사람 기준 치수다.
- 개구부는 "자리 × 배율 + 원래 폭"으로 잡는다. 예: 침실 문은 칸막이 안쪽 면에서 0.2m 띄운
  자리에 폭 1.2m 그대로 뚫는다. 벽 조각의 끝점은 이 개구부에서 역산한다.
- 붙박이(주방 카운터·욕실)는 크기가 그대로라, 좌표를 방 안쪽 **면 기준**으로 잡아 벽을 따라간다.
- 생성 검증이 벽 높이 2.5m와 침실 문 1.2 × 2.04m를 직접 확인한다. 배율이 높이나 문으로
  새면 여기서 걸린다.
- 집이 4배 넓어진 만큼 이동 시간이 늘고, 투척 사거리(조준 12m / 홀드 15m)가 상대적으로
  짧아진다. 체감이 나쁘면 `PlayerMoveSettings` · `FurnitureThrowSettings`를 따로 손본다.

**배율 비교용 집** — 배율이 정말 필요한지 눈으로 보려고, 같은 도면을 배율 없이(×1) 지은 집을
House_01 동쪽 3m 옆에 하나 더 세워 뒀다(`House_01_OriginalScale_Right`). 이 집은 방 슬롯도
프리셋도 쓰지 않고 **생성 도구가 방마다 가구를 깔아 준다** — 도면 치수에서 침실·주방·거실이
가구로 얼마나 차는지가 이 집의 전부이기 때문이다. 침실 두 칸은 도면의 Bedroom_A · Bedroom_C
구성을 그대로 쓴다. 자세한 것은 [06-furniture-physics.md](furniture-physics.md#씬-배치-prototype).

| 개구부 | 폭 | 위치 |
|---|---|---|
| 문 | 1.2m | 침실1, 침실2 |
| 문 | 0.9m | 욕실, 창고 |
| 실내 이동문 | 1.4m | 침실1 ↔ 주방 ↔ 침실2 연결부 |
| 현관문 | 1.5m | 거실 남측 |

도면 비고

- 모든 치수: 내부 실측 기준 (m)
- 표기 치수: 가로 × 세로, 높이
- 문 폭: 1.2m / 0.9m
- 실내 이동문: 1.4m
- 현관문: 1.5m

> 슬롯을 프리셋 최대값에 맞춰 다시 키워야 한다.

## 3. 맵 생성 규칙

집에 있는 방들을 어떻게 랜덤으로 선택할 건지 설명하고자 함.

### 3.1 집 하나 당 기본 구성

- House 1. 거실 1, 주방 1, 욕실 1, 침실 2, 창고 1
- House 2. 거실 1, 주방 1, 욕실 2, 침실 3, 창고 1
- House 3. 거실 1, 주방 1, 욕실 1, 침실 2, 지하실 1

⇒ 총 3가지 집을 제작하려고 함.

### 3.2 Room Preset Pool

각 방 종류 별 Slot을 두고 게임 시작할 때 집 하나의 기본 구성에 맞춰 슬롯 안에서 방을 고르고자 함.

ex) 침실 A, 침실 B, 침실 C, 침실 D, 침실 E ⇒ Bedroom Slot

Bedroom Slot → 침실 A, 침실 B를 고르고자 함.

### 3.3 주의 해야 할 점: 중복 허용 금지

```
침실 1 → 침실 A
침실 2 → 침실 A
침실 3 → 침실 A
```

⇒ 같은 집에서는 방 프리셋 중복 금지.

## 4. 방 프리셋 구성

방 안에 고정될 요소와 랜덤하게 나타낼 요소를 나누고자 한다.

### 4.1 고정 요소

- 집 전체 구조
- 집 전체 크기
- 각 방의 위치 및 용도
- 복도 및 방 연결 구조
- 출입구 및 문 위치
- 방 프리셋의 기본 구조
- 벽, 바닥, 창문
- 방을 구별할 수 있는 주요 대형 가구 (ex_ 화장실: 변기, 거실: 쇼파 등)

### 4.2 랜덤 요소

반복 플레이 시 공간의 변화를 제공할 수 있는 요소는 랜덤으로 결정하고자 함

- 각 Room Slot에 배치되는 Room Preset
- 소형 가구 및 소형 오브젝트
- 장식 및 잡동사니
- 청소 관련 콘텐츠 (ex_ 청소해야 할 가구, 물품들)
- 귀신 관련 콘텐츠

## 5. Spawn Point

Room Preset을 제작할 때 방 내부의 적절한 위치에 여러 개의 Spawn Point를 지정해놓고자 한다.

맵 생성 시 모든 Spawn Point에 오브젝트를 생성하는 것이 아니라, Spawn Point의 종류와 생성 조건에 따라 일부 지점만 선택하여 오브젝트를 생성한다.

예시: Bedroom_A

- 바닥 Spawn Point 6개 → 박스, 쓰레기통, 쓰레기봉투, 빨래바구니, 소형 가구
- 책상 위 Spawn Point 2개 → 컵, 책, 병, 휴지, 작은 소품 등
- 벽 Spawn Point 4개 → 액자, 거울, 불 스위치, 창문, 벽 장식 등
- 콘텐츠 Spawn Point → 청소 대상, 귀신 관련 오브젝트

맵 생성 시 위 Spawn Point 중 일부가 선택되며, 선택된 Spawn Point에 해당 종류의 오브젝트가 랜덤 생성된다.

### Spawn Point 선택 규칙

Room Preset에는 실제 생성할 오브젝트 수보다 많은 Spawn Point를 미리 배치하고, 맵 생성 시 각 Spawn Type별로 정해진 개수만큼 Spawn Point를 랜덤 선택한다.

선택되지 않은 Spawn Point에는 아무 오브젝트도 생성하지 않는다.

### 예시)

Bedroom_A의 바닥에 다음과 같이 Spawn Point가 배치되어 있다고 가정한다.

- Floor Spawn Point: 7개
- 실제 들어갈 오브젝트 개수: 3개

### Spawn Type별 개수 설정

Spawn Point 선택 개수는 Spawn Type마다 별도로 설정함.

| Spawn Type | 후보 Spawn Point | 실제 선택 수 |
|---|---|---|
| Floor | 6~7개 | 3개 |
| Desk | 2~3개 | 1개 |
| Sofa | 2~3개 | 1개 |
| Wall | 3~4개 | 1~2개 |

맵 생성 시:

```
Floor Spawn Point 7개 확인
↓
7개 중 서로 다른 Spawn Point 3개를 랜덤 선택
↓
선택된 각 Spawn Point에서 Floor Spawn Pool 조회
↓
Spawn Pool에서 오브젝트를 랜덤 선택
↓
선택된 3개의 위치에 각각 오브젝트 생성
```

결과 예시:

- Floor_01 → 이삿짐 박스
- Floor_04 → 쓰레기봉투
- Floor_06 → 빨래바구니

나머지 Floor_02 / 03 / 05 / 07에는 아무것도 생성하지 않는다.

또한, Bedroom이 생성될 때마다 6~7개의 후보 위치 중 서로 다른 3곳이 랜덤으로 선택되고, 해당 위치에 박스, 쓰레기봉투, 빨래바구니, 쓰레기통 등의 작은 오브젝트가 생성된다.

예:

```
1회차   Floor_01 / Floor_03 / Floor_06 선택
2회차   Floor_02 / Floor_04 / Floor_07 선택
3회차   Floor_01 / Floor_05 / Floor_07 선택
```

같은 Bedroom_A를 사용하더라도 작은 오브젝트가 놓이는 위치가 플레이마다 달라질 수 있다.

### 5.1 방 내부 오브젝트 결정 프로세스

**방 내부 오브젝트 결정**

예시)

```
Bedroom_B

Floor Spawn 01
      ↓
Floor Object Pool
      ↓
박스 선택

Sofa Spawn 01
      ↓
Sofa Object Pool
      ↓
쿠션 선택
```

## 6. 콘텐츠 배치 시스템

일반 오브젝트와 게임 콘텐츠 분리

ex) 청소 대상, 귀신 관련 오브젝트, 은신용 요소, 필요한 물건 등 콘텐츠에 필요한 오브젝트는 일반 오브젝트와 분리해야 함.

### 6.1 Content Spawn Point

한 집에는 콘텐츠(ex_귀신 집착 오브젝트)가 반드시 1~3개 생성된다.

해당 오브젝트는 Content Spawn Point에 중 하나에 생성된다.

청소 대상은 각 방에 최소 2개 이상 존재해야 한다.

### 6.2 콘텐츠 생성 제한

> **미결정:** 원문에서 항목만 있고 내용은 아직 작성되지 않았다.

### 6.3 게임 콘텐츠 결정 프로세스

**게임 콘텐츠 결정**

일반 인테리어 오브젝트 배치가 완료된 후 청소 및 귀신 등 실제 플레이에 필요한 콘텐츠를 생성한다.

```
완성된 Room
↓
Content Spawn Point 확인
↓
콘텐츠 생성 조건 확인
↓
청소 / 귀신 / 특수 콘텐츠 배치
↓
검증
```

최종적으로 다음과 같은 계층으로 맵이 생성된다.

```
House
│
├─ Room Slot
│    │
│    └─ Room Preset
│          │
│          ├─ Fixed Object
│          │
│          ├─ Spawn Point
│          │     │
│          │     └─ Random Object
│          │
│          └─ Content Spawn Point
│                │
│                └─ Game Content
│
├─ Room Slot
│    └─ Room Preset
│          └─ ...
│
└─ Room Slot
     └─ Room Preset
          └─ ...
```

### 구현 현황 (2026.08.16)

침실 슬롯 랜덤 배치까지 Game 씬(구 Prototype)에 들어갔다. Spawn Point / 소형 오브젝트 랜덤은 아직이다.

| 요소 | 씬 오브젝트 | 상태 |
|---|---|---|
| Room Slot | `House_01/RoomSlots/BedroomSlot_01·02` | 침실 2개(7.6 × 7.2m). 방 중심(바닥면), 회전 없음(+Z가 북쪽) |
| Room Pool | `Room_Presets/BedroomPreset_A·B·C` | 집 남쪽 바깥(z ≈ -20) 전시장에 3종. 가구 A 12 / B 15 / C 13개 |
| 랜덤 선택 | `RoomSlotAssigner` | 세션 시작 시 서버가 풀을 섞어 슬롯당 하나씩 |
| Spawn Point | — | 미구현. 자리만 **고정 배치 소품**으로 미리 채워 두었다(아래) |

**Spawn Point 자리는 소품 큐브로 미리 채워 두었다** — 랜덤 선택 로직은 아직 없으므로, 프리셋마다
바닥 Spawn Point 자리(상자 · 쓰레기통 · 빨래바구니)와 책상/협탁 위 Spawn Point 자리(컵 · 책 ·
화장품 상자)에 소품을 **고정으로** 놓았다. 10장 표대로 실제 메시 대신 큐브 하나로 때운 것이고,
전부 던질 수 있는 물리 가구다. 나중에 Spawn Point 시스템이 들어오면 이 좌표가 그대로
후보 지점이 된다. 위에 얹는 소품은 상판 윗면을 지지면 높이로 넘겨 정확히 앉힌다
(`MakePhysical(..., supportHeight)`) — 몇 cm 떠 있으면 세션 시작과 동시에 떨어진다.

**가구 원본** — 프리셋에 놓인 가구는 전부 `Assets/Prefabs/Furniture/` 프리팹의 인스턴스다
(MIG-6). 같은 종류는 어느 방에 있든 같은 프리팹에서 나오므로, 치수를 고치려면 프리팹만
고치면 된다. 벽 방향이 다른 자리는 치수가 아니라 회전으로 맞춘다.

**배치 방식** — 프리셋을 프리팹으로 스폰하지 않는다. 맵 가구는 전부 씬에 놓인 `NetworkObject`라
호스트가 시작될 때 한꺼번에 스폰되는데, 프리셋을 프리팹으로 만들면 가구가 중첩 NetworkObject가
되고 스폰 경로가 둘로 갈린다. 대신 **이미 스폰된 가구를 서버가 슬롯으로 옮긴다**
(`RoomPreset.ApplyTo`). 클라이언트는 `NetworkTransform` 복제로 같은 결과를 보고, 늦게 들어와도
스폰 시점의 위치를 그대로 받으므로 "어떤 프리셋이 뽑혔는지"를 따로 동기화할 필요가 없다.

**중복 없음** — 풀을 Fisher-Yates로 섞어 앞에서부터 슬롯에 하나씩 준다. A·A 같은 조합은 나오지
않는다. 슬롯 수보다 프리셋이 적으면 배정 자체가 불가능하므로 생성 검증이 막는다.
세션을 다시 시작하면 먼저 모든 프리셋을 전시 자리로 되돌린 뒤 다시 뽑는다.

**문 동선 제약** — 침실1의 문은 방 서쪽 끝에서 6.2m(동쪽 칸막이 쪽), 침실2의 문은 1.42m
지점에 있다(도면의 L자 외곽과 욕실 위치 때문에 두 슬롯의 문 위치를 맞출 수 없다). 어느 슬롯에
뽑혀도 문이 가구를 쓸고 지나가지 않도록, 프리셋은 **방 남쪽 1.11m 띠를 비운다**(문짝 1.2m가
그리는 사분원). 예외는 두 문 사이 가운데 띠(방 중심 기준 x −1.18 ~ +2.40)로, 어느 문도
지나가지 않아 남쪽 벽까지 쓸 수 있다 — Bedroom_C의 상자가 여기 있다. 전시장 바닥에 이 금지
구역을 어두운 띠로 깔아 뒀다(`DoorSweep_KeepOut`).

**도면과 달라진 점** — 슬롯이 7.6 × 7.2m로 커지면서 세 프리셋 모두 도면의 가구 구성을
그대로 담는다(B의 서랍장·발치 협탁 포함). 대신 방이 가구보다 훨씬 커서 남쪽 절반이 비었기에,
**도면에 없는 가구를 프리셋마다 두 개씩 더 넣어** 빈 벽을 채웠다 —
A에 서랍장·책장, B에 책장·수납함, C에 옷장·협탁. 도면 가구는 그대로 두고 빈 벽만 채운 것이라
방의 성격(A 1인용 침실 / B 부부 침실 / C 아이 방)은 유지된다.
남은 여백은 위의 고정 배치 소품이 메운다.

프리셋 가구를 늘릴 때 지켜야 할 것:

- 남쪽 1.11m 띠는 그대로 비운다(두 문 사이 가운데 띠 x −1.18 ~ +2.40 제외).
- 북쪽 벽 가운데 창(폭 1.45m, 방 중심 기준 x ±0.725)은 키 큰 가구로 막지 않는다.
- 검증이 프리셋 × 슬롯 전 조합을 실제로 놓아 보므로, 겹치면 생성 단계에서 걸린다.

**생성 검증** — `HousePrototypeBuilder.ValidateRoomPresets`가 프리셋 × 슬롯 **전 조합**을 실제로
배치해 보고 (1) 벽·가구 겹침 (2) 문짝이 닫힘~열림 사이 어느 각도에서도 가구를 쓸지 않는지를
검사한다. 뽑기는 런타임이라 "가끔 나오는 조합만 깨지는" 버그를 여기서 잡지 않으면 알아채기 어렵다.

**검증할 로직**

```
House
↓
Room Slot 읽기
↓
카테고리에 맞는 Room Pool 검색
↓
Room Preset 랜덤 선택
↓
Slot에 정상 배치
↓
각 Room의 Spawn Point 검색
↓
Spawn Point 타입에 맞는 Object Type 검색
↓
랜덤 Object 생성
↓
Content Spawn Point에 임시 콘텐츠 생성
↓
검증
```

### 프로토타입에서 확인할 것

**1. Room 랜덤 선택이 제대로 되는가**

침실 슬롯 3개가 있다면:

```
1회
Bedroom A / C / D

2회
Bedroom B / D / A

3회
Bedroom C / A / B
```

처럼 의도한 규칙대로 뽑히는지.

**2. Spawn Point 방식이 실제로 편한가**

기획 단계에서는 Spawn Point가 좋아 보여도 직접 몇 개 만들어보면

> "어? 책상 위 / 바닥 / 벽 이렇게 나누니까 너무 많은데?"

또는 반대로

> "Floor 하나로 묶으니까 이상한 배치가 너무 많이 나오네."

같은 문제가 나올 수 있음.

**3. Object Pool 구조가 적절한가**

예를 들어 처음에는

```
Floor Object Pool
```

하나면 될 것 같았는데 테스트하다 보면

```
Floor_Corner
Floor_Open
BedSide
TableTop
Shelf
```

처럼 세분화할 필요가 있다는 걸 알 수도 있어.

**4. 재생성했을 때 충분히 달라 보이는가**

이게 아주 중요함.

기획상으로는

> 방 랜덤 + 소형 오브젝트 랜덤 = 매 판 다른 느낌

이라고 생각했는데 직접 20번 생성해보니까

> "별 차이 없는데?"

가 될 수도 있거든.

그럼 프리셋 종류를 늘리거나 랜덤 요소를 더 추가해야 한다는 걸 일찍 알 수 있어.

## 11. 맵 생성 전체 프로세스

```
[게임 시작]
      │
      ▼
① House 선택 / 불러오기
      │
      │  집의 전체 구조 및 Room Slot 확인
      │
      │  ex)
      │  ├─ LivingRoom Slot × 1
      │  ├─ Kitchen Slot × 1
      │  ├─ Bathroom Slot × 2
      │  └─ Bedroom Slot × 3
      │
      ▼
② Room Slot별 방 카테고리 확인
      │
      │
      ├─ LivingRoom Slot → LivingRoom Pool
      ├─ Kitchen Slot    → Kitchen Pool
      ├─ Bathroom Slot   → Bathroom Pool
      └─ Bedroom Slot    → Bedroom Pool
      │
      ▼
③ 각 Pool에서 Room Preset 랜덤 선택
      │
      │  ex)
      │
      │  Bedroom Pool
      │  [A / B / C / D / E]
      │
      │  Bedroom Slot 01 → B
      │  Bedroom Slot 02 → E
      │  Bedroom Slot 03 → A
      │
      ▼
④ 선택된 Room Preset 배치
      │
      │
      │  Room Preset에 포함된 고정 오브젝트, 요소 잘 붙어있나 확인
      │
      ├─ 벽 / 바닥 / 천장
      ├─ 문 / 창문
      ├─ 대형 가구
      └─ Spawn Point
      │
      ▼
⑤ Room 내부 Spawn Point 확인
      │
      │
      ├─ Table Spawn Point
      ├─ Sofa Spawn Point
      ├─ Cleaning Spawn Point
      └─ Content Spawn Point
      │
      ▼
⑥ 소형 오브젝트 Pool 불러오기
      │
      │  Spawn Point 종류에 따라
      │  생성 가능한 오브젝트 후보 확인
      │
      │  ex)
      │
      │  Floor Spawn Point
      │      ↓
      │  [박스 / 쓰레기통 / 소형가구]
      │
      │  Sofa Spawn Point
      │      ↓
      │  [쿠션 / 담요]
      │
      ▼
⑦ 소형 오브젝트 랜덤 선택 및 배치
      │
      │
      │  생성 개수 / 확률 / 중복 조건 적용
      │
      └─ 각 Spawn Point에 오브젝트 배치
      │
      ▼
⑧ 게임 콘텐츠 배치
      │
      │
      ├─ 청소 대상
      ├─ 귀신 관련 오브젝트
      ├─ 집착 오브젝트
      └─ 기타 특수 콘텐츠
      │
      │  각 콘텐츠의 조건에 맞는
      │  Content Spawn Point에 배치
      │
      ▼
⑨ 생성 결과 검증
      │
      ├─ 모든 Room Slot이 채워졌는가?
      ├─ 필수 콘텐츠가 존재하는가?
      ├─ 문 / 이동 경로가 막히지 않았는가?
      ├─ 오브젝트가 겹치지 않았는가?
      └─ 콘텐츠 생성 조건을 만족하는가?
      │
      ├───────────────┐
      │ 정상          │ 문제 발생
      ▼               ▼
⑩ 맵 생성 완료     문제 요소 재추첨 / 재배치 후 다시 검증
      │
      ▼
[플레이 시작]
```
