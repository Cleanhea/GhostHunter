# ADR-0008: 플레이어 이동만 소유자 권위로 둔다

- **상태**: Accepted
- **날짜**: 2026-08-19
- **결정자**: MinGiHong
- **관련**: [ADR-0010](ADR-0010-server-authoritative-furniture-physics.md), [../networking.md](../networking.md), [../player-controller.md](../player-controller.md)

## 배경 (Context)

[../networking.md](../networking.md) §1은 "서버 권위가 기본이고 클라이언트는 상태를 확정하지 않는다"를
MUST로 건다. 가구 물리도 그 원칙을 따른다([ADR-0010](ADR-0010-server-authoritative-furniture-physics.md)).

그런데 플레이어 이동은 프로토타입 시기부터 **소유자 권위**(`ClientNetworkTransform`)로 구현되어 있다.
당시 근거는 "프로토타입이라 치팅은 문제가 아니다"였다. 본 프로젝트로 승격하면서 그 근거가 사라졌으므로
결정을 다시 세우거나 되돌려야 한다.

## 검토한 선택지 (Options)

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. **소유자 권위 유지** (`ClientNetworkTransform`) | 로컬 조작 지연 0. 구현 완료 | 이동에 관해 클라이언트를 신뢰한다 (텔레포트·속도 핵 가능) |
| B. 서버 권위 + 예측 없음 | 원칙 일관 | **입력 → 화면 반응에 RTT가 그대로 실린다.** 1인칭에서 조작 불능 수준 |
| C. 서버 권위 + 클라이언트 예측/재조정 | 원칙 일관 + 지연 은폐 | 구현 규모가 크다. `CharacterController` 기반 예측·리컨실리에이션 직접 작성 |

## 결정 (Decision)

**A를 유지한다.** 단, 근거를 "프로토타입이라서"가 아니라 아래로 다시 세운다.

> **예측·보정 없는 서버 권위 이동은 왕복 지연이 그대로 조작감에 실린다.**
> Steam SDR 릴레이 경유에서 이 손실은 1인칭 게임에서 수용 불가능하고,
> 이 게임의 치팅 노출 면적에 비해 방어 이득이 작다.

**함께 거는 제약** — 이 신뢰가 다른 판정으로 번지지 않게 막는다.

- 위치를 근거로 하는 **서버 판정은 서버가 받은 최신 위치로 다시 검증**한다.
  가구 잡기 거리(`maxTargetDistance`), 문 상호작용 거리(`_maxInteractDistance`)가 여기 해당한다.
- 클라이언트가 보낸 **조준 방향은 정규화·NaN 검사** 후 사용한다.
- **가구 물리·문 상태·홀더 슬롯은 예외 없이 서버 권위다.** 이동 예외를 근거로 다른 예외를 만들지 않는다.

## 근거 (Rationale)

**1. 지연 비용이 비대칭이다.** 가구는 "누른 뒤 조금 있다 뜬다"가 연출로 가려지지만
([ADR-0010](ADR-0010-server-authoritative-furniture-physics.md) 완화책), 이동은 **매 프레임 전신으로 느껴진다.**
같은 RTT라도 체감 손실이 훨씬 크다.

**2. C의 비용이 이 게임에서 회수되지 않는다.** 예측·재조정은 경쟁 FPS가 치팅 방어와 정밀 판정을
동시에 원할 때 값어치를 한다. 이 게임의 판정 대상은 이동이 아니라 **가구 상태**고, 그건 이미 서버 권위다.

**3. 치팅으로 얻을 것이 적다.** 이동 핵으로 얻는 것은 빠른 이동뿐이고, 가구를 날리거나 문을 여는 것은
서버가 거리를 재검증하므로 위치를 위조해도 통과하지 못한다(위 제약).

## 결과 (Consequences)

### 긍정
- 1인칭 조작감이 유지된다.
- 구현이 이미 끝나 있고 추가 비용이 없다.
- 권위 예외가 **정확히 하나**로 문서화되어, 다른 예외 요청을 거절할 근거가 생긴다.

### 부정 / 감수하는 비용
- **이동에 관한 한 클라이언트를 신뢰한다.** 텔레포트·속도 조작을 막지 못한다.
- 서버가 보는 위치와 클라이언트가 보는 위치 사이에 미세한 차이가 남는다.
  거리 판정이 경계에 걸리면 "분명 닿았는데 안 잡힌다"가 생길 수 있다.
  → 완화: 거리 임계값에 여유를 둔다. 판정 실패 사유를 클라이언트에 알려 디버깅 가능하게 한다.
- 협력 게임이라 지금은 문제가 아니지만, **대전 요소가 들어오면 즉시 문제가 된다.**

### 후속 작업
- [x] `ClientNetworkTransform` 구현 (Y축 회전만 복제, 피치는 로컬)
- [ ] 서버 측 거리 재검증이 **최신 수신 위치**를 쓰는지 코드 확인
- [ ] 조준 방향 정규화·NaN 검사가 모든 서버 RPC 진입부에 있는지 확인
- [ ] 스폰 시 `TeleportClientRpc` 경로 검증 (소유자 권위라 서버가 직접 쓰면 덮인다)

## 재검토 조건

**아래 중 하나라도 발생하면 이 ADR을 다시 연다.**

- 대전·경쟁 요소(PvP, 랭킹, 전적) 도입
- 이동 자체가 승패에 직결되는 메커닉(추격·술래) 도입
- 공개 서버·랜덤 매칭 도입 — 아는 사람끼리가 아니게 되는 순간 치팅 유인이 생긴다
