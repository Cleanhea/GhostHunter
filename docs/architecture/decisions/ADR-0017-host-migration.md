# ADR-0017: Steam 로비를 조정 채널로 사용해 호스트를 이전한다

- **상태**: 구현 중 — 기존 Steam/NGO 서버 권위 구조 유지(사용자 확정), 실기 검증과 커밋 확인 경로 대기
- **날짜**: 2026-09-27
- **결정자**: 사용자(호스트 이전·무작위 선출·기존 Steam/NGO 구조 유지)
- **관련**: [스테이지 시스템 기획서](../../project/stage-system.md), [ADR-0001](ADR-0001-steam-p2p-facepunch-transport.md), [네트워크 구조](../networking.md)

## 배경

현재 프로젝트는 NGO의 클라이언트·서버 방식으로 호스트가 귀신, 가구 물리, 청소, 정신력과 씬 전환을 판정한다. 호스트가 떠나면 NGO 세션과 서버 전용 상태가 사라진다. 2026-09-27 사용자 결정은 로딩 중 또는 진행 중 호스트 이탈 후 남은 플레이어 중 무작위로 새 호스트를 뽑아 같은 스테이지를 이어 가는 것이다. 방장이 `타이틀로`를 누른 경우에도 적용한다.

Unity의 [Multiplayer Services 호스트 이전 문서](https://docs.unity.com/en-us/mps-sdk/session-host-migration)는 NGO의 기본 이전 경로에 Distributed Authority 사용을 안내한다. 이 저장소는 현재 서버 권위 토폴로지를 사용하고 있어 그대로 적용하는 것은 전체 권위 모델 변경이다. Facepunch의 [Lobby API](https://wiki.facepunch.com/steamworks/Data.Lobby)는 오너 변경, 멤버 조회, 로비 데이터 쓰기를 제공한다.

## 검토한 선택지

| 선택지 | 장점 | 비용 |
| --- | --- | --- |
| A. 현행 서버 권위 유지 + 클라이언트가 받은 상태를 새 서버에 재구성 | 기존 서버 판정 코드를 유지 | 모든 스테이지 상태의 스냅샷·재연결을 직접 구현해야 함 |
| B. NGO Distributed Authority로 변경 | SDK의 이전 경로 활용 | 권위 모델·트랜스포트·상호작용 판정을 폭넓게 재설계해야 함 |
| C. 호스트 이탈 시 스테이지 재시작 | 구현이 단순 | 같은 스테이지 진행 상태를 유지한다는 확정 규칙을 충족하지 못함 |

## 선택한 방식과 현재 코드

1. Steam 로비 오너가 남은 멤버 목록에서 무작위로 차기 호스트를 선정하고 선출 세대 번호와 Steam ID를 로비 데이터에 게시한다. 자발적 이탈이면 기존 오너가 퇴장 전에 게시하고, 예고 없는 이탈이면 Steam이 넘겨준 새 로비 오너가 게시한다. 새 NGO 호스트가 로비 데이터를 갱신할 수 있도록 로비 오너도 선정된 사람에게 넘긴다.
2. 서버가 0.2초 간격으로 복구 스냅샷을 생성해 Steam P2P 채널 9로 모든 남은 로비 멤버에게 신뢰 전송한다. 수신자는 완전한 청크와 체크섬·스테이지 ID를 확인한 뒤에만 보관한다. 새 방장은 멤버들의 복제본을 모아 가장 큰 시퀀스를 선택한다. 구현 위치는 `StageRecoveryCoordinator`, `StageRecoverySnapshotUtility`, 각 게임플레이 컴포넌트의 `CaptureStageState`/`ServerRestoreStageState`다.
3. 기존 NGO 세션을 내린 뒤 선출된 플레이어가 같은 `Game` 씬에서 `StartHost`한다. 스냅샷을 적용한 뒤 로비에 준비 신호를 게시하고, 다른 플레이어는 게시된 새 Steam ID로 `StartClient`한다. 전체 복원 중 입력, 귀신 AI, 정신력 어둠 틱, 청소·가구 초기 랜덤 배치를 막는다. 재접속한 플레이어의 Steam ID는 Facepunch 전송 연결의 인증된 Steam ID와 대조한 뒤 복원한다.
4. 선출 세대 번호와 스테이지 ID로 준비·재개 신호의 오래된 값을 거부한다. 복원이 끝나면 선택된 스냅샷을 다시 배포하고 재개 신호를 게시한다. 재접속이 지연된 기존 로비 멤버의 상태는 별도로 보관해 도착 시 적용한다.
5. 전원 이탈이면 새 호스트를 뽑지 않고 비정상 종료한다. 로딩 중 한 명만 남았으면 스테이지 시작을 취소한다.

## 선행 작업

- [x] 상태 소유자 1차 조사. `NetworkVariable` 밖의 서버 전용 값이 있어 단순 재호스팅으로는 복구되지 않음을 확인했다.
- [x] 정산 이력은 Steam 로비 데이터에 순번별로 게시하고 Result 오너 변경 시 다시 읽는다. `SanityState`와 `GhostStateMachine`의 서버 전용 값에 스냅샷 추출·복원 API 및 회귀 검사를 추가했다. 전송·적용 경로는 아직 연결되지 않았다.
- [x] Steam 로비 무작위 선출·오너 이전·세대 번호, 복제본 전송·재호스트·월드/플레이어 적용 코드. C# 어셈블리 빌드 통과. 실제 2~4인 경쟁 상태는 미검증.
- [ ] NGO 세션 종료 후 같은 씬 재시작과 네트워크 객체 재생성 실기 검증.
- [ ] 호스트 강제 종료, 자발적 타이틀 이동, 로딩 중 이탈을 Steam 계정 2개 이상으로 검증.
- [ ] 액션 완료 시점을 복제본 수신 확인 뒤로 미루는 커밋 경로. **현행 주기 스냅샷에서는 호스트가 마지막 전송 전에 갑자기 종료되면 최대 한 전송 간격의 변경이 사라질 수 있다.** 사용자가 요구한 직전 변경의 보존을 아직 보장하지 못한다.
- [ ] 잡기·던지기 중 홀더 연결, 진행 중 도구 행동, 귀신 현상의 일시적인 연출 상태 전수 복구. 현재는 배치·속도·내구도·결과, 귀신 FSM·추격/은신 판정 등 확인 가능한 상태를 복원한다.

### 1차 상태 조사

| 상태 | 현재 복제 | 이전 때 필요한 복구 |
| --- | --- | --- |
| 플레이어 위치·입력 상태·사망·정신력·시체 | 일부 `NetworkTransform`·`NetworkVariable`, 일부 서버 전용 `SanityState` | Steam ID별 소유권 재매핑, 정신력 원본·시체 재생성 |
| 목표 가구 배치·물리·내구도·반출 완료 | 위치/상태/내구도 일부 복제 | 배치 seed, Rigidbody 속도, 완료 플래그, 서버 물리 소유권 복원 |
| 얼룩 위치·청소 진행 | `CleaningStain.State` 복제 | 재호스팅 시 초기화 경로 차단·상태 복구 |
| 귀신 단계·추격·이벤트 | 단계 일부 복제, AI 경로·타이머는 서버 전용 | FSM·타이머·대상·랜덤 상태 복구 |
| 문·가구 조립·도구·아이템 | 개별 `NetworkVariable`과 서버 내부 상태 혼합 | 전체 네트워크 객체 식별·연결 재구성 |
| 정산 이력·공동 상점 | 로컬 Bootstrap 메모리 / Steam 로비 데이터 | 이전 시 정산 이력 동기화, 상점은 로비 데이터 유지 |

NGO의 서버가 끊긴 뒤 `OnNetworkSpawn`에서 여러 값이 기본값으로 재설정되고, 일부
`OnNetworkDespawn`은 배치한 가구를 원위치로 돌린다. 이 때문에 현재 클라이언트가 가진
`NetworkVariable`만으로 새 서버를 시작하면 진행 상태가 유실된다. 상태 커밋 확인 방식에 관한
사용자 응답과 복구 프로토콜 검증이 끝나기 전에는 진행 중 스테이지 이전을 완료로 표시하지 않는다.

## 재검토 조건

상태 전수를 클라이언트에 보존하기 어렵거나 복구 중 데이터 무결성이 깨지면 Distributed Authority 전환 또는 별도 중계 서비스를 다시 검토한다. 패키지·토폴로지 변경은 별도 결정이 필요하다.
