# ADR-0013: B안을 제작 기준으로 선택하고 씬 가구 풀을 서버에서 랜덤 배치한다

- **상태**: Accepted
- **날짜**: 2026-09-12
- **결정자**: 사용자(B안 선택·가구 랜덤 스폰 제작 지시), 구현은 기존 서버 권위·사전 배치 규약 적용
- **관련**: [맵 생성 §10.1.3](../map-generation.md), [MAP-19](../../project/roadmap.md), [ADR-0009](ADR-0009-scene-placed-level-objects.md), [ADR-0010](ADR-0010-server-authoritative-furniture-physics.md)

## 배경 (Context)

v0.4는 맵별 Target Furniture Type·Count 선정과 후보 지점 배치를 요구한다. 사용자는 B안을 선택하고
가구 랜덤 스폰 제작을 지시했다. Game 씬에는 B·C 실내가 이미 저장되어 있으며 B안의 현재 방 좌표는
2026-09-06 여백 정리 재설계 결과다. ADR-0009에 따라 가구는 씬에 놓인 프리팹 인스턴스이고 물리는 서버 권위다.

## 검토한 선택지 (Options)

| 선택지 | 장점 | 단점 |
|---|---|---|
| 씬 풀을 서버에서 재배치 | 기존 씬 동기화·가구 물리·R 복구 경로 사용, 에디터에서 풀·후보 확인 | 최대 수량을 미리 배선해야 함 |
| 가구 런타임 Instantiate/Spawn | 수량에 따라 인스턴스 생성 가능 | ADR-0009 변경 필요, 스폰·삭제·프리팹 등록 수명주기 추가 |
| 각 피어가 같은 시드로 배치 | 위치 전송을 줄일 여지 | 물리 후보 검사 결과 차이로 불일치 가능, 기존 서버 권위와 충돌 |

## 결정 (Decision)

**현재 제작 맵은 B안**, 도면 파일은 `HousePlanC.png`, 외곽 30×24m ×2층 + 다락 20×14m로 한다.
현재 `House_Prototype_PlanB`의 실내를 사용한다. A안 결정은 과거 기록으로 남기고 C안은 비교 자료로 보존한다.

랜덤 가구는 Editor 메뉴에서 기존 가구 프리팹을 보관 풀에 배치하고 서버만 전체 계획을 계산해 옮긴다.
위치는 `NetworkTransform`, 배치·대상 여부는 서버 쓰기 `NetworkVariable`로 복제한다. 시드는 재현용이며
클라이언트는 배치를 다시 계산하지 않는다. Controller와 가구는 NetworkObject 부모·자식 관계를 만들지 않는다.
기존 프리팹 물리 설정은 유지하고 씬 인스턴스에 `RandomFurnitureItem`·탐지 마커와 풀 식별자만 추가한다.
이는 맵 배선을 위한 컴포넌트 오버라이드이며 공통 질량·콜라이더·투척값을 인스턴스별로 수정하지 않는다.

## 근거 (Rationale)

선택한 레벨과 기존 NGO 구조로 랜덤 배치·잡기·탐지를 연결할 수 있다. 전체 배치 계획을 먼저 검증하므로
부족한 수량이나 공간 충돌 때문에 일부 가구만 게임에 남는 상황을 피한다. 새로운 패키지나 어셈블리는 필요 없다.

## 결과 (Consequences)

- 최초 설정은 기획서 예시 4종 16개 **[TEMP]**다. 기존 B안 인테리어와 별도의 풀을 작업 대상으로 사용한다.
- SO에서 종류 수·종류별 수량 범위·시드·방 상한·탐색 예산을 조정한다. 설정 수량을 늘릴 때 씬 풀도 보충해야 한다.
- 설치 메뉴는 B안 앞마당에 플레이어 시작 위치를 연결하고 Game 씬과 설정 에셋을 저장한다.
- 유효 후보가 없는 방은 사용하지 않는다. 모든 수량을 놓을 수 없으면 오류로 끝내고 완료 상태를 올리지 않는다.
- 최종 작업 집계·운반 완료·집중 제한 수치·열쇠 공간 포함 여부·재추첨 정책은 기존 TBD로 남는다.
  B안 귀신·은신처·세이프 존의 전체 레벨 이전과 실제 운반 경로 판정도 후속 작업이다.
- C# 빌드·Unity 자동 임포트 컴파일/NGO IL 후처리와 순수 계획 테스트 13개는 통과했다.
  Unity 설치 메뉴로 풀 16개·안전 후보 91개·B안 시작 위치를 저장했고 내부 seed 0~15 검증도 통과했다. Unity Test Runner·Host/Client 검증은 대기다.

## 재검토 조건

사용자가 제작 맵을 변경하거나, 사전 풀 용량이 씬 로드·메모리에 부담이 되거나,
정식 작업량이 가변 인스턴스 생성을 요구할 때 재검토한다. ADR-0009·0010은 유지한다.
