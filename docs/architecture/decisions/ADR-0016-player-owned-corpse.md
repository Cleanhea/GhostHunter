# ADR-0016: 플레이어 오브젝트가 임시 시체 상태를 복제한다

- 상태: Accepted
- 날짜: 2026-09-27
- 관련: [죽음 기획서](../../project/death-system.md), [ADR-0010](ADR-0010-server-authoritative-furniture-physics.md)

## 배경

죽음 기획서는 사망 위치에 남아 물리적으로 이동할 수 있는 시체를 요구한다. 현재 별도 시체 프리팹과
애니메이션은 없다. 사용자는 기존 Player 외형으로 임시 구현을 승인했다. 물리 상태의 권위는 기존
가구 규약과 같이 서버에 두어야 한다.

## 검토한 선택지

| 선택지 | 장점 | 비용 |
| --- | --- | --- |
| 시체 전용 NetworkObject 프리팹 | 독립 수명과 다양한 외형으로 확장하기 쉽다 | 신규 프리팹·등록·GUID 배선이 필요하다 |
| 기존 Player NetworkObject의 상태로 복제 | 현재 Player 외형·설정을 재사용하고 별도 네트워크 프리팹 등록이 없다 | 시체 수명이 Player 스폰 수명에 묶인다 |

## 결정

임시 시체는 `PlayerVisuals`가 사망 시 `RemoteBody` 메시를 복제해 만든다. (2026-09-27 갱신: 몸이
두더지 스킨 메시로 바뀌어 렌더러만 복제하면 본이 따라오지 않으므로, 본을 포함한 모델 루트
`_corpseModel`을 복제해 캡슐 중심 루트 `Corpse_{id}` 아래 둔다. 콜라이더 치수는 `SpectatorSettings`의
`CorpseHeight`·`CorpseRadius` → [player-controller.md](../player-controller.md) "캐릭터 모델·애니메이션".) 서버만 시체
`Rigidbody`를 시뮬레이션하고 위치·회전을 Player의 `NetworkVariable`로 복제한다. 생존 플레이어의
좌클릭 요청은 `GrabController`의 소유자 RPC를 거쳐 서버가 거리·시야·생존 상태를 다시 검사한다.
짧은 클릭은 힘을 주고, 길게 누르면 홀더가 된다. 홀더가 두 명 이상일 때 서버가 평균 목표점을 향해
시체를 끌어올린다. 부활·디스폰 때 복제 몸체와 홀더를 정리한다.

## 결과와 재검토

- 네트워크 시체 프리팹 등록과 새 GUID는 필요하지 않다.
- 시체 위치는 서버 권위이고, 죽은 Player 루트는 관전 이동으로 옮기지 않는다.
- 런타임 시체는 별도 NetworkObject가 아니므로 늦게 접속한 플레이어는 Player의 생존 상태와 시체
  위치·회전에서 현재 모습을 재구성한다.
- 정식 캐릭터 모델·래그돌·부활 위치 규칙이 정해지면 전용 시체 프리팹과 수명 분리를 재검토한다.
