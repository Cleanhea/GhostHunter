# 가구 재조립(조립 스테이션) 구현 컨텍스트

> 목적: **분해한 가구를 특정 위치에서 다시 합치는 기능**을 플레이 가능한 수준까지 완성하기 위한
> 작업 컨텍스트다. 게임 규칙의 권위는 [가구용 멀티 드라이버 기획서](../project/furniture-multidriver-system.md)
> §4.2·§4.3·§5·§6.3·§6.4이고, 이 문서는 그 규칙을 **실제로 돌아가게 만들기 위해 무엇이 있고
> 무엇이 없는지**를 정리한다. §7에서 사용자가 확정한 항목은 기획서에도 반영해야 한다(FR-IMPL-7).
>
> 작성일 2026-09-16 · 대상 브랜치 `feature/furniture-multidriver`

## 1. 한 줄 요약

분해(FM-IMPL-2)는 실제 씬에서 동작을 확인했다. **재조립은 서버 판정·실행 코드(FM-IMPL-3)까지
존재하지만 화면에 아무것도 그리지 않아 플레이어가 조립 가능 여부를 알 수 없고, 한 번도 실제
플레이로 검증된 적이 없다.** 이번 작업은 "코드가 있다"를 "플레이어가 쓸 수 있다"로 만드는 것이다.

## 3. 지금 없는 것 (이번 작업 범위)

1. **3색 실루엣 렌더링.** 서버는 흰/초록/빨강 상태를 이미 복제하지만 그리는 코드가 저장소에 없다
   (`Silhouette` 문자열은 판정·컨트롤러에만 등장). 플레이어 입장에서는 **조립 영역이 아무 반응 없는
   빈 바닥**이고, Ready가 되었는지 알 방법이 없는데 Ready가 아니면 조준조차 되지 않는다.
2. **조립 스테이션의 물리적 실체.** 지금은 보이지 않는 트리거 상자 하나뿐이다. 바닥 표시·경계·
   드릴 카 연결이 없다.
3. **실패·안내 피드백.** 부품 혼입/개수 초과(빨강), 큰 가구 풀 고갈, 부품이 아직 굴러다녀서
   `IsGrounded`가 false인 상태를 구분해 알려주지 않는다.
4. **조립 결과물 처리.** 완성된 큰 가구가 영역 중앙 1m 위에서 떨어져 영역 안에 그대로 남는다 → §5 R-1.
5. **검증.** 조립 경로는 PlayMode 자동 테스트도, 실제 Local Host 플레이도, 원격 Host/Client도 0건이다.
6. **손목 애니메이션**(FM-IMPL-4 잔여, 분해와 공용).

## 4. 요구 사항 (기획서에서 그대로 옮김 — 재확정 아님)

- 조립 = 작은 가구 N개 → 큰 가구 1개. 성공 시 부품 전부 삭제, 큰 가구 1개 생성(§4.2).
- 점유 인정 조건 2개: **영역 안** + **바닥에 놓인 상태**(§4.2.1).
- 조립 취소 조건: 가구가 영역 밖으로 나감 / 플레이어에게 잡힘 / **다른 가구가 영역에 들어옴**(§4.2.1).
- 성립 규칙 1: 다른 큰 가구의 부품 혼입 또는 개수 초과 → 조립 불가(빨강).
- 성립 규칙 2: 같은 종류 큰 가구에서 나온 부품은 출처를 구분하지 않는다.
- 실루엣: 흰 `#FFFFFF`(투명도 50) 부분 / 초록 `#78C664` 조립 가능 / 빨강 `#D66565` 불가(§6.4).
  부품 **하나만 놓아도** 그 부품의 원형 큰 가구 실루엣이 영역 가운데에 뜬다.
- 조립 실행: 초록 실루엣에 포인터를 맞추고 우클릭을 **행동 시간 끝까지 누르고 있어야** 완료(§3.2, 1.1).
- 연출: 완료 시 부품이 사라지고 **영역 중앙 공중 1m**에서 큰 가구가 생성돼 떨어진다(§6.3).
- 내구도: 완성 가구 = 사용된 부품 내구도의 **평균**(소수점 버림, §5). 아이템 내구도는 **성공 시에만** 5 감소.

## 5. 설계 쟁점과 위험

**R-1 — 완성된 가구가 영역을 오염시킨다. [해결안 확정 2026-09-16]**
`ServerTryAssemble`은 완성 가구를 `영역 위치 + 1m`에 활성화한다. 그 가구도
`FurnitureDriverPoolItem`이고 `PoolKey`가 큰 가구 ID라, 착지하면 트리거 후보로 잡혀
어떤 레시피의 부품 ID와도 맞지 않아 영역이 곧바로 **Invalid(빨강)** 이 된다 → 완성품을 치우기 전까지
다음 조립 불가.
**확정: 점유 판정에서 큰 가구 풀 키를 무시한다.** 영역 안 오브젝트 중 어떤 레시피의 **부품 ID에도
해당하지 않는 것**은 개수 집계에서 제외한다(완성품이 남아 있어도 실루엣은 Empty, 연속 조립 가능).
기획서 §4.2.1의 "다른 가구가 영역에 들어옴 → 취소"는 **부품으로 인정되는 오브젝트에 한정**되도록
해석을 좁힌다 — 기획서에 이 단서를 명시해야 한다(FR-IMPL-7).

**R-2 — Ready가 아니면 조준 자체가 안 된다. [해결안 확정 2026-09-16]**
컨트롤러가 `Silhouette != Ready`인 영역을 대상에서 제외한다.
**확정: 흰색·빨강 상태에서도 조준은 되고, 우클릭하면 즉시 "조립 실패" 연출을 낸다.**
행동 시간을 돌리지 않고 시작 시점에 거절한다 — 아이템 내구도는 감소하지 않는다.
컨트롤러의 Ready 게이트를 조준 단계에서 제거하고 `BeginAction` 직전 검사로 옮긴다.
Empty(부품 0개) 영역은 조준 대상이 아니다.

**R-3 — 실루엣 메시의 출처. [해결안 확정 2026-09-16]**
**확정: `FurnitureDisassemblyRecipe`에 시각 전용 실루엣 프리팹 필드를 추가한다.**
`NetworkObject` 없는 로컬 오브젝트이며 클라이언트가 영역 중앙에 생성·색 변경·파기한다.
큰 가구 풀 인스턴스의 렌더러를 빌려 쓰지 않는다(활성/비활성 토글과 충돌).

**R-4 — 큰 가구 풀 고갈. [확정 2026-09-16 — 발생 불가로 정리]**
`TryFindInactive`가 실패하면 `ServerTryAssemble`이 `false`를 반환하고 **조용히 끝난다**
(행동 시간은 이미 소모, 내구도는 감소하지 않음).
**확정: 분해하면 원본 인스턴스가 비활성화되므로 부품이 존재하는 한 되돌아갈 빈 자리도 반드시 있다.** 별도 UI를 만들지 않고 경고 로그만 남긴다 — 이 경로가 실제로 찍히면 풀 관리 버그다.

**R-5 — 부품이 계속 구른다.** `IsGrounded` 속도 임계가 0.05 m/s다. 분해 직후 부품이 서로 겹쳐
생성돼 튕기는 문제(구현 문서 §"남은 작업")가 남아 있어, 영역에 던져 넣은 부품이 한동안 인정되지
않을 수 있다. 실루엣이 흰색에서 초록으로 늦게 바뀌는 형태로 드러난다.

**R-6 — 영역 크기. [확정 2026-09-16]** 트리거를 **4×2.5×4 m**로 확대한다(center y 1.25 유지).
최대 부품 수는 식탁 5개(상판 1 + 다리 4), 선반 5개(프레임 1 + 보드 4)다.

- 서버 권위. 클라이언트는 표시만. 조립 실행·판정은 전부 서버(§3.5, ADR-0010).

- 씬·프리팹 편집은 Unity MCP 또는 `Assets/Scripts/Editor/` 생성 도구로만.

| 실제 씬 | Local Host에서 침대 분해 → 부품 3개를 스테이션까지 운반 → 초록 실루엣 확인 → 3초 유지 → 침대 복원·내구도 평균 확인 → 완성품을 치우지 않은 채 두 번째 조립 가능 확인 |
| 원격 | Host/Client 2PC에서 실루엣 색이 양쪽에 같게 보이는지, 조립 결과가 복제되는지 |
