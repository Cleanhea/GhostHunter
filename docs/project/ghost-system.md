## 2. 개요

### 2.1 문서 목적과 범위

이 문서는 **모든 귀신에게 공통으로 적용되는** 규칙을 정의한다.

- 귀신 생성·존재 방식
- 4개 공통 상태와 전이 조건 (+ 강제 진정)
- 팀 평균 정신력 연동
- 초자연현상
- 어택 타임 판정·지속·종료
- 플레이어 탐지, 추격·수색 AI
- 상태별 공통 연출과 예외 처리

다음은 이 문서의 범위가 **아니다.**

| 내용 | 정의하는 곳 |
| --- | --- |
| 귀신별 고유 능력·특수 조건·특수 탐지 | 각 귀신 개별 시스템 기획서 (미작성) |
| **초자연현상의 규칙** (1.1에서 이관) | 별도 기획서 (미작성) — 이관 전까지 [§6](#6-행동-빈도와-초자연현상)을 구현 근거로 유지한다 |
| 공통 규칙을 덮어쓰는 귀신별 예외 | 각 귀신 개별 시스템 기획서 (미작성) |
| 정신력 수치·증감·디버프·UI | [sanity-system.md](sanity-system.md) |
| 강제 진정 아이템의 종류·소지 개수·사용 조건 | 아이템 기획서 (미작성) |
| 두더지 땅속 은신의 쿨타임·유지시간, 은신이 깨지는 예외 | [mole-skill-system.md](mole-skill-system.md) §5 (기획서 1.0) |
| 현재 프로토타입 구현·배선·검증 | [ghost-prototype.md](../architecture/ghost-prototype.md) |

### 2.3 시스템 목적

귀신은 플레이어의 청소·이사 작업을 방해하고 생존 위협을 제공하는 핵심 시스템이다.
정신력·청소 진행도·귀신별 특수 조건에 따라 활동하며, 조건을 만족하면 실제로 플레이어를
공격하는 어택 상태로 진입한다.

```text
청소·이사 작업 → 귀신 활동 증가 → 위험 징후 → 어택 → 도주·은신 → 어택 종료 → 작업 재개
```

평소에는 초자연현상으로 작업을 방해하고, 특정 순간에만 직접적인 생존 위협으로 전환한다.

## 3. 귀신 생성과 존재 방식

### 3.1 생성 규칙 [확정]

| 항목 | 규칙 |
| --- | --- |
| 기본 생성 수 | 집 하나당 **1마리** |
| 최초 상태 | **활동** (1.1 — 1.0의 평상시는 삭제됐다 → §4.3) |
| 생성 위치 | 해당 집 내부 |
| 활동 범위 | 해당 집 내부 |
| 집 밖 이동 | 불가능 |
| 드릴 카 진입 | 불가능 |
| 추가 귀신 | 특정 콘텐츠 또는 귀신별 특수 조건에 따라 생성 가능 |

- 집 하나당 기본 귀신은 **1마리** 생성한다.
- 기본 귀신은 **해당 집 내부에서만** 활동한다.
- 귀신은 집 외부와 드릴 카에 **갈 수 없다.**
- 특수 조건을 충족하면 추가 귀신이 생성될 수 있다.
  - 귀신 들린 인형 등 **저주받은 오브젝트**를 옮기려 할 때
  - 귀신별 특수 조건 충족

복수 귀신의 상태·어택 처리 규칙은 [§13 G-10](#13-미결정-목록)에서 대기 중이다.

### 3.2 존재 방식 [확정]

귀신은 **어택 중이 아닐 때도 집 내부에 실제 위치를 가지고 이동한다.** 실제 위치는 다음에 쓰인다.

- 주변 오브젝트 간섭
- 문·환경 오브젝트 조작
- 초자연현상 발생 기준 위치
- 귀신 이동
- 어택 시 탐색 시작 위치

### 3.3 시각 노출 정책 [확정]

> **기획 의도**
> 플레이어가 귀신의 모습에 익숙해지는 것을 방지한다. 집 안에 실제로 존재한다는 공간감은
> 유지하되, 모습 자체는 아껴서 보여 준다.

귀신의 실제 모습을 **상시 노출하지 않는다.** 시각적으로 노출하는 경우는 다음뿐이다.

- 초자연현상
- 귀신별 특수 이벤트 (개별 귀신 기획서에서 정의)
- 경고·어택 상태

일부 초자연현상은 **실제 귀신 위치와 무관하게** 플레이어 주변 또는 지정된 Spawn Point에
일시적인 귀신 모습을 생성할 수 있다.

### 3.4 베이직 귀신 [확정 — 1.1 신설]

**베이직 귀신**은 이 공통 기획서의 시스템만 적용된 귀신이다. 고유 능력·특수 조건·특수 탐지가
**하나도 없다.** 개별 귀신 기획서가 나오기 전까지 프로토타입이 다루는 귀신은 베이직 귀신이다.

- 이 문서에 적힌 규칙을 덮어쓰는 예외가 없다.
- 아트 리소스 기획은 원문의 별도 데이터베이스에 있다(저장소 미반영).

## 4. 귀신 상태

귀신은 4개의 공통 상태를 가진다. 별도로 아이템에 의한 **강제 진정** 효과가 존재한다.

> **1.1 구조 변경 — 평상시가 사라졌다.** 1.0의 평상시·활동 2단계가 **활동 하나로 합쳐졌다.**
> 원문 §4.4가 자연 진정을 설명하며 "평상시(=활동모드)"라고 쓴 것이 근거다. 활동은 이제
> "정신력 61~100일 때의 기본 상태"이며 **그냥 배회한다.** 1.0에서 활동에 붙어 있던
> "환경 간섭·초자연현상 증가"는 원문이 초자연현상을 이 문서 범위에서 뺐으므로 §6에 근거만 남긴다.

### 4.1 상태 요약

| 상태 | 지속 시간 | 어택 판정 | 공격 | 이동 | 주체 |
| --- | --- | --- | --- | --- | --- |
| 활동 | 조건이 바뀔 때까지 | O (팀 평균 ≤ 60일 때만) | X | O | 귀신 |
| 경고 | **5초** [확정] | X | X | O | **플레이어** |
| 어택(일반) | **60초** [확정] | X | **O** | O | 귀신 |
| 어택(고위험) | **90초** [확정] | X | **O** | O | 귀신 |
| 자연 진정 | **30초** [확정] | X | X | O (활동과 동일) | 귀신 |
| 강제 진정 | **10초** [확정] | X | X | 제한적 | 귀신 |

> **경고는 플레이어의 상태다** (1.1 원문 §4.2). 귀신이 아니라 **어택이 온다는 것을 플레이어에게
> 알리는** 상태이므로, 연출(심장 소리·조명 깜빡임)이 곧 이 상태의 내용이다 → §10.3.

### 4.2 전체 상태 흐름 [확정]

```text
게임 시작
   ↓
[활동]  ← 기본 상태 (정신력 61~100)
   ↓ 어택 판정 성공 (정신력 31~60 확률 / 0~30 100%)
[경고 5초]
   ↓
[어택]  일반 60초 · 고위험 90초
   ↓  탐지 → 추격 → 수색 → 공격
[자연 진정 30초]  ← 어택 확률을 계산하지 않는다
   ↓ 30초 후 현재 정신력 재확인
[활동] 또는 다시 어택 판정
```

- **활동 상태는 어택 직전 상태를 의미하지 않는다.** 활동 중 어택 판정에 실패하면 계속 활동한다.
- 강제 진정은 위 흐름과 **별개 시스템**이며 어느 상태에서든 개입한다 → §4.8

### 4.3 평상시 — 1.1에서 삭제됨

**1.0의 평상시 상태는 더 이상 없다.** 귀신은 활동 상태에서 시작한다(§3.1).
1.0에서 평상시 → 활동 전환 조건이던 "정신력 80 이하 / 청소 40% 도달 / 귀신별 특수 조건"은
**전환할 대상이 없어졌다.** 청소 진행도는 1.1에서 **어택 발동 조건**으로 옮겨 갔다(§7.1).

> 이 절은 1.0 기준으로 구현된 `Idle` 상태가 코드에 남아 있어 대응 관계를 잃지 않으려고 남긴다.
> 코드의 상태 enum을 어떻게 정리할지는 [§12.3](#123-현재-구현과의-차이)과
> [§13 G-16](#13-미결정-목록)에서 다룬다.

### 4.4 활동 상태 [확정]

**기본 상태다.** 팀 평균 정신력 **61~100** 구간에서 귀신이 놓이는 상태이며,
집 내부를 **그냥 돌아다닌다.**

- 플레이어를 직접 공격할 수 **없다.**
- 팀 평균 정신력이 **60 이하**인 경우에만 기본 어택 판정을 실행할 수 있다.
- **활동 상태가 반드시 어택으로 연결되는 것은 아니다.**

**활동 중인 귀신을 목격하면 정신력이 줄어든다** [확정 — 1.1 신설].

| 항목 | 규칙 |
| --- | --- |
| 최초 목격 | 정신력 **−5** |
| 계속 보고 있을 때 | **5초마다 −5** 반복 |

> **정신력 문서와의 정합성.** [sanity-system.md §4.2](sanity-system.md)의 감소 표에는
> "귀신 이벤트 목격 −15"만 있고 **이 −5 항목이 없다.** 둘은 다른 사건이다 — −15는
> 초자연현상 목격, −5는 **귀신 본체** 목격이다. 정신력 기획서 반영은
> [§13 G-17](#13-미결정-목록)에서 대기한다. 판정 기준(거리·시야각·가림)도 원문에 없다.

### 4.5 경고 상태 [확정]

어택 판정이 성공하여 **어택 발생이 확정된** 상태다. 귀신이 아니라 **플레이어의 상태**로 정의한다.

- 지속 시간: **5초**
- 경고 중에는 신규 어택 판정을 하지 않는다.
- 연출: **심장 박동 소리** + **조명 깜빡임 5초** → §10.3
- 경고 종료 후 **어택 상태로 전환한다.**

> **해석 주의.** 원문에는 경고 도중 정신력이 회복되어 어택이 **취소되는 경로가 없다.**
> 따라서 경고에 들어간 어택은 취소되지 않는 것으로 읽는다. 강제 진정만이 이를 끊을 수 있다(§4.8).

### 4.6 어택 상태 [확정]

귀신이 실제로 플레이어를 탐지·추적·공격할 수 있는 상태다. **일반 어택과 고위험 어택으로 나뉜다.**

행동 흐름은 둘 다 같다: **탐지 → 추격 → 수색 → 공격**

| | 일반 어택 | 고위험 어택 |
| --- | --- | --- |
| 지속 시간 | **60초** | **90초** |
| 탐지 능력 | 기본 | **강화** → §8 |
| 종료 후 | 자연 진정 | 자연 진정 |

- 조명이 위험을 알리는 **빨간색**으로 바뀐다 → §10.4
- 플레이어 탐지 활성화 → §8 / 수색·추격 AI 활성화 → §9
- 어택 중 신규 어택 판정 **금지**
- 플레이어 한 명이 사망해도 **어택은 종료되지 않는다.**
- 귀신은 집 내부에서만 활동한다. 드릴 카·집 밖 플레이어는 공격할 수 **없다.**

> **고위험 어택의 발동 기준이 원문에 명시되지 않았다.** 정신력 0~30 구간이 "100% 강제 어택,
> 탐지 강화"이고 고위험 어택의 특징이 "탐지 능력 강화"이므로 **0~30 구간의 어택 = 고위험**으로
> 읽는다. 확정 전까지 이 해석으로 구현한다 → [§13 G-18](#13-미결정-목록).

지속·종료 규칙은 §7.5.

### 4.7 자연 진정 상태 [확정]

어택 종료 후 연속 재어택을 방지하는 상태다.

- 지속 시간: **30초**
- **팀 정신력이 몇이든 어택 확률을 계산하지 않는다.** 0~30이어도 이 30초 동안은 어택하지 않는다.
- 귀신은 이 30초 동안 **평상시(= 활동 모드)로 지속**한다 — 배회한다.
- 신규 어택 발생 불가 / 경고 상태 진입 불가 / 플레이어 추격·공격 불가
- 30초 종료 후 **현재 정신력을 다시 확인**하고 그 구간의 규칙대로 실행한다.

```text
30초 경과 → 현재 정신력 확인
   61~100 → 활동 유지
   31~60  → 어택 확률 재판정
   0~30   → 다시 100% 어택
```

### 4.8 강제 진정 효과 [확정]

특정 아이템 사용으로 귀신에게 강제 적용하는 억제 효과다. **자연 진정과는 별개 시스템으로 관리한다.**

- 지속 시간: **10초**
- 진행 중인 어택 **즉시 종료**
- 신규 어택 발생 차단
- 활동 상태 진입 억제
- 공격 행동 불가
- 효과 종료 후 현재 정신력을 재검사하여 **활동** 또는 어택 판정으로 전환

아이템 종류·소지 개수·사용 조건은 아이템 기획서에서 정의한다.

## 5. 정신력 연동

정신력 수치의 정의·증감·디버프·UI는 [정신력 시스템 기획서](sanity-system.md)가 단일 권위다.
이 문서는 **그 값을 어떻게 읽어 쓰는지**만 정의한다.

### 5.1 기본 규칙 [확정]

- 각 플레이어는 개인 정신력을 가진다.
- 일반 귀신의 공통 상태 전이와 어택 판정에는 **생존 플레이어의 팀 평균 정신력**을 사용한다.
- 일부 특수 귀신은 팀 평균 대신 특정 플레이어의 **개인 정신력**을 참조할 수 있다
  (개별 귀신 기획서에서 정의).

구현상 팀 평균의 출처는 `ISanityTeamService`이며, 귀신은 자체 정신력을 갖지 않는다 →
[ghost-prototype.md §3](../architecture/ghost-prototype.md)

### 5.2 정신력 구간 [확정]

1.1에서 **3구간**으로 정리됐다.

| 팀 평균 정신력 | 귀신 상태 여부 |
| --- | --- |
| 61~100 | 어택 X, **활동 O** |
| 31~60 | 확률에 따라 어택 여부를 결정하고 결과대로 실행 |
| 0~30 | **100% 강제 어택**, 탐지 강화 |

### 5.3 구간별 규칙 [확정]

**61~100** — 활동 상태다. 어택 판정을 하지 않는다. 귀신을 목격하면 정신력이 깎인다(§4.4).

**31~60** — 어택 판정을 실행할 수 있다. **이 구간에 들어갔다고 즉시 어택이 발생하지는 않는다.**
확률표(§7.3)로 판정하고 성공한 경우에만 경고 상태로 진입한다.

**0~30** — 고위험 구간이다.

- **어택 확률 100%** — 판정이 아니라 강제 발동이다.
- **탐지 강화** — 고위험 어택으로 취급한다(§4.6).
- 어택이 60초를 넘겨도 **계속 유지**된다(§7.5).
- 1.0의 "초자연현상 빈도 증가"·"귀신 특수 능력 사용 가능"은 1.1 원문이 언급하지 않는다.
  초자연현상은 범위 이관(§2.1), 특수 능력은 개별 귀신 기획서 소관이므로 **삭제하지 않고 둔다.**

## 6. 행동 빈도와 초자연현상

> **1.1에서 이 문서의 범위를 벗어났다.** 원문 §1.1이 "초자연현상의 규칙은 추후 다른 기획서에서
> 별도로 정의한다"고 선언했다. 별도 기획서가 나올 때까지 **이 절을 지우지 않는다** — 8종 중 6종이
> 이미 구현돼 있고(§12.1), 그 근거가 여기에만 있기 때문이다. 새 기획서가 생기면 통째로 옮긴다.

### 6.1 기본 발생 규칙 [확정 — 1.0 근거 유지]

- 활동 상태에서 초자연현상이 발생한다.
- 1.0의 "평상시 낮은 빈도 / 활동 높은 빈도" 2단계는 평상시가 사라져 **한 단계로 합쳐졌다.**
- 팀 평균 정신력 30 이하에서는 **추가로** 빈도가 증가한다.
- 상태별 실제 발생 주기는 프로토타입 테스트로 조정한다 [TBD].

### 6.2 청소 진행도 40% 트리거 [확정]

청소 진행도가 **최초로** 40%에 도달하면 귀신의 방해가 강해진다.

| 도달 시점의 상태 | 처리 |
| --- | --- |
| 활동 | 활동 유지 + **일정 시간 동안 방해 빈도 증가** |

1.1에서 청소 진행도는 **어택 발동 조건** 쪽으로 옮겨 갔다(§7.1) — 전환할 평상시가 없어졌기 때문이다.
어느 쪽으로 읽을지는 [§13 G-1](#13-미결정-목록) 대기다.

빈도 증가 지속 시간은 원문 검증 항목(§12.2)에 **90초** [임시]로만 등장한다.

### 6.3 초자연현상 정의 [확정]

초자연현상은 귀신이 플레이어를 위협하거나 작업을 방해하기 위해 발생시키는 **비공격 행동**이다.
공격은 하지 않지만 방해하는 모든 현상을 초자연현상으로 정의한다.

- **초자연현상 자체로는 플레이어가 사망하지 않는다.**
  사망은 어택 상태에서 귀신에게 잡혔을 때만 발생한다.

역할:

- 공포 연출
- 정신력 감소
- 작업 방해
- 귀신 존재 위치 암시
- 플레이어 이동·행동 유도

### 6.4 현상 선정 방식 [확정]

```text
1. 현재 귀신 상태 확인
2. 초자연현상 발생 여부 판정
3. 현재 실행 가능한 초자연현상 Pool 확인
4. Pool 내부에서 랜덤 선택
5. 현상 실행
6. 직전에 실행한 현상은 다음 선택 Pool에서 제외
```

6단계로 동일 현상의 연속 발생을 방지한다.

### 6.5 초자연현상 종류 [확정]

| # | 현상 |
| --- | --- |
| 1 | 주변 물건 흔들기 |
| 2 | 작은 물건 떨어뜨리기 |
| 3 | 정리된 소품 위치 변경 |
| 4 | 문 또는 서랍 열고 닫기 |
| 5 | 전등 이상 |
| 6 | 가전제품 작동 |
| 7 | 벽·문 두드리는 소리 |
| 8 | 플레이어 발소리 |
| 9 | 청소 중인 방의 오브젝트가 지진처럼 동시에 흔들림 |

프로토타입에서는 이 중 **대표 3~5개**만 구현한다 → §12.1

> **G-6 해결(사용자 확정, 2026-08-31).** 종류를 가리지 않고, 발생한 현상을 실제로 목격한
> 플레이어면 전부 `귀신 이벤트 목격`으로 쳐서 정신력 **−15**를 적용한다 → [ghost-prototype.md §4](../architecture/ghost-prototype.md).
> 물리 간섭(1·2·3·9)은 서버 권위 규칙을 따른다 → [ADR-0010](../architecture/decisions/ADR-0010-server-authoritative-furniture-physics.md)

## 7. 어택 타임

### 7.1 발동 조건 [확정]

어택 발생 경로는 두 가지다.

1. **일반 어택 판정** — 일정 주기마다 확률로 판정
2. **특수 어택 Trigger** — 특정 조건 충족 시 즉시 100% 발동

일반 어택 판정의 전제 조건(**모두** 만족):

- 귀신이 **활동 상태**일 것
- 팀 평균 정신력 **60 이하**일 것
- 경고·어택·자연 진정·강제 진정 상태가 **아닐** 것

1.1 원문이 "어택 발동 조건"으로 드는 것은 둘이다.

1. **청소 진행도 40~50% 달성**
2. 정신력 **31~60**일 때 확률표(§7.3)로 발동 여부 결정

> **해석 보류.** 1.0에서 청소 40%는 *활동 진입* 트리거였는데(§6.2) 1.1에서는 *어택 발동 조건* 쪽에
> 적혀 있다. 그런데 ① 청소 40~50%가 어택의 **필수 전제**인지(그 전에는 어택이 아예 없는지),
> ② 40~50% **구간에서만** 유효한지 50% 이후에도 유지되는지, ③ 정신력 조건과 AND인지 OR인지가
> 원문에 없다. **임의로 정하지 않는다** → [§13 G-1](#13-미결정-목록).

### 7.2 기본 어택 판정 [임시]

- 판정 주기: **10초**

```text
10초 경과
   ↓
현재 어택 가능 조건 검사
   ↓ 충족
정신력 구간별 Attack Roll
   ├─ 성공 → 경고 상태
   └─ 실패 → 10초 후 재검사
```

어택이 시작된 순간부터 다음 어택 판정을 **중지**하고, **자연 진정이 종료된 이후에 재개**한다.

### 7.3 정신력별 어택 확률 [확정 — 1.1]

| 팀 평균 정신력 | 어택 확률 | 비고 |
| --- | ---: | --- |
| 61~100 | **0%** | 걍 돌아다니기만 함 |
| 51~60 | **20%** | |
| 41~50 | **40%** | |
| 31~40 | **60%** | |
| 0~30 | **100%** | 판정이 아니라 강제 발동 |

정신력이 낮아질수록 단계적으로 증가한다.

> **1.0에서 바뀐 값: 0~30 구간 80% → 100%.** 이 구간은 더 이상 확률 판정이 아니다.
> 판정 주기(§7.2 10초)는 1.1 원문에 언급이 없어 1.0의 [임시]값을 유지한다.

### 7.4 특수 어택 Trigger [확정]

다음 상황에서는 10초 주기를 기다리지 않고 **즉시 100% 어택**을 진행한다.

- 저주받은 오브젝트 조작
- 귀신별 특수 조건
- 특정 콘텐츠 Trigger

> **원문 미완결.** "단, 이미 공격 상태일 때 특수 어택 Trigger 행동을 했다면," 에서 문장이 끊긴다.
> 이미 어택 중일 때의 처리(무시 / 지속시간 연장 / 재시작)는 [§13 G-2](#13-미결정-목록)에서 대기 중이다.

### 7.5 지속 시간과 종료 [확정 — 1.1]

| 항목 | 값 |
| --- | --- |
| 일반 어택 지속시간 | **60초** |
| 고위험 어택 지속시간 | **90초** |
| 조기 종료 조건 | **20초 이내에 정신력을 회복**하면 조기 종료 |
| 정신력 0~30일 때 | **시간이 지나도 계속 어택** |

- 어택 발동 후 **60초가 지나면 자동으로 종료**되고 자연 진정 상태로 들어간다(§4.7).
- **단, 팀 정신력이 0~30이면 60초가 지나도 계속 어택한다.**
- 어택을 강제 종료하는 **아이템**을 사용하면 즉시 종료되고 자연 진정으로 넘어간다 → §4.8.
- 플레이어가 한 명 사망하더라도 어택은 계속 유지된다.

> **원문이 비워 둔 것 2가지.**
> ① "20초 이내 정신력을 회복하면"의 **회복 기준값이 없다.** 1.0은 "팀 평균 70 이상"이었다.
> ② 0~30일 때 "계속 어택"과 고위험 어택 "90초 후 자연 진정"이 **서로 어긋난다** —
> 90초에 끝나는지, 정신력이 30을 넘을 때까지 무한히 가는지 정해지지 않았다.
> 둘 다 [§13 G-9](#13-미결정-목록)에서 대기한다. 1.0의 "최소 30초 보호구간"은 1.1에 없어 삭제했다.

## 8. 플레이어 탐지

공통 탐지는 **어택 상태에서만** 활성화한다.

### 8.1 시야 탐지 [확정]

귀신은 전방의 **원뿔형 시야 범위**를 사용한다. 다음을 **모두** 만족하면 탐지한다.

- 플레이어가 시야 범위 내부에 위치
- 귀신과 플레이어 사이에 벽·차단 가능한 장애물이 **없음**

시야에 들어온 플레이어는 즉시 추격 대상이 된다. **은신처에 들어가는 것을 시야에서 봤다면
은신처 안이어도 찾아내 죽인다** → §9.5.

| 항목 | 값 |
| --- | --- |
| 시야 거리 | **[TBD]** |
| 시야 각도 | **[TBD]** |

### 8.2 귀신 시야 표시 [확정]

어택 상태에서는 귀신의 원뿔형 시야 범위를 플레이어가 **빨간색 영역**으로 볼 수 있게 표시한다.

| 상태 | 시야 표시 |
| --- | --- |
| 활동 | 없음 |
| 경고 | 없음 |

## 9. 추격·수색 AI

### 9.1 기본 흐름 [확정]

```text
집 내부 배회
   ↓ 플레이어 탐지
추격
   ↓ 추격 가능한 플레이어 0명
마지막으로 놓친 위치 기억 → 그 위치까지 이동
   ↓
10초 수색
   ├─ 재탐지 → 추격
   └─ 실패  → 집 내부 배회
```

### 9.2 추격 [확정]

- 추격 중 시야·소리로 위치를 계속 갱신한다.
- 놓쳐도 위치 정보를 즉시 삭제하지 않고 **마지막으로 놓친 위치**를 저장해, 그 근처를 맴돌며 찾는다.

**추격 타깃 선정** [확정 — 1.1 신설]

| 항목 | 규칙 |
| --- | --- |
| 위치 확인 주기 | **0.2초** |
| 타깃 선정 | 추격 가능한 플레이어 중 **귀신과 좌표상 가장 가까운** 플레이어 |
| 동일 거리 | **기존 타깃 유지** |
| 타깃 변경 | 다른 플레이어가 기존 타깃보다 **1m 이상 가까울 때** |
| 은신 플레이어 | 타깃 후보 **제외** |
| 바닥 파기 사용 플레이어 | 타깃 후보 **제외** |

**타깃 선정은 직선거리, 실제 이동은 최단 경로다.** 벽이나 장애물이 있어도 좌표상 가장 가까운
플레이어를 타깃으로 고르고, 이동은 갈 수 있는 최단 경로로 쫓아간다.

> 1m 히스테리시스와 동일 거리 유지 규칙은 **두 플레이어 사이에서 타깃이 떨리는 것**을 막기 위한
> 것이다. 0.2초 주기와 함께 구현한다.

### 9.3 수색 [확정]

| 항목 | 규칙 |
| --- | --- |
| 수색 시작 조건 | 추격 가능한 플레이어 **0명** |
| 수색 위치 | **마지막 타깃을 놓친 위치 주변** |
| 수색 시간 | **10초** (1.0의 7초에서 변경) |
| 수색 행동 | 해당 위치 주변을 어슬렁거리며 탐색 |
| 수색 중 플레이어 등장 | **즉시 추격 재개** |
| 10초 동안 타깃 없음 | 수색 종료 → 집 내부 배회 |

수색 중에도 시야 재탐지·이동 소리 재탐지·주변 은신처 검사(→ §9.5)가 가능하다.

### 9.3.1 은신·바닥 파기 처리 [확정 — 1.1 신설]

| 상황 | 처리 |
| --- | --- |
| 플레이어가 은신 성공 | 추격 대상에서 제외 |
| 플레이어가 바닥 파기 성공 | 추격 대상에서 제외 |
| **은신 중 말하기** | **불가** |
| **은신 중 손전등 사용** | **불가** |
| 수색 중 은신 해제 | 즉시 타깃 후보로 복귀 |
| 수색 중 추격 가능한 플레이어 발생 | 즉시 추격 재개 |

> **음성 채팅과 충돌한다.** "은신 중 말하기 불가"는 근접 음성 기획서에 없는 규칙이다 —
> [voice-chat-system.md](voice-chat-system.md)는 어떤 상태에서도 말하기를 막지 않는다(§8.3).
> 어느 쪽을 따를지 [§13 G-19](#13-미결정-목록)에서 대기한다. 손전등은 시스템 자체가 아직 없다.

### 9.4 문 [확정]

귀신은 어택·수색 중 **일반 방문을 직접 열 수 있다.**
따라서 방문만 닫고 방 안에 있는 것으로는 완전한 은신이 되지 않는다.

### 9.5 은신처 [확정 / 확률은 임시]

공통 은신처: **옷장 · 침대 밑 · 책상 밑 · 땅속**

**은신을 목격했을 때** [확정 — 1.1에서 명문화]

| 은신 종류 | 처리 |
| --- | --- |
| 일반 은신처(침대 밑·옷장 등) | 귀신이 은신을 **목격** → 해당 은신처 검사 → **무조건 처치** |
| 바닥 파기 | 귀신이 보는 앞에서 사용 → 굴에 손을 넣음 → 두더지를 꺼냄 → **처치** |

숨더라도 **들어가는 장면이 귀신 시야에 있었다면 은신처여도 찾아내 죽인다**(§8.1).
아래 30% 확률 검사는 **목격당하지 않은** 은신처에만 적용된다.

**일반 은신처** — 귀신은 수색 중 근처 은신처를 발견하면 **30% 확률로 검사한다** [임시].
귀신은 플레이어가 그 안에 있다는 정보를 알고 검사하는 것이 아니라, 주변의 가능한 은신처를
**랜덤하게** 확인한다. 따라서 일반 은신처는 **완전한 안전지대가 아니다.**

> **엎드려 침대 밑 은신 — 부분 구현 (사용자 확정 2026-09-04).** "침대 밑"만 먼저 구현했다.
> 침대를 다리로 띄워 밑을 비우고, 엎드려서(`Z`) 침대 밑 상자에 완전히 들어간 상태가 **귀신에게
> 안 쫓기고 시야에도 안 걸린 채 ~1초** 이어지면 은신이 성립한다. 성립하면 탐지·잡힘·**수색
> 훔쳐보기에서 전부 빠진다**(위 30% 검사 대상이 아니다 — 일반 상자 은신처보다 강하게 확정).
> **단, 들어가는 과정을 귀신이 봤으면**(그 순간 추격/수색 대상이면) 성립하지 않고, 추격이
> 그대로 유지되며 침대 밑까지 쫓아와 **잡을 수 있다.** 귀신이 놓쳐 배회로 돌아간 뒤 계속 숨어
> 있으면 그제서야 안전해진다. 구현·수치는 [ghost-prototype.md](../architecture/ghost-prototype.md),
> [player-controller.md](../architecture/player-controller.md). 옷장·책상 밑은 아직.

> **G-8 판정 시점·주기·재검사 — 임시 구현 (사용자 확정 2026-08-31, 여전히 미정).**
> 원문·구현 모두 "수색 중 은신처에 **최초로** 접근했을 때 1회만" 30% 검사하는 것으로 임시
> 확정했다. 이번 수색(7초) 동안 같은 은신처를 다시 확인하지는 않는다. **정식 규칙(주기적
> 재판정 여부 등)은 여전히 미정**이며, 이건 플레이 테스트 전까지 쓰는 임시값이다 →
> [ghost-prototype.md §4](../architecture/ghost-prototype.md).

**땅속 은신** — 두더지 플레이어의 굴착 스킬. 정상적으로 활성화된 동안에는 귀신에게
**탐지·공격되지 않는다.** 유지 시간 5초 [확정], 쿨타임 [TBD] →
[두더지 스킬 시스템 기획서 §5](mole-skill-system.md).

> **예외 2가지 [확정 · 구현됨 2026-09-05]** — ① **귀신 시야에 이미 감지된 상태에서 매몰**한
> 경우, ② **땅굴 안에서 손전등을 사용**하는 경우에는 땅속에서도 감지된다.
>
> **①은 구현됐다.** `BurrowExposureTracker` 가 **매몰이 시작된 순간** "쫓기거나 마지막 위치를
> 수색 중인가"(`_pursuit != Roam && _target == player` — 침대 밑과 같은 기준)를 한 번 판정하고,
> 참이면 그 굴착이 끝날 때까지 **탐지·포획 양쪽에서** 땅속을 무시한다. 들어간 뒤 귀신이
> 놓쳐도 안전해지지 않는다. ②는 손전등 시스템 자체가 없어 착수할 수 없다.
>
> 이로써 **땅속 은신과 엎드려 침대 밑 은신의 규칙이 같아졌다** — 둘 다 30% 검사는 안 받되
> **들어가는 걸 봤으면 그대로 잡힌다.** 굴착은 이제 "추격을 끊는" 스킬이 아니라
> **"들키기 전에 미리 숨는"** 스킬이고, 쫓기는 중에 쓰면 이동이 잠긴 채 제자리에 묶여
> 오히려 잡히기 쉬워진다 → [mole-skill-system.md §5.2.1](mole-skill-system.md).
>
> **함께 막은 틈새** — `TryCatch` 가 굴착을 전혀 보지 않아, 탐지에서 빠진 뒤에도 수색(7초) 동안
> 남아 있는 `_target` 이 **안전하게 숨은 플레이어를 땅속에서 잡을 수 있었다.**

## 10. 공통 연출

상태 변화를 플레이어가 시청각으로 인지할 수 있게 한다.
**연출은 게임 판정과 분리한다.** 서버가 상태·사건을 확정하고 각 클라이언트가 재생한다.

### 10.1 활동 [확정]

- 별도의 상태 UI **없음**
- 초자연현상으로 존재를 간접 표현

### 10.2 활동 중 위험 전달 [확정]

귀신 상태를 **직접 UI로 표시하지 않는다.** 다음 변화로 간접 전달한다.

- 초자연현상 빈도 증가
- 물건 간섭 증가
- 이상음 증가
- 조명·환경 변화 증가

플레이어가 귀신 행동을 관찰해 위험 증가를 판단하게 한다.

### 10.3 경고 [확정]

어택 확정을 전달해야 하므로 다른 상태보다 **명확한 공통 신호**를 사용한다. 지속 5초.

- **심장 박동 소리** — 어택이 가까워졌음을 전달하는 핵심 청각 연출
- **조명이 5초 간 깜빡인다** (1.1에서 "조명 이상" → 깜빡임으로 구체화)
- 공통 경고 사운드 또는 환경음 변화

세부 사운드 디자인·VFX는 추후 연출/사운드 기획에서 정의한다 [TBD].

### 10.4 어택 [확정]

- **조명이 위험을 알리는 빨간색으로 바뀐다** (1.1 신설 — 경고의 깜빡임과 구분된다)
- 귀신 본체 시각적 노출
- 귀신 전방의 **빨간 원뿔형 시야 표시** → §8.2
- 추격 관련 사운드 활성화
- 경고 연출 → 어택 연출로 전환

### 10.5 자연 진정 [확정]

어택 관련 연출을 제거하고 환경을 점차 활동 상태 수준으로 복원한다.

- 빨간 시야 표시 제거
- 추격 사운드 종료
- 경고·어택 관련 효과 종료

### 10.6 강제 진정

아이템별 시각·청각 효과를 적용한다. 세부 연출은 아이템 기획서에서 정의한다 [TBD].

## 11. 예외 처리

### 11.1 드릴 카 세이프 존 [확정]

드릴 카는 귀신으로부터 안전한 세이프 존이다.

- 귀신은 집 밖으로 이동할 수 없고, 드릴 카 내부로 진입할 수 없다.
- 드릴 카 내부 플레이어는 **탐지 대상에서 제외**하며 공격받지 않는다.
- 한 명이 드릴 카로 이동해도 다른 플레이어에 대한 어택은 종료되지 않는다.
- **모든 플레이어가 집에서 나가도 귀신의 현재 상태는 초기화되지 않는다.**
- 어택 중 전원이 집 밖으로 나가도 **어택 타이머는 계속 진행**한다.
- 어택 종료 전에 집 안으로 재진입하면 현재 어택 상태의 영향을 다시 받는다.

### 11.2 플레이어 사망 [확정]

한 명이 어택 중 사망해도 **어택을 종료하지 않는다.**
생존 플레이어가 남아 있으면 귀신은 기존 규칙대로 계속 탐지·수색한다.

사망자의 특수능력 제한과 자유시점·생존 플레이어 관전은
[사망 후 관전 시스템 기획서](spectator-system.md)를 따른다(2026-09-12 핵심 요구 확정, 관전 구현 미착수).
관전 대상이 0명인 경우의 화면 처리와 전원 사망 시 승패 판정은 구분한다. 승패는 여전히 GDD의 TBD다.

### 11.3 중복 어택 방지 [확정]

다음 상태에서는 신규 어택 판정을 실행하지 않는다.

- 경고 · 어택 · 자연 진정 · 강제 진정

따라서 하나의 어택 진행 중 추가 어택이 중첩되는 상황은 발생하지 않는다.

### 11.4 추가 귀신 [TBD]

특수 콘텐츠로 추가 귀신이 생성될 때의 규칙은 프로토타입 이후 결정한다.

- 복수 귀신이 동시에 어택 가능한지
- 귀신별 상태를 독립적으로 관리하는지
- 하나의 공통 어택 상태를 공유하는지

## 12. 프로토타입 범위

### 12.1 반드시 만들어야 하는 시스템

> 아래 "현재" 열은 2026-08-30 재구현 기준이다. 구현 구조·수치 대응은
> [ghost-prototype.md](../architecture/ghost-prototype.md)가 단일 권위다.

| 시스템 | 구현 수준 | 현재 |
| --- | --- | --- |
| 플레이어 기본 이동 | 걷기 / 달리기 / 웅크리기 | **3단계 전부 구현** (걷기 5·달리기 ×1.4=7·웅크리기 3.5 m/s). 웅크리기는 귀신 소리 탐지 제외. `RunSpeedThreshold` 6m/s로 걷기(6m 반경)·달리기(12m 반경) 구분 |
| 정신력 시스템 | 개인 정신력 + 팀 평균 계산 | 구현됨 |
| 청소 진행도 | 실제 청소 대신 테스트용 단순화 가능 | F1 디버그 스텁 (수동 0~100%, 40% 일회성 트리거) |
| 귀신 상태 시스템 | **1.1: 활동 / 경고 / 어택 / 자연 진정** | 1.0 기준 5상태 + 강제 진정 구현, **전이는 팀 평균 정신력·청소 40%·F1 강제 기반** |
| 귀신 이동 AI | 집 내부 배회 | 상자 범위 무작위 지점 배회 구현 (NavMesh 없음) |
| 귀신 행동·초자연현상 | 대표 3~5개 | **구현** — §6.4 선정 루프 + 8종 중 6종 활성(흔들기·떨어뜨리기·문·서랍·조명·일시 출현). 소리 2종은 오디오 대기. 목격 시 정신력 −15 연결 완료(G-6) |
| 어택 판정 | 정신력별 확률 + 10초 판정 | **구현** — §7.3 확률표 + 10초 주기 |
| 플레이어 탐지 | 시야 + 걷기·달리기 소리 | 시야(15m/120°)+근거리 구현. 서버 속력 추정으로 달리기 12m / 걷기 6m / 웅크리기 무음 |
| 추격·수색 AI | 추격 → 마지막 위치 → 7초 수색 | **구현 (수색 7초)** |

### 12.3 현재 구현과의 차이

2026-08-30 재구현은 이 기획서 1.0을 기준으로 처음부터 작성했고, `[임시]` 수치는
`GhostPrototypeSettings` 에셋에 노출했다. 대응 현황은
[ghost-prototype.md §8](../architecture/ghost-prototype.md)이 단일 권위다. 남은 차이만 적는다.

> **1.1에서 새로 생긴 차이 — 구현이 아직 1.0을 따른다.** 아래는 기획이 바뀌어서 생긴 차이이며,
> 코드는 손대지 않았다. 반영 순서·범위는 사용자 확인 후 진행한다.
>
> | 항목 | 기획서 1.1 | 현재 구현(1.0 기준) |
> | --- | --- | --- |
> | 상태 개수 | 활동·경고·어택·자연 진정 (4) | 평상시 포함 **5상태 + 강제 진정** |
> | 최초 상태 | 활동 | 평상시 |
> | 정신력 구간 | 61~100 / 31~60 / 0~30 | 81~100 / 61~80 / 31~60 / 0~30 |

> | 어택 지속 | 일반 60초 / 고위험 90초 | 최소 30초 ~ 최대 90초 |
