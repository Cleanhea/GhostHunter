이 문서는 **모든 귀신에게 공통으로 적용되는** 규칙을 정의한다.

- 귀신 생성·존재 방식

### 2.3 시스템 목적

귀신은 플레이어의 청소·이사 작업을 방해하고 생존 위협을 제공하는 핵심 시스템이다.
정신력·청소 진행도·귀신별 특수 조건에 따라 활동하며, 조건을 만족하면 실제로 플레이어를
공격하는 어택 상태로 진입한다.

```text
청소·이사 작업 → 특정 조건에 따른 초자연현상 → 정신력 감소 → 경고 → 어택 → 도주·은신 → 어택 종료 → 작업 재개
```

평소에는 작업을 방해하고, 특정 순간에 직접적인 생존 위협으로 전환한다.
초자연현상의 발생·효과 규칙은 별도 기획서에서 정의한다(§2.1).

## 3. 귀신 생성과 존재 방식

### 3.1 생성 규칙 [확정]

| 항목 | 규칙 |
| --- | --- |
| 기본 생성 수 | 집 하나당 **1마리** |
| 최초 상태 | **활동** (원문 0.2 — 과거 저장소판의 평상시는 삭제됐다 → §4.3) |
| 생성 위치 | 해당 집 내부 |
| 활동 범위 | 해당 집 내부 |
| 집 밖 이동 | 불가능 |
| 드릴 카 진입 | 불가능 |
| 추가 귀신 | 특정 콘텐츠 또는 귀신별 특수 조건에 따라 생성 가능 |

- 집 하나당 기본 귀신은 **1마리** 생성한다.
- 기본 귀신은 **해당 집 내부에서만** 활동한다.
- 귀신은 집 외부와 드릴 카에 **갈 수 없다.**
- 특정 콘텐츠 또는 귀신별 특수 조건에 따라 추가 귀신이 생성될 수 있다.
  구체적인 콘텐츠·조건은 원문 0.2에 없다.

복수 귀신의 상태·어택 처리 규칙은 [§13 G-10](#13-미결정-목록)에서 대기 중이다.

### 3.2 존재 방식 [과거 저장소판의 구현 설계]

귀신은 **어택 중이 아닐 때도 집 내부에 실제 위치를 가지고 이동한다.** 실제 위치는 다음에 쓰인다.

- 주변 오브젝트 간섭
- 문·환경 오브젝트 조작
- 초자연현상 발생 기준 위치
- 귀신 이동
- 어택 시 탐색 시작 위치

### 3.3 활동 중 시각 노출 [TBD]

원문 0.2는 **활동 중인 귀신을 플레이어가 마주치면 정신력 −5**라고 정한다(§4.4).
귀신 본체가 언제 보이는지, 목격의 거리·시야각·가림 기준은 정하지 않았다.
과거 저장소판의 "본체는 경고·어택·특수 이벤트 때만 노출" 정책은 이 규칙과 함께
그대로 확정할 수 없다. 현재 구현은 사용자 요청(2026-10-29)으로 본체를 **어택에만** 표시한다 —
활동 중 목격 −5 판정은 남아 있어 보이지 않는 본체도 목격으로 친다.
노출 범위와 시간의 최종 연출은 G-17 결정이 필요하다(§12.3).

### 3.4 베이스 귀신 [확정 — 사용자 제공 원문, 2026-11-01]

## 4. 귀신 상태

귀신은 **활동·어택·자연 진정** 상태를 가진다. **경고는 5초간 플레이어에게 적용되는
어택 예고 상태**다. 아이템은 진행 중인 어택을 강제 종료해 자연 진정으로 보낸다.

> **원문 0.2 — 평상시가 사라졌다.** 과거 저장소판의 평상시·활동 2단계가 **활동 하나로 합쳐졌다.**
> 원문 §4.4가 자연 진정을 설명하며 "평상시(=활동모드)"라고 쓴 것이 근거다. 활동은 이제
> "정신력 61~100일 때의 기본 상태"이며 **그냥 배회한다.** 1.0에서 활동에 붙어 있던
> "환경 간섭·초자연현상 증가"는 원문이 초자연현상을 이 문서 범위에서 뺐으므로 §6에 근거만 남긴다.

### 4.1 상태 요약

| 상태 | 지속 시간 | 어택 판정 | 공격 | 이동 | 주체 |
| --- | --- | --- | --- | --- | --- |
| 활동 | 조건이 바뀔 때까지 | O (팀 평균 ≤ 60일 때만) | X | O | 귀신 |
| 경고 | **5초** [확정] | X | X | O | **플레이어** |
| 어택(일반) | **60초** [확정] | X | **O** | O | 귀신 |
| 어택(고위험) | **90초** [확정] | X | **O** | O | 귀신 |
| 자연 진정 | **40초** [확정 — 원문 0.3, 0.2는 30초] | X | X | O (활동과 동일) | 귀신 |

> **경고는 플레이어의 상태다** (원문 0.2 §4.2). 귀신이 아니라 **어택이 온다는 것을 플레이어에게
> 알리는** 상태이므로, 연출(심장 소리·조명 깜빡임)이 곧 이 상태의 내용이다 → §10.3.

### 4.2 전체 상태 흐름 [확정]

```text
게임 시작
   ↓
[활동]  ← 기본 상태 (정신력 61~100)
   ↓ 어택 판정 성공 (정신력 31~60 확률 / 0~30 100%)
[경고 5초]
   ↓
[어택]  일반 60초 · 고위험 90초
   ↓  탐지 → 추격 → 수색 → 공격
[자연 진정 40초]  ← 어택 확률을 계산하지 않는다
   ↓ 40초 후 현재 정신력 재확인
[활동] 또는 다시 어택 판정
```

- **활동 상태는 어택 직전 상태를 의미하지 않는다.** 활동 중 어택 판정에 실패하면 계속 활동한다.
- 어택 강제 종료 아이템을 사용하면 **즉시 자연 진정**으로 전이한다 → §4.8.

### 4.3 평상시 — 원문 0.2에서 삭제됨

**1.0의 평상시 상태는 더 이상 없다.** 귀신은 활동 상태에서 시작한다(§3.1).
1.0에서 평상시 → 활동 전환 조건이던 "정신력 80 이하 / 청소 40% 도달 / 귀신별 특수 조건"은
**전환할 대상이 없어졌다.** 청소 진행도는 원문 0.2에서 **어택 발동 조건**으로 옮겨 갔다(§7.1).

> `Idle` enum 값은 과거 데이터 호환용으로 남지만 현재 상태 기계는 진입하지 않는다.

### 4.4 활동 상태 [확정]

**기본 상태다.** 팀 평균 정신력 **61~100** 구간에서 귀신이 놓이는 상태이며,
집 내부를 **그냥 돌아다닌다.**

- 플레이어를 직접 공격할 수 **없다.**
- 팀 평균 정신력이 **60 이하**인 경우에만 기본 어택 판정을 실행할 수 있다.
- **활동 상태가 반드시 어택으로 연결되는 것은 아니다.**

**활동 중인 귀신을 목격하면 정신력이 줄어든다** [확정 — 원문 0.2].

| 항목 | 규칙 |
| --- | --- |
| 최초 목격 | 정신력 **−5** |
| 계속 보고 있을 때 | **5초마다 −5** 반복 |

> **정신력 문서와의 정합성.** [sanity-system.md §4.2](sanity-system.md)에 귀신 본체 목격 −5를
> 별도 항목으로 반영했다. 초자연현상 목격 −5와 본체 목격 −5는 **같은 프레임에 둘 다 적용(합 −10)** 하는 것이 의도다(사용자 확정 2026-10-29).
> 본체 노출·목격의 거리·시야각·가림 기준은 원문에 없다 → [§13 G-17](#13-미결정-목록).

> **원문 0.3의 표현 충돌 (G-25).** 0.3 §4.1은 정신력 61~100의 귀신을 "비활동 — 시야에 보이지 않고 활동하지 않는다"라고 적고,
> 어택 확률표는 "보이지도 않고 귀신이 없음"이라 한다. 반면 같은 문서의 정신력 표·§4.4는 같은 구간을 "활동"이라 부르고
> §4 제목도 "활동, 경고, 어택, 자연진정"이다. 이 문서는 현행 구현(활동 = 집 안 배회 + 초자연현상, 본체는 어택에만 노출)을
> 유지하고 "배회하는가 / 아예 없는가"는 결정 대기로 둔다. 본체가 평소 보이지 않는다는 점은 이미 반영돼 있다(§3.3).
> 활동 중 목격 −5(위)는 0.3 본문에 없지만 2026-10-29 사용자 확정([sanity-system.md](sanity-system.md))이라 유지한다.

### 4.5 경고 상태 [확정]

어택 판정이 성공하여 **어택 발생이 확정된** 상태다. 귀신이 아니라 **플레이어의 상태**로 정의한다.

- 지속 시간: **5초**
- 경고 중에는 신규 어택 판정을 하지 않는다.
- 연출: **심장 박동 소리** + **조명 깜빡임 5초** → §10.3
- 경고 종료 후 **어택 상태로 전환한다.**

> **해석 주의.** 원문에는 경고 도중 정신력이 회복되거나 어택 강제 종료 아이템을 사용했을 때의
> 처리 경로가 없다. 경고 취소 가능 여부는 정해지지 않았다.

### 4.6 어택 상태 [확정]

귀신이 실제로 플레이어를 탐지·추적·공격할 수 있는 상태다. **일반 어택과 고위험 어택으로 나뉜다.**

행동 흐름은 둘 다 같다: **탐지 → 추격 → 수색 → 공격**

| | 일반 어택 | 고위험 어택 |
| --- | --- | --- |
| 지속 시간 | **60초** | **90초** |
| 탐지 능력 | 기본 | **강화** → §8 |
| 종료 후 | 자연 진정 | 자연 진정 |

- 조명이 위험을 알리는 **빨간색**으로 바뀐다 → §10.4
- 플레이어 탐지 활성화 → §8 / 수색·추격 AI 활성화 → §9
- 어택 중 신규 어택 판정 **금지** (과거 저장소판의 중복 방지 규칙)
- 플레이어가 사망했을 때: **쉬움 난이도는 한 명이라도 죽으면 어택이 자동 종료**, 보통·어려움은 계속된다
  [확정 — 원문 0.3] → §7.5, 난이도 정의는 [§13 G-23](#13-미결정-목록).
- 귀신은 집 내부에서만 활동한다. 드릴 카·집 밖 플레이어는 공격할 수 **없다.**

> **고위험 어택의 발동 기준이 원문에 명시되지 않았다.** 정신력 0~30 구간의
> "100% 강제 어택·탐지 강화"와 고위험 어택의 "탐지 강화"가 같은 개념인지는
> [§13 G-18](#13-미결정-목록)에서 확인한다.

지속·종료 규칙은 §7.5.

### 4.7 자연 진정 상태 [확정]

어택 종료 후 연속 재어택을 방지하는 상태다.

- 지속 시간: **40초** (원문 0.3 — 0.2는 30초)
- **팀 정신력이 몇이든 어택 확률을 계산하지 않는다.** 0~30이어도 이 40초 동안은 어택하지 않는다.
- 귀신은 이 40초 동안 **평상시(= 활동 모드)로 지속**한다 — 배회한다.
- 신규 어택 발생 불가 / 경고 상태 진입 불가 / 플레이어 추격·공격 불가
- 40초 종료 후 **현재 정신력을 다시 확인**하고 그 구간의 규칙대로 실행한다.

```text
40초 경과 → 현재 정신력 확인
   61~100 → 활동 유지
   31~60  → 어택 확률 재판정
   0~30   → 다시 100% 어택
```

### 4.8 어택 강제 종료 아이템 [확정 / 아이템 사양 TBD]

아이템 사용 시 진행 중인 어택이 **즉시 종료**되고 **자연 진정 상태**로 들어간다(§4.7).
별도의 10초 강제 진정 상태는 원문 0.2에 없다. 코드에는 직렬화 호환용
`Suppressed` enum 값만 남았고, 아이템 API는 `Calming`으로 전환한다(§12.3).

아이템의 종류·디자인·사용 조건은 별도 아이템 기획서에서 정의한다.

## 5. 정신력 연동

정신력 수치의 정의·증감·디버프·UI는 [정신력 시스템 기획서](sanity-system.md)가 단일 권위다.
이 문서는 **그 값을 어떻게 읽어 쓰는지**만 정의한다.

### 5.1 기본 규칙 [확정]

- 각 플레이어는 개인 정신력을 가진다.
- 일반 귀신의 공통 상태 전이와 어택 판정에는 **생존 플레이어의 팀 평균 정신력**을 사용한다.
- 일부 특수 귀신은 팀 평균 대신 특정 플레이어의 **개인 정신력**을 참조할 수 있다
  (개별 귀신 기획서에서 정의).

구현상 팀 평균의 출처는 `ISanityTeamService`이며, 귀신은 자체 정신력을 갖지 않는다 →
[ghost-prototype.md §3](../architecture/ghost-prototype.md)

### 5.2 정신력 구간 [확정]

원문 0.2에서 **3구간**으로 정리됐다.

| 팀 평균 정신력 | 귀신 상태 여부 |
| --- | --- |
| 61~100 | 어택 X, **활동 O** |
| 31~60 | 확률에 따라 어택 여부를 결정하고 결과대로 실행 |
| 0~30 | **100% 강제 어택**, 탐지 강화 |

### 5.3 구간별 규칙 [확정]

**61~100** — 활동 상태다. 어택 판정을 하지 않는다. 귀신을 목격하면 정신력이 깎인다(§4.4).

**31~60** — 어택 판정을 실행할 수 있다. **이 구간에 들어갔다고 즉시 어택이 발생하지는 않는다.**
확률표(§7.3)로 판정하고 성공한 경우에만 경고 상태로 진입한다.

**0~30** — 고위험 구간이다.

- **어택 확률 100%** — 판정이 아니라 강제 발동이다.
- **탐지 강화** — 고위험 어택과 동일한 분류인지는 미결정이다(§4.6).
- 어택이 60초를 넘겨도 **계속 유지**된다(§7.5).
- 과거 저장소판의 "초자연현상 빈도 증가"·"귀신 특수 능력 사용 가능"은 원문 0.2에 없다.
  초자연현상 세부는 별도 기획서, 특수 능력은 개별 귀신 기획서 소관이다(§2.1).

## 6. 행동 빈도와 초자연현상

> **이 절은 과거 저장소판의 기록이며 원문 0.2의 확정 규칙이 아니다.** 원문은 초자연현상의
> 규칙을 별도 기획서에서 정의한다고 명시한다. 이미 구현된 현상의 근거를 추적할 수 있도록
> 아래 내용을 보존했지만, 새 공통 규칙으로 적용하거나 수치를 확정하는 근거로 쓰지 않는다.

### 6.1 기본 발생 규칙 [과거 저장소판]

- 활동 상태에서 초자연현상이 발생한다.
- 1.0의 "평상시 낮은 빈도 / 활동 높은 빈도" 2단계는 평상시가 사라져 **한 단계로 합쳐졌다.**
- 팀 평균 정신력 30 이하에서는 **추가로** 빈도가 증가한다.
- 상태별 실제 발생 주기는 프로토타입 테스트로 조정한다 [TBD].

### 6.2 청소 진행도 40% 트리거 [과거 저장소판]

청소 진행도가 **최초로** 40%에 도달하면 귀신의 방해가 강해진다.

| 도달 시점의 상태 | 처리 |
| --- | --- |
| 활동 | 활동 유지 + **일정 시간 동안 방해 빈도 증가** |

원문 0.2에서 청소 진행도는 **어택 발동 조건** 쪽으로 옮겨 갔다(§7.1) — 전환할 평상시가 없어졌기 때문이다.
현행 동작은 §7.1의 G-1 결정을 따른다.

빈도 증가 지속 시간 **90초**는 과거 저장소판의 임시값이다. 원문 0.2는 이 값을 정하지 않는다.

### 6.3 초자연현상 정의 [과거 저장소판]

초자연현상은 귀신이 플레이어를 위협하거나 작업을 방해하기 위해 발생시키는 **비공격 행동**이다.
공격은 하지 않지만 방해하는 모든 현상을 초자연현상으로 정의한다.

- **초자연현상 자체로는 플레이어가 사망하지 않는다.**
  사망은 어택 상태에서 귀신에게 잡혔을 때만 발생한다.

역할:

- 공포 연출
- 정신력 감소
- 작업 방해
- 귀신 존재 위치 암시
- 플레이어 이동·행동 유도

### 6.4 현상 선정 방식 [과거 저장소판]

```text
1. 현재 귀신 상태 확인
2. 초자연현상 발생 여부 판정
3. 현재 실행 가능한 초자연현상 Pool 확인
4. Pool 내부에서 랜덤 선택
5. 현상 실행
6. 직전에 실행한 현상은 다음 선택 Pool에서 제외
```

6단계로 동일 현상의 연속 발생을 방지한다.

### 6.5 초자연현상 종류 [과거 저장소판]

| # | 현상 |
| --- | --- |
| 1 | 주변 물건 흔들기 |
| 2 | 작은 물건 떨어뜨리기 |
| 3 | 정리된 소품 위치 변경 |
| 4 | 문 또는 서랍 열고 닫기 |
| 5 | 전등 이상 |
| 6 | 가전제품 작동 |
| 7 | 벽·문 두드리는 소리 |
| 8 | 플레이어 발소리 |
| 9 | 청소 중인 방의 오브젝트가 지진처럼 동시에 흔들림 |

프로토타입에서는 이 중 **대표 3~5개**만 구현한다 → §12.1

> **G-6 해결(사용자 확정, 2026-08-31).** 종류를 가리지 않고, 발생한 현상을 실제로 목격한
> 플레이어면 전부 `귀신 이벤트 목격`으로 쳐서 정신력 **−5**(2026-10-29: 15 → 5)를 적용한다 → [ghost-prototype.md §4](../architecture/ghost-prototype.md).
> 물리 간섭(1·2·3·9)은 서버 권위 규칙을 따른다 → [ADR-0010](../architecture/decisions/ADR-0010-server-authoritative-furniture-physics.md)

## 7. 어택 타임

### 7.1 발동 조건 [확정 — 원문 0.3 / 세부 G-22]

어택 발동 조건은 둘이다.

1. **청소 진행도 40~50% 달성 ⇒ 무조건 한 번 어택 발동.** 이 조건으로 한 번 발동한 뒤에는 청소 진행도가 다시 40~50%여도
   발동하지 않는다 — **일회성**이다.
2. 정신력 **31~60**일 때 확률표(§7.3)로 발동 여부를 결정하고, 발동되면 어택을 시작한다. 0~30은 강제 발동이다.

> **G-1 재개 (2026-11-01).** 이전 문서는 2026-09-27 사용자 결정으로 "청소 40% 도달은 어택의 **필수 전제**이고, 도달 전에는
> 정신력이 0~30이어도 어택하지 않는다"라고 적었다. 원문 0.3은 40~50%를 **일회성 강제 발동 트리거**로 적고, 정신력 기반
> 발동에는 청소 진행도 전제를 달지 않았다. 두 서술은 양립하지 않는다. 문서는 0.3을 기준으로 하되 이전 결정을 뒤집는 일이라
> **G-22에서 확인한다.** 현재 코드는 이전 결정(필수 전제)대로 동작한다.

### 7.2 기본 어택 판정 [과거 프로토타입 / 현행 주기 TBD]

- 프로토타입 판정 주기: **10초**. 원문 0.2에는 주기가 없다(§13 G-20).

```text
10초 경과
   ↓
현재 어택 가능 조건 검사
   ↓ 충족
정신력 구간별 Attack Roll
   ├─ 성공 → 경고 상태
   └─ 실패 → 10초 후 재검사
```

어택이 시작된 순간부터 다음 어택 판정을 **중지**하고, **자연 진정이 종료된 이후에 재개**한다.

### 7.3 정신력별 어택 확률 [확정 — 원문 0.2]

| 팀 평균 정신력 | 어택 확률 | 비고 |
| --- | ---: | --- |
| 61~100 | **0%** | 0.2: "돌아다니기만 함" / 0.3: "보이지도 않고 귀신이 없음" → G-25 |
| 51~60 | **20%** | |
| 41~50 | **40%** | |
| 31~40 | **60%** | |
| 0~30 | **100%** | 판정이 아니라 강제 발동 |

정신력이 낮아질수록 단계적으로 증가한다.

> **1.0에서 바뀐 값: 0~30 구간 80% → 100%.** 이 구간은 더 이상 확률 판정이 아니다.
> 판정 주기는 원문 0.2에 없다. 현재 프로토타입이 쓰는 10초는 현행 규칙으로 확정되지 않았다(§7.2).

### 7.4 특수 어택 Trigger [과거 저장소판 / 현행 규칙 TBD]

과거 저장소판은 다음 상황에서 10초 주기 없이 **즉시 100% 어택**으로 정의했다.
원문 0.2는 귀신별 특수 조건에 따른 추가 귀신만 언급하며, 특수 어택 Trigger 자체는 정의하지 않는다.

- 저주받은 오브젝트 조작
- 귀신별 특수 조건
- 특정 콘텐츠 Trigger

> 위 특수 어택 Trigger는 원문 0.2가 정의하지 않는다. 유지 여부와 이미 어택 중일 때의 처리는
> [§13 G-2](#13-미결정-목록)에서 대기 중이다.

### 7.5 지속 시간과 종료 [원문 0.3 / 일부 충돌 TBD]

| 항목 | 값 |
| --- | --- |
| 일반 어택 지속시간 | **60초** |
| 고위험 어택 지속시간 | **90초** |
| 조기 종료 조건 | **어택 시작 후 60초 이내** 팀 평균 정신력을 **61~100**으로 올리면 귀신이 사라지고 종료 (0.2는 20초 이내) |
| 쉬움 난이도에서 사망 | **한 명이라도 죽으면 어택 자동 종료** (원문 0.3) |
| 보통·어려움에서 사망 | 팀원이 죽어도 **어택은 계속** (원문 0.3) |
| 정신력 0~30일 때 | **시간이 지나도 계속 어택** |

- **일반 어택**은 60초 후, **고위험 어택**은 90초 후 자연 진정으로 들어간다고 적혀 있다(§4.7).
- 다만 종료 조건에는 **팀 정신력이 0~30이면 60초가 지나도 계속 어택한다**고도 적혀 있다.
- 어택을 강제 종료하는 **아이템**을 사용하면 즉시 종료되고 자연 진정으로 넘어간다 → §4.8.
- 쉬움 난이도는 한 명이라도 죽으면 어택이 종료되고, 보통·어려움은 사망해도 계속된다. 종료 후 상태(자연 진정으로 가는지)와
  난이도의 정의는 원문 0.3에 없다 → G-23.

> **G-9 부분 결정(2026-09-27, 시한은 원문 0.3에서 변경):** 조기 종료 기준은 **61 이상**이고, 시한은 20초에서 **60초 이내**로 바뀌었다. 0~30일 때
> "계속 어택"과 고위험 90초 종료의 충돌은 아직 결정 대기다. 현재 코드는 고위험 어택을
> 90초에 자연 진정으로 보내는 임시 해석을 쓴다. 과거의 최소 30초 보호구간은 제거했다.

## 8. 플레이어 탐지

공통 탐지는 **어택 상태에서만** 활성화한다.

### 8.1 시야 탐지 [확정]

귀신은 전방의 **원뿔형 시야 범위**를 사용한다. 다음을 **모두** 만족하면 탐지한다.

- 플레이어가 시야 범위 내부에 위치
- 귀신과 플레이어 사이에 벽·차단 가능한 장애물이 **없음**

시야에 들어온 플레이어는 즉시 추격 대상이 된다. **은신처에 들어가는 것을 시야에서 봤다면
은신처 안이어도 찾아내 죽인다** → §9.5.

| 항목 | 값 |
| --- | --- |
| 시야 범위 — 튜토리얼 | **조금 짧게. 지금보다 절반 정도로 줄인다** [방향 확정 — 원문 0.3 / 수치 G-24] |
| 시야 범위 — 대저택 맵 | **프로토타입에 적용된 범위와 동일** (현재 15m / 120°) |
| 시야 각도 | **[TBD]** — 0.3은 "범위"만 말하고 각도를 따로 정하지 않았다 |

### 8.2 귀신 시야 표시 [과거 저장소판]

원문 0.2는 **어택 중 조명이 빨간색**이라고 정한다. 아래 빨간 원뿔형 시야 표시 UI는
과거 저장소판의 별도 규칙이며 원문 0.2에는 없다.

어택 상태에서는 귀신의 원뿔형 시야 범위를 플레이어가 **빨간색 영역**으로 볼 수 있게 표시한다.

| 상태 | 시야 표시 |
| --- | --- |
| 활동 | 없음 |
| 경고 | 없음 |
| **어택** | **표시** |
| 자연 진정 | 없음 |

> **기획 의도**
> 귀신의 시선을 피해 이동하는 회피 플레이를 가능하게 하고, 빨간 영역이 자신이 숨은 곳에
> 닿을까 불안해하도록 만든다.

## 9. 추격·수색 AI

> **2026-09-30 AI 실험 모드:** 사용자 요청으로 단서 추적·수색 점수화·예측·가구 충돌 조사·
> 공포 간격 조절을 개별 토글로 추가했다. 기본 에셋은 ON이며, 아래 정식 좌표 추격·수색 조건은
> 전체 실험 또는 해당 토글 OFF에서 적용한다. [실험 범위·수치·사용법](ghost-ai-experiments.md).

### 9.1 기본 흐름 [확정]

```text
집 내부 배회
   ↓ 플레이어 탐지
추격
   ↓ 추격 가능한 플레이어 0명
마지막으로 놓친 위치 기억 → 그 위치까지 이동
   ↓
10초 수색
   ├─ 재탐지 → 추격
   └─ 실패  → 집 내부 배회
```

### 9.2 추격 [확정]

- 추격 중 시야·소리로 위치를 계속 갱신한다.
- 놓쳐도 위치 정보를 즉시 삭제하지 않고 **마지막으로 놓친 위치**를 저장해, 그 근처를 맴돌며 찾는다.

**추격 타깃 선정** [확정 — 원문 0.2]

| 항목 | 규칙 |
| --- | --- |
| 위치 확인 주기 | **0.2초** |
| 타깃 선정 | 추격 가능한 플레이어 중 **귀신과 좌표상 가장 가까운** 플레이어 |
| 동일 거리 | **기존 타깃 유지** |
| 타깃 변경 | 다른 플레이어가 기존 타깃보다 **1m 이상 가까울 때** |
| 은신 플레이어 | 타깃 후보 **제외** |
| 바닥 파기 사용 플레이어 | 타깃 후보 **제외** |

**타깃 선정은 직선거리, 실제 이동은 최단 경로다.** 벽이나 장애물이 있어도 좌표상 가장 가까운
플레이어를 타깃으로 고르고, 이동은 갈 수 있는 최단 경로로 쫓아간다.

> 1m 히스테리시스와 동일 거리 유지 규칙은 **두 플레이어 사이에서 타깃이 떨리는 것**을 막기 위한
> 것이다. 0.2초 주기와 함께 구현한다.

### 9.3 수색 [확정]

| 항목 | 규칙 |
| --- | --- |
| 수색 시작 조건 | 추격 가능한 플레이어 **0명** |
| 수색 위치 | **마지막 타깃을 놓친 위치 주변** |
| 수색 시간 | **10초** (1.0의 7초에서 변경) |
| 수색 행동 | 해당 위치 주변을 어슬렁거리며 탐색 |
| 수색 중 플레이어 등장 | **즉시 추격 재개** |
| 10초 동안 타깃 없음 | 수색 종료 → 집 내부 배회 |

수색 중에도 시야 재탐지·이동 소리 재탐지·주변 은신처 검사(→ §9.5)가 가능하다.

### 9.3.1 은신·바닥 파기 처리 [확정 — 원문 0.2]

| 상황 | 처리 |
| --- | --- |
| 플레이어가 은신 성공 | 추격 대상에서 제외 |
| 플레이어가 바닥 파기 성공 | 추격 대상에서 제외 |
| **은신 중 말하기** | **허용 — 2026-09-27 사용자 결정** |
| **은신 중 손전등 사용** | **불가** |
| 수색 중 은신 해제 | 즉시 타깃 후보로 복귀 |
| 수색 중 추격 가능한 플레이어 발생 | 즉시 추격 재개 |

> **G-19 결정:** 음성 송신은 [voice-chat-system.md §8.3](voice-chat-system.md)의
> 모든 상태 허용 규칙을 따른다. 손전등은 안전모 **헤드라이트**로 구현했다(2026-09-28) — 은신처 상자 안이나
> 엎드려 침대 밑 공간에 들어가면 자동으로 꺼지고 그 안에서는 켤 수 없다 → [headlamp-system.md](headlamp-system.md).

### 9.4 문 [과거 저장소판]

귀신은 어택·수색 중 **일반 방문을 직접 열 수 있다.**
따라서 방문만 닫고 방 안에 있는 것으로는 완전한 은신이 되지 않는다.

### 9.5 은신처 [목격 시 처치 확정 / 나머지는 과거 저장소판]

공통 은신처: **옷장 · 침대 밑 · 책상 밑 · 땅속**

**은신을 목격했을 때** [확정 — 원문 0.2]

| 은신 종류 | 처리 |
| --- | --- |
| 일반 은신처(침대 밑·옷장 등) | 귀신이 은신을 **목격** → 해당 은신처 검사 → **무조건 처치** |
| 바닥 파기 | 귀신이 보는 앞에서 사용 → 굴에 손을 넣음 → 두더지를 꺼냄 → **처치** |

숨더라도 **들어가는 장면이 귀신 시야에 있었다면 은신처여도 찾아내 죽인다**(§8.1).
목격하지 않은 은신처의 처리 방식은 원문 0.2에 없다. 아래 30% 확률 검사는 과거 프로토타입에만 적용됐다.

**과거 프로토타입의 일반 은신처 검사** — 원문 0.2에는 목격하지 않은 은신처를
검사할 확률이 없다. 과거 프로토타입은 수색 중 근처 은신처를 발견하면 **30% 확률로 검사했다** [임시].
귀신은 플레이어가 그 안에 있다는 정보를 알고 검사하는 것이 아니라, 주변의 가능한 은신처를
**랜덤하게** 확인한다. 따라서 일반 은신처는 **완전한 안전지대가 아니다.**

> **엎드려 침대 밑 은신 — 부분 구현 (사용자 확정 2026-09-04).** "침대 밑"만 먼저 구현했다.
> 침대를 다리로 띄워 밑을 비우고, 엎드려서(`Z`) 침대 밑 상자에 완전히 들어간 상태가 **귀신에게
> 안 쫓기고 시야에도 안 걸린 채 ~1초** 이어지면 은신이 성립한다. 성립하면 탐지·잡힘·**수색
> 훔쳐보기에서 전부 빠진다**(위 30% 검사 대상이 아니다 — 일반 상자 은신처보다 강하게 확정).
> **단, 들어가는 과정을 귀신이 봤으면**(그 순간 추격/수색 대상이면) 성립하지 않고, 추격이
> 그대로 유지되며 침대 밑까지 쫓아와 **잡을 수 있다.** 귀신이 놓쳐 배회로 돌아간 뒤 계속 숨어
> 있으면 그제서야 안전해진다. 구현·수치는 [ghost-prototype.md](../architecture/ghost-prototype.md),
> [player-controller.md](../architecture/player-controller.md). 옷장·책상 밑은 아직.

> **G-8 판정 시점·주기·재검사 — 임시 구현 (사용자 확정 2026-08-31, 여전히 미정).**
> 과거 저장소판·구현은 "수색 중 은신처에 **최초로** 접근했을 때 1회만" 30% 검사하는 것으로 임시
> 확정했다. 이번 수색(7초) 동안 같은 은신처를 다시 확인하지는 않는다. **정식 규칙(주기적
> 재판정 여부 등)은 여전히 미정**이며, 이건 플레이 테스트 전까지 쓰는 임시값이다 →
> [ghost-prototype.md §4](../architecture/ghost-prototype.md).

**땅속 은신** — 두더지 플레이어의 굴착 스킬. 정상적으로 활성화된 동안에는 귀신에게
**탐지·공격되지 않는다.** 유지 시간 5초 [확정], 쿨타임 [TBD] →
[두더지 스킬 시스템 기획서 §5](mole-skill-system.md).

> **예외 2가지 [확정 · 구현됨 2026-09-05]** — ① **귀신 시야에 이미 감지된 상태에서 매몰**한
> 경우, ② **땅굴 안에서 손전등을 사용**하는 경우에는 땅속에서도 감지된다.
>
> **①은 구현됐다.** `BurrowExposureTracker` 가 **매몰이 시작된 순간** "쫓기거나 마지막 위치를
> 수색 중인가"(`_pursuit != Roam && _target == player` — 침대 밑과 같은 기준)를 한 번 판정하고,
> 참이면 그 굴착이 끝날 때까지 **탐지·포획 양쪽에서** 땅속을 무시한다. 들어간 뒤 귀신이
> 놓쳐도 안전해지지 않는다. **②도 구현됐다(2026-09-28, 헤드라이트)** — 땅속에서 헤드라이트가 켜져 있으면
> 귀신에게는 숨지 않은 플레이어로 보여 그대로 탐지·포획된다 → [headlamp-system.md](headlamp-system.md).
>
> 이로써 **땅속 은신과 엎드려 침대 밑 은신의 규칙이 같아졌다** — 둘 다 30% 검사는 안 받되
> **들어가는 걸 봤으면 그대로 잡힌다.** 굴착은 이제 "추격을 끊는" 스킬이 아니라
> **"들키기 전에 미리 숨는"** 스킬이고, 쫓기는 중에 쓰면 이동이 잠긴 채 제자리에 묶여
> 오히려 잡히기 쉬워진다 → [mole-skill-system.md §5.2.1](mole-skill-system.md).
>
> **함께 막은 틈새** — `TryCatch` 가 굴착을 전혀 보지 않아, 탐지에서 빠진 뒤에도 수색(7초) 동안
> 남아 있는 `_target` 이 **안전하게 숨은 플레이어를 땅속에서 잡을 수 있었다.**

## 10. 공통 연출

상태 변화를 플레이어가 시청각으로 인지할 수 있게 한다.
**연출은 게임 판정과 분리한다.** 서버가 상태·사건을 확정하고 각 클라이언트가 재생한다.
원문 0.2에서 명시된 공통 연출은 **경고의 심장 소리·5초 조명 깜빡임과 어택의 빨간 조명**이다.
그 밖의 항목은 과거 저장소판의 연출 기록이며 원문 0.2의 확정 규칙이 아니다.

### 10.1 활동 [확정]

- 별도의 상태 UI **없음**
- 초자연현상으로 존재를 간접 표현

### 10.2 활동 중 위험 전달 [확정]

귀신 상태를 **직접 UI로 표시하지 않는다.** 다음 변화로 간접 전달한다.

- 초자연현상 빈도 증가
- 물건 간섭 증가
- 이상음 증가
- 조명·환경 변화 증가

플레이어가 귀신 행동을 관찰해 위험 증가를 판단하게 한다.

### 10.3 경고 [확정]

어택 확정을 전달해야 하므로 다른 상태보다 **명확한 공통 신호**를 사용한다. 지속 5초.

- **심장 박동 소리** — 어택이 가까워졌음을 전달하는 핵심 청각 연출
- **조명이 5초 간 깜빡인다** (원문 0.2)
- 공통 경고 사운드 또는 환경음 변화

세부 사운드 디자인·VFX는 추후 연출/사운드 기획에서 정의한다 [TBD].

### 10.4 어택 [확정]

- **조명이 위험을 알리는 빨간색으로 바뀐다** (원문 0.2 — 경고의 깜빡임과 구분된다)
- 귀신 본체 시각적 노출
- 귀신 전방의 **빨간 원뿔형 시야 표시** → §8.2
- 추격 관련 사운드 활성화
- 경고 연출 → 어택 연출로 전환

### 10.5 자연 진정 [확정]

어택 관련 연출을 제거하고 환경을 점차 활동 상태 수준으로 복원한다.

- 빨간 시야 표시 제거
- 추격 사운드 종료
- 경고·어택 관련 효과 종료

### 10.6 어택 강제 종료 아이템

아이템별 시각·청각 효과를 적용한다. 세부 연출은 아이템 기획서에서 정의한다 [TBD].

## 11. 예외 처리

### 11.1 드릴 카 세이프 존 [진입 불가 확정 / 세부는 과거 저장소판]

드릴 카는 귀신으로부터 안전한 세이프 존이다.
원문 0.2는 **귀신이 집 밖과 드릴 카에 들어갈 수 없다**고만 정한다.
아래 플레이어 탐지·타이머 세부 처리는 과거 저장소판의 보충 규칙이다.

- 귀신은 집 밖으로 이동할 수 없고, 드릴 카 내부로 진입할 수 없다.
- 드릴 카 내부 플레이어는 **탐지 대상에서 제외**하며 공격받지 않는다.
- 한 명이 드릴 카로 이동해도 다른 플레이어에 대한 어택은 종료되지 않는다.
- **모든 플레이어가 집에서 나가도 귀신의 현재 상태는 초기화되지 않는다.**
- 어택 중 전원이 집 밖으로 나가도 **어택 타이머는 계속 진행**한다.
- 어택 종료 전에 집 안으로 재진입하면 현재 어택 상태의 영향을 다시 받는다.

### 11.2 플레이어 사망 [원문 0.3 — 난이도별]

| 난이도 | 한 명이 어택 중 사망하면 |
| --- | --- |
| 쉬움 | **어택 자동 종료** |
| 보통 · 어려움 | **어택 계속.** 생존 플레이어가 남아 있으면 귀신은 기존 규칙대로 계속 탐지·수색한다 |

난이도를 어떻게 정하는지, 쉬움에서 종료된 뒤 상태는 무엇인지는 원문에 없다 → G-23. Tutorial 맵은 "쉬움"으로 기록돼 있다
([tutorial-stage.md](tutorial-stage.md)).

사망자의 특수능력 제한과 자유시점·생존 플레이어 관전은
[사망 후 관전 시스템 기획서](spectator-system.md)를 따른다(2026-09-12 핵심 요구 확정, 관전 구현 미착수).
관전 대상이 0명인 경우의 화면 처리와 전원 사망 시 전멸 판정은 구분한다. 전멸 규칙은 [죽음 시스템 기획서 §8](death-system.md#8-전멸했을-경우)를 따른다.

### 11.3 중복 어택 방지 [과거 저장소판]

다음 상태에서는 신규 어택 판정을 실행하지 않는다.

- 경고 · 어택 · 자연 진정

따라서 하나의 어택 진행 중 추가 어택이 중첩되는 상황은 발생하지 않는다.
과거 코드의 `Suppressed` 상태는 원문 0.2의 귀신 상태가 아니다(§4.8).

### 11.4 추가 귀신 [TBD]

특수 콘텐츠로 추가 귀신이 생성될 때의 규칙은 프로토타입 이후 결정한다.

- 복수 귀신이 동시에 어택 가능한지
- 귀신별 상태를 독립적으로 관리하는지
- 하나의 공통 어택 상태를 공유하는지
