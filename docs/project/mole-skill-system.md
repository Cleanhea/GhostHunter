- 스킬 사용 연출과 재사용 대기 UI

### 2.3 시스템 개요 [확정]

- 두더지 스킬은 **모든 플레이어 캐릭터가 지니는 고유 스킬**이다.
- 스테이지 내에서 **생존 중인 모든 플레이어 캐릭터**가 사용할 수 있다.
- 두더지 스킬은 **총 2개**로 구성된다.

| 스킬 | 한 줄 정의 | 상세 |
| --- | --- | --- |
| **탐지** | 레이저 장비로 5초 동안 모든 얼룩과 이동해야 하는 가구를 확인한다 (**Q**) | [§4](#4-탐지-스킬) |
| **굴착** | 5초간 땅을 파고 들어가 몸을 숨기고, 종료 시 공중으로 4m 튀어오른다 (**T**) | [§5](#5-굴착-스킬) |

두 스킬은 **같은 형태의 시전 시간 / 쿨타임 UI를 공유한다** → §6.

### 2.4 기획 의도

> **기획 의도**
> - 플레이에 필요한 스킬을 **'두더지'의 특성**을 반영해 기획하여, '두더지 외계인'이라는
>   플레이어 캐릭터의 매력을 살린다.
> - **탐지** — 가구 이동과 청소가 필요한 곳을 시각적으로 피드백하여, 플레이어가 작업을
>   오래 헤매지 않도록 한다.
> - **굴착** — 귀신의 어택에 플레이어가 대응할 수 있게 하여, 일방적으로 공격당한다는
>   불합리함을 줄이고 스킬을 활용한 전략적·피지컬적 회피를 가능하게 한다.

## 3. 스킬 공통 규칙

### 3.1 사용 자격 [확정]

- 스테이지 내에서 **생존 중인** 모든 플레이어 캐릭터가 사용할 수 있다.
- 플레이어 캐릭터가 **사망 상태일 때는 모든 두더지 스킬의 사용이 제한된다.**

2026-09-12 사용자 요청으로 사망 후 **자유시점 / 생존 플레이어 관전** 두 모드가 추가됐다.
두 모드 모두 이 사용 제한을 적용한다. 관전 전환과 진행 중 능력 정리 결정은
[사망 후 관전 기획서 §2·§5](spectator-system.md)를 따른다. 탐지 시전·표시 중 사망 처리(MS-20)는
그 문서의 SP-2와 같은 결정이며, 확정 시 양쪽 문서와 `CancelOnDeath` 구현을 함께 갱신한다.

사망 외에 사용이 제한되는 상태(기절·드릴 카 내부·정신력 디버프 등)는 [TBD] → MS-15.

### 3.2 사용 횟수 [확정]

- 모든 두더지 스킬은 **횟수 제한 없이 무제한으로** 사용할 수 있다.
- 소지품·자원을 소모하지 않는다.

### 3.3 재사용 대기 시간 [확정 / 공유 여부 TBD]

- 모든 두더지 스킬은 **사용 종료 후** 재사용 대기 시간을 거친다.
  대기는 사용 **시작**이 아니라 **종료** 시점부터 센다.
| 스킬 | 재사용 대기 시간 | 근거 |
| --- | --- | --- |
| **탐지** | **10초** [확정] | 플로우차트 |
| **굴착** | **10초** [확정] | 사용자 확정 2026-09-05 |

**두 스킬 모두 10초다.** 굴착은 `MoleBurrowSettings_Default.asset` 의 `_cooldownSeconds` 가
**이미 10** 이라 값 변경이 필요 없다(이 문서가 "3초 임의값"이라고 적어 왔던 것은 오기다 — §8).

- 두 스킬이 대기 시간을 공유하는지, 각각 독립인지는 [TBD] → MS-3 잔여.
  탐지 플로우가 "**탐지** 스킬이 사용중인 상태가 아닌가"처럼 스킬 단위로 묻는 것을 보면
  독립으로 읽히지만, 명시된 문장은 없다. **수치가 같아져서 실질 차이는 "굴착 쿨타임 동안
  탐지도 막히는가" 하나만 남는다.**

### 3.4 사용 가능 판정 [확정 — 탐지 기준]

탐지 플로우차트([§4.2](#42-스킬-플로우-확정))가 판정 3개를 순서대로 정의했다.
**세 개가 모두 참이어야 시전되고, 하나라도 거짓이면 입력을 무시한다** — 실패해도 대기열에
쌓이지 않고 그냥 버린다.

| 순서 | 판정 | 거짓일 때 |
| --- | --- | --- |
| 1 | **플레이어가 생존 상태인가** | 입력 무시 |
| 2 | **그 스킬이 사용 중인 상태가 아닌가** | 입력 무시 |
| 3 | **재사용 대기 시간 == 0** | 입력 무시 |

> **굴착은 판정 2가 다르게 동작한다.** 굴착은 사용 중에 키를 다시 누르면 **즉시 종료**하므로
> (§5.3), "사용 중이면 무시"가 아니라 "사용 중이면 종료"다. 굴착 플로우차트가 오면 확인한다.

**남은 것** → MS-2: 위 3개가 **두 스킬 공통 규칙인지**(굴착 플로우 미전달), 그리고 사망 외에
막히는 상태(기절·드릴 카 내부·정신력 디버프)가 있는지(MS-15). 탐지는
`DetectionSkillStateMachine.TryStart`에서 세 판정을 명시적으로 검사하며, 굴착의 토글 종료 규칙은
§5.3을 따른다.

### 3.5 입력 [탐지 Q 확정 / 굴착 키 충돌]

| 스킬 | 키 | 액션 | 상태 |
| --- | --- | --- | --- |
| 탐지 | **Q** [확정 — 원문 1.0] | `Player/Detect` | **구현됨** — `PlayerInputReader.DetectPressedThisFrame` 로 로컬 소유자에게 전달 |
| 굴착 | **T** [확정 — 사용자 2026-09-05] | `Player/Burrow` | 바인딩 완료 (`<Keyboard>/t`) |

**굴착 키는 T로 확정됐다** (MS-16 해소).

- 원문 1.0은 **E**로 적었지만, `Interact`(문 여닫기)가 이미 E를 써서 같은 프레임에 문 토글과
  굴착이 함께 발동한다. 이 충돌 때문에 프로토타입은 **R**(커밋 `e851cff`) → **T**(커밋 `0aad69e`)로
  옮겼고, **실제 바인딩인 T를 그대로 확정값으로 채택**했다. 원문의 E는 채택하지 않는다.
- `ProjectWiringTests`의 굴착 키 단언도 확정값 **T**에 맞춰져 있다.
- 이 확정은 "일단 굴러가게 두는" 선택이다. 정식 키 배치를 다시 잡을 때 재검토할 수 있다.

탐지의 Q는 원문 1.0에서 확정됐으므로 [gdd.md §3.1](gdd.md) 표와
[player-controller.md](../architecture/player-controller.md)에 함께 반영했다.
`Player/Detect` 액션은 `Assets/InputSystem_Actions.inputactions`에 생성되어 있으며, 실제 프리팹
컴포넌트·씬 UI 배선은 `GhostHunter/두더지 스킬(탐지·공통 UI) 설치` 멱등 메뉴가 수행한다.

굴착은 **스킬 키를 한 번 더 누르면 즉시 종료**하므로(§5.3), 굴착 액션은 토글 입력이다
(`MoleBurrowController` — `PlayerInputReader.BurrowPressedThisFrame` 의 눌림 엣지만 본다).

### 3.6 네트워크 권위 [탐지 로컬 / 굴착 프로토타입]

탐지 스킬은 **순수 로컬**이다. `DetectionSkillController`는 소유자 오브젝트에서만 Update를
돌고 `DetectionTargetMarker`의 머티리얼만 바꾸며 `NetworkVariable`·RPC를 사용하지 않는다.
따라서 다른 클라이언트에는 탐지 색상·UI 상태가 전파되지 않는다.

이 저장소는 **물리 상태의 권위를 서버에 두고**, 소유자 권위 예외는 플레이어 이동 하나뿐이다
→ [ADR-0008](../architecture/decisions/ADR-0008-owner-authoritative-player-movement.md) ·
[ADR-0010](../architecture/decisions/ADR-0010-server-authoritative-furniture-physics.md).

**프로토타입은 굴착을 이동 권위의 연장으로 구현했다** — `PlayerMotor.IsCrouching`과 같은
Owner-write / Everyone-read `NetworkVariable<bool>`(`MoleBurrowController.IsBurrowed`)로,
`SanityNetworkState.IsCrouching`이 이미 검증한 것과 같은 패턴이다. 서버(귀신 AI)는 이 값을
그대로 신뢰해 탐지를 건너뛴다(§9 GhostPrototypeController.TryDetectPlayer). **이것이 정식
ADR을 대체하지는 않는다** — 위 코드 패턴을 새 소유자 권위 예외로 굳히려면 여전히 ADR이
필요하다 → MS-13 잔존.

### 3.7 용어 충돌 주의

이 문서의 **탐지**는 플레이어가 쓰는 스킬 이름이다.
[ghost-system.md §8](ghost-system.md)의 **탐지**는 귀신이 플레이어를 찾는 판정이다.
**둘은 다른 시스템이다.** 코드·문서에서 혼동하지 않도록 표기한다.

| 개념 | 주체 | 문서 |
| --- | --- | --- |
| 탐지 스킬 | 플레이어 | 이 문서 §4 |
| 플레이어 탐지 | 귀신 | [ghost-system.md §8](ghost-system.md) |

## 4. 탐지 스킬

### 4.1 정의 [확정]

**레이저 장비**를 통해 **5초 동안 맵 안의 다음 대상을 전부** 보여 주는 스킬이다.

- **옮겨야 하는 가구**
- **닦아야 하는 얼룩** (피·구정물 등)

| 항목 | 값 |
| --- | --- |
| 입력 키 | **Q** [확정] |
| 표시 범위 | **맵 전체** [확정] — "맵 내에 존재하는 모든" |
| 표시 대상 | **시전한 플레이어의 카메라에만** [확정 — MS-6 해소] |
| 시전 중 조작 | **제한 없음** [확정] — 이동·시점·던지기·상호작용 전부 그대로 가능 |

> **굴착과 정반대의 스킬이다.** 굴착은 조작을 잠그고 몸을 숨기지만, 탐지는 아무것도 잠그지
> 않는다. 즉 탐지는 "켜 두고 계속 플레이하는" 스킬이다.

### 4.2 스킬 플로우 [확정]

![탐지 스킬 플로우](../images/DetectSkillFlow.png)

> `docs/images/DetectSkillFlow.png` (2026-09-05 수령). **굴착 스킬 플로우는 아직 없다.**

```
스킬 키(Q) 입력
  ├─ 플레이어가 생존 상태인가?        ─No→ 입력 무시 (스킬 사용 X)
  ├─ 탐지 스킬이 사용중이 아닌가?     ─No→ 입력 무시
  └─ 재사용 대기 시간 == 0 인가?      ─No→ 입력 무시
        │ Yes
        ▼
  탐지 스킬 시전 연출 (임시 0.5초, 카운트는 아직 시작하지 않음)
        ▼
  5초 표시 카운트 시작
        ▼
  카운트 종료 후, 스킬 시전 종료
        ▼
  재사용 대기 시간 10초 부여
```

**플로우차트가 새로 정의한 것**

| 항목 | 값 | 해소 |
| --- | --- | --- |
| 사용 가능 판정 3개 | 생존 / 미사용 중 / 쿨타임 0 | MS-2 부분 |
| 판정 실패 시 처리 | **입력 무시** — 대기열에 쌓지 않고 버린다 | — |
| **탐지 재사용 대기 시간** | **10초** | MS-3 부분 |
| 쿨타임 부여 시점 | **시전 종료 후** — §3.3의 "종료 시점부터 센다"와 일치 | — |

> **플로우차트에 §4.4 시전 연출(레이저 포인터 → 화면 파란빛)이 그려져 있지 않다.**
> 본문은 "연출은 시전 *전에* 진행되고 그동안 카운트다운이 멈춘다"고 적었으므로,
> 실제 순서는 `입력 → 판정 3개 → **연출** → 5초 카운트 → 종료 → 쿨타임 10초`다.
> 구현은 연출 길이를 `DetectionSkillSettings.CastDurationSeconds`로 분리하고 기본값 0.5초를 둔다.
> 연출 도중 판정이 다시 깨지면(예: 그 사이 사망) 어떻게 되는지는 정의되지 않았다 → MS-2.

### 4.4 시전 연출 [확정]

1. 두더지 손이 **주머니에서 레이저 포인터를 꺼내 든다.**
2. **레이저를 작동시켜 화면이 파란빛으로 물들었다가 돌아오며** 스킬이 시전된다.

- **연출은 스킬 시전 *전에* 진행되고, 연출이 도는 동안에는 스킬 카운트다운이 진행되지 않는다.**
  즉 표시 5초는 연출이 끝난 시점부터 센다.
- 연출 길이는 **[TBD]** → MS-14. `DetectionSkillSettings.CastDurationSeconds`로 카운트 시작을
  분리하고, `MoleSkillHud`가 시전 상태에서만 로컬 화면 파란빛 오버레이를 펄스로 표시한다.
  기본 색 `#40a0ff`·최대 불투명도 0.35는 [TBD: MS-14] 임시값이다. 손·주머니·레이저 포인터
  모델/애니메이션 에셋이 없어 포인터를 꺼내 드는 동작은 아직 연결하지 않았다.
- 레퍼런스: 맨 인 블랙 기억 삭제 — <https://youtu.be/Q3wrCMk_bw4>

> 굴착의 시전 시간(0.3초, §5.3)과 달리 탐지의 시전 연출 길이는 정해지지 않았다.
> 이 구간에 무적/취약 판정이 붙는지도 원문에 없다.

#### 벽 투시 — **없다** [확정 — 사용자 2026-09-05]

**시전자 시야에서 실제로 보이는 표면에만 표시한다.** 벽·가구에 가려진 대상은 빛나지 않는다.

| 항목 | 값 |
| --- | --- |
| 가림(occlusion) | **적용** — `DetectionHighlight.shader` 의 `ZTest LEqual` |
| 사거리 제한 | **없음** |
| 시야각 제한 | **없음** (카메라 화각 밖은 애초에 그려지지 않는다) |

> **"맵 내에 존재하는 모든"의 해석이 좁아졌다.** 원문 §3-1 의 이 표현은 한때 벽 투시의 근거로
> 읽혔고 1.0 은 그렇게 구현했지만, **1.1 에서 사거리·시야각 제한이 없다는 뜻으로만 한정했다.**
> 즉 탐지는 대상을 *찾아 주는* 것이 아니라 *눈앞의 것을 구분해 주는* 스킬이다 —
> 방을 돌아다니며 켜야 하므로 §2.4 "작업을 오래 헤매지 않도록"의 강도는 약해진다.
>
> 셰이더는 대상과 **같은 지오메트리**를 그리므로 깊이가 동일하다. 부동소수 오차로 표면이
> 깜빡이지 않도록 `Offset -1, -1` 로 카메라 쪽에 미세하게 당겼다(`ZWrite` 는 꺼져 있어 깊이
> 버퍼에는 영향이 없다). 되돌리려면 `ZTest LEqual` 을 `Always` 로 되돌리면 된다.

렌더링 방식(아웃라인 / 실루엣 / 전체 발광)은 아직 MS-19로 남겨 두었다. 현재 기본값은
`DetectionHighlightMode.FullBodyEmission`이며, 전체 메시를 전용 투명 발광색으로 덮는 스캐폴드다.
던지기 조준 아웃라인과의 우선순위도 MS-4 잔여로 남아 있다.

가구 아웃라인은 이미 던지기 시스템이 쓰고 있다 →
[furniture-physics.md](../architecture/furniture-physics.md). **조준 중인 가구의 아웃라인과
탐지의 노란색이 같은 가구에 동시에 걸릴 수 있다** — 색·우선순위 충돌을 확인해야 한다.

### 4.6 대상 정의 [TBD]

**개별 가구의 작업 대상 여부와 얼룩을 판정하는 기준은 아직 미정**이다 → MS-5.

  → [map-generation.md §6·§12 MG-22](../architecture/map-generation.md). 얼룩(피·구정물)은 정식 콘텐츠로 존재하지 않는다.
- **B안 1차 구현(MAP-19, 2026-09-12)**은 별도 씬 풀 16개 [TEMP]를 작업 대상으로 선택하고
  `RandomFurnitureItem`의 서버 복제 상태로 `DetectionTargetMarker.SetTargetActive()`를 제어한다.
  B안 Game 씬 설치는 완료했으며 Unity Test Runner·Host/Client Play 검증은 대기다. 기존 인테리어 포함 여부·반출 완료·청소 진행도는 여전히 MS-5/MG-22다
  → [map-generation.md §10.1.3](../architecture/map-generation.md).
- 귀신 시스템은 **청소 진행도 40%**를 활동 조건으로 이미 참조한다
  → [ghost-system.md §6.2](ghost-system.md). 진행도의 정의도 같은 작업 시스템에 달려 있다.

탐지 스킬은 판정 기준을 임의로 만들지 않기 위해 `DetectionTargetMarker`가 붙은 오브젝트만
대상으로 삼는 **스캐폴드 형태로 구현했다**. 설치 도구는 기존 가구 중 하나에만 임시 마커를
추가하고, 별도 얼룩 실린더 하나를 만든다. 마커의 `DetectionTargetKind`(이동 가구 / 얼룩)와
`SetTargetActive(bool)`가 작업 시스템과의 교체 지점이다. Game 씬에는 검증용 `[TEMP]` 마커를
소수만 두며, 이 배치는 작업 시스템의 실제 대상 정의가 아니다. **MS-5는 닫히지 않았다.**

## 5. 굴착 스킬

### 5.1 정의 [확정]

**5초 동안** 캐릭터가 **땅굴을 파고 들어가 몸을 숨기고**, 굴착이 끝나면
**공중으로 4m 튀어오르는** 스킬이다. 어택 시간에 땅속으로 들어가 숨는 용도다.

| 항목 | 값 |
| --- | --- |
| 입력 키 | **T** [확정 — 사용자 2026-09-05]. 원문 1.0의 E는 `Interact` 충돌로 채택하지 않는다 → §3.5 |
| 유지 시간 | **5초** [확정] |
| 재사용 대기 | **10초** [확정 — 사용자 2026-09-05]. 에셋 값이 이미 10이다 |
| 도약 높이 | **4m** [확정] |
| 조작 제한 | **시야 회전과 스킬 키 재입력을 제외한 모든 조작** [확정 · **구현됨 2026-09-05**] |
| 은신 예외 | **귀신에게 이미 감지된 상태에서 시전하면 땅속에서도 감지된다** [확정 · **구현됨 2026-09-05**] |

### 5.2 은신 효과 [확정]

굴착으로 들어간 **땅속**은 귀신 시스템의 공통 은신처 중 하나이며,
**정상적으로 활성화된 동안 귀신에게 탐지·공격되지 않는다**
→ [ghost-system.md §9.5](ghost-system.md).

> 옷장·책상 밑 같은 **일반 상자 은신처는 귀신이 30% 확률로 검사**하지만,
> **땅속 은신은 검사 대상이 아니다.** 이것이 두더지 고유 능력의 차별점이다.
>
> **엎드려 침대 밑 은신**(2026-09-04 구현, [ghost-system.md §9.5](ghost-system.md))도 30% 검사를
> 안 받는다는 점은 땅속과 같으나, **들어가는 과정을 귀신이 보면 그대로 추격당하고 침대 밑에서도
> 잡힌다** — 굴착은 시전(0.3s)만 지나면 추격 중에도 안전해지는 것과 다르다. 굴착 = 스킬(쿨타임·
> 튀어오름), 엎드리기 = 자세(`Z` 토글, 쿨타임 없음).

#### 5.2.1 은신이 깨지는 예외 [확정 · 구현됨 (2026-09-05)]

땅속 은신은 **무조건이 아니다.** 다음 두 경우에는 땅굴 안에서도 귀신에게 감지된다.

| # | 조건 | 상태 |
| --- | --- | --- |
| 1 | **귀신의 시야에 이미 감지된 상태에서 스킬을 시전**한 경우 | **구현됨** |
| 2 | **땅굴 안에서 손전등을 사용**하는 경우 | **확정 / 착수 불가** — 손전등 시스템 자체가 없다 |

**판정 규칙 (구현)**

| 항목 | 내용 |
| --- | --- |
| 판정 주체 | 서버(귀신) — `GhostPrototypeController.EvaluateBurrowExposure`, 어택 틱마다 |
| 판정 시점 | **매몰이 시작된 순간 한 번**. 시전(0.3초) 중에는 아직 매몰이 아니다 |
| "감지된 상태" | `_pursuit != Roam && _target == player` — **쫓기는 중이거나 마지막 위치를 수색 중.** 침대 밑 은신과 같은 기준이다 |
| 지속 | 그 굴착이 끝날 때까지 유지. **들어간 뒤 귀신이 놓쳐도 안전해지지 않는다** |
| 효과 | 탐지(`TryDetectPlayer`)와 **포획(`TryCatch`) 양쪽**에서 땅속이 아닌 것처럼 다룬다 |

순수 판정은 `BurrowExposureTracker`(`Assets/Scripts/Gameplay/Ghost/`)에 있고
`BedHideEvaluator`와 같이 EditMode에서 검증한다(`GhostBurrowExposureTests` 8건).

> **틈새 하나가 함께 닫혔다.** 탐지에서 빠져도 `_target`은 수색(7초) 동안 남는데,
> `TryCatch`가 굴착을 전혀 보지 않아 **안전하게 숨은 플레이어가 땅속에서 잡힐 수 있었다.**
> 같은 규칙을 포획에도 적용하면서 막았다.

> **시전 중에 따돌리면 안전하게 숨는다.** 판정이 매몰 시작 시점이라, 0.3초 시전 동안 귀신이
> 추격을 완전히 놓으면(`Roam` 복귀) 노출되지 않는다. 다만 시야만 끊긴 상태는 `Search`(7초)라
> 여전히 "감지된 상태"로 친다.

> **이 규칙은 굴착의 성격을 바꾼다.** 이전에는 시전 0.3초만 버티면 추격 중에도 안전해졌지만,
> 이제 굴착은 **들키기 전에 미리 숨는** 스킬이 된다. 이미 쫓기고 있으면 굴착으로 못 벗어난다
> — 오히려 이동이 잠긴 채(§5.5.1) 5초 동안 제자리에 묶여 **잡히기 더 쉬워진다.**
>
> 결과적으로 **엎드려 침대 밑 은신**([ghost-system.md §9.5](ghost-system.md))과 규칙이 같아진다 —
> "들어가는 걸 봤으면 그대로 잡힌다." 남는 차이는 굴착이 **스킬**(쿨타임·튀어오름·위치 제한 없음)
> 이고 엎드리기는 **자세**(Z 토글, 쿨타임 없음, 침대가 있어야 함)라는 점이다.
>
> 감지 상태에서 시전했을 때 **스킬 자체를 막을지, 시전은 되되 안전하지 않을지**는
> "감지될 수 있다"는 표현대로 **후자**로 읽는다. 즉 굴착은 정상 진행되고 튀어오름도 그대로이며,
> 다만 그동안 귀신이 계속 볼 수 있다.

### 5.3 지속과 종료 [확정 / 일부 수치 임시 — 프로토타입 구현됨]

| 항목 | 값 | 코드 |
| --- | --- | --- |
| 시전 시간 (입력 → 실제로 숨음) | **0.3초** [임시 — MS-10 임의값] | `MoleBurrowSettings.EnterCastSeconds` |
| 최대 유지 시간 | **5초** [임시] | `MoleBurrowSettings.MaxBurrowDuration` |
| 재사용 대기 시간 | **10초** [확정 — 사용자 2026-09-05] | `MoleBurrowSettings.CooldownSeconds` |

종료 방식은 2가지다.

| # | 종료 조건 | 결과 |
| --- | --- | --- |
| 1 | **스킬 키를 한 번 더 입력** | 즉시 스킬이 끝난다 |
| 2 | **최대 유지 시간(5초) 경과** | 자동으로 종료된다 |

**두 경우 모두 종료 시 튀어오른다**(§5.4). 원문은 자동 종료 연출을 "파바박하면서 튀어나온다"로 적었다
(연출 자체는 아직 없다 → §6).

시전(Entering) 중에는 아직 숨지 않은 상태라 귀신에게 **그대로 탐지된다.** 시전 중 사망하면
튀어오르지 않고 조용히 취소된다(`MoleBurrowController.Cancel`) — §3.1 "사망 시 스킬 사용 제한"의
연장. 매몰(Buried) 중 사망해도 튀어오르지 않고 즉시 종료한다.

### 5.4 튀어오름 [확정 / 수치 — 사용자 확정 + 프로토타입 구현됨 (2026-08-31)]

- 종료 시 캐릭터는 **공중으로 높게 튀어오른다.**
- 목표 기준: **2층을 바로 올라갈 수 있을 정도의 높이** [확정 — 기준만]

> **현재 맵에는 2층이 없다.** `House_01`은 단층이다 →
> [map-generation.md](../architecture/map-generation.md).
> 아래 4m는 그 기준을 환산한 값이 아니라 **사용자가 프로토타입용으로 직접 지정한 수치**였는데,
> **원문 1.0이 "공중으로 4m 튀어오른다"로 같은 값을 명시하면서 기획서 확정값이 됐다.**
> 다만 "2층을 바로 올라갈 정도"라는 *기준*과 4m라는 *수치*가 실제로 일치하는지는
> 맵에 2층이 생겨야 검증할 수 있다.
>
> **2026-09-05 — 맵 생성 기획서 v0.3 이 2~3층 대저택을 확정했다.** 층고(현재 벽 높이 2.5m + 슬래브)가
> 정해지는 대로 이 값을 다시 잡아야 한다 → [roadmap.md §1.2 MAP-12](roadmap.md).

| 항목 | 값 | 비고 |
| --- | --- | --- |
| 도약 높이 | **4m** [확정 — 원문 1.0 명시. 프로토타입 값과 일치] | `MoleBurrowSettings.PopHeight` |
| 도약 속도 | 높이·중력로 역산 (`√(높이 × 2 × 중력)`) | 점프와 같은 공식 재사용. 사용자가 "임의로 설정" 허용 |
| 착지 낙하 피해·경직 | **없음** [확정] | 애초에 플레이어에 낙하 피해 시스템이 없다 |

### 5.5 사용 중 행동 [전부 확정 — 조작 제한 구현됨]

#### 5.5.1 조작 제한 [확정 · 구현됨 (2026-09-05)]

**시야 회전과 스킬 키(T) 재입력을 제외한 모든 조작을 잠근다.**

| 입력 | 굴착 중 | 현재 구현 |
| --- | --- | --- |
| `Look` (시야 회전) | **허용** | 허용 |
| `Burrow` (T, 재입력 = 즉시 종료) | **허용** | 허용 — 막으면 스스로 나올 수 없다 |
| `Move` | 차단 | 차단 (입력 0 + `PlayerMotor.MovementLocked`) |
| `Jump` | 차단 | 차단 — 대기 중이던 점프도 버린다 |
| `Attack` (가구 잡기·던지기) | 차단 | 차단 |
| `Interact` (문 여닫기) | 차단 | 차단 |
| `Prone` (엎드리기 토글) | 차단 | 차단 |
| `Crouch` | 차단 | **마지막 값으로 얼린다** — 잠기는 것만으로 자세가 바뀌면 안 된다 |
| `Sprint` | 차단 | 차단 |
| `Pause` (ESC) | **허용** | 허용 — 일시정지 메뉴는 별개 계층이다 → [pause-menu-system.md](pause-menu-system.md) |

**구현** — `PlayerInputReader.SetSkillInputLocked(bool)` 신설. 일시정지 메뉴의
`SetGameplayInputLocked`(**전부** 0으로)와 **독립된 두 번째 잠금**이며, 이쪽은 `Look`·`Burrow`만
남긴다. 둘이 겹치면 **메뉴 쪽이 이긴다**(더 강한 잠금이라 시점까지 잠근다).
`MoleBurrowController`가 시전 시작에 걸고 정상 종료·시전 취소·디스폰 **세 경로 모두에서** 푼다.

`PlayerMotor.MovementLocked`도 그대로 함께 세운다 — 입력이 0이어도 모터에서 한 번 더 막아야
잔여 속도나 다른 경로의 이동이 새지 않는다.

> **가구를 든 채 굴착하면?** 잠금은 `Attack` **입력**만 막을 뿐 이미 들고 있는 가구를 놓지는
> 않는다. 일시정지 메뉴는 잠그기 **전에** `GrabController.ForceRelease()`를 부르는데(PM-15),
> 굴착은 그렇게 하지 않았다 — 가구를 든 채 땅속에 들어가면 어떻게 되는지가 **MS-12 미결정**이라
> 임의로 정하지 않았다. 결정되면 여기에 붙인다.

## 6. 공통 스킬 UI [규격·에셋 확정 / **구현됨 — 정적 배선 확인·수동 Play 검증 대기**]

**탐지와 굴착은 같은 형태·같은 위치의 UI를 공유한다.** 스킬별로 인포그래픽(아이콘)만 다르다.

### 6.1 공통 형태 [확정]

| 항목 | 값 |
| --- | --- |
| 형태 | 스킬 인포그래픽이 그려진 **원형 기호** |
| 위치 | **화면 우측 상단** |
| 생성 시점 | **스킬을 시전하면** 생성 |
| 진행 표현 | **원형 테두리 선이 일정한 속도로 감소** (원형 게이지) |
| 배경 | 회색 `#595959`, **투명도 70%** — 시전/쿨타임 공통 |

구현은 `MoleSkillHud`가 런타임 로컬 Canvas를 만들고, `IMoleSkillStatus`의 단계·남은 시간을
읽어 탐지와 굴착을 각각 한 칸씩 쌓는다. 두 지표는 독립 상태라 동시에 표시할 수 있다.
기본 배치(80px, 우·상단 24px, 세로 간격 12px)는 `MoleSkillUiSettings`에 노출했으며,
`MoleSkillSetup` 메뉴가 아이콘·설정·씬/프리팹 참조를 멱등으로 연결한다.
