## 2. 개요

### 2.1 문서 목적과 범위

이 문서는 스테이지에서 **모든 플레이어 캐릭터가 공통으로 가지는 두더지 스킬**의 규칙을 정의한다.

- 두더지 스킬의 종류와 공통 규칙
- 사용 조건 · 사용 중 행동 · 종료 조건 · 재사용 대기 시간
- 스킬 사용 연출과 재사용 대기 UI

다음은 이 문서의 범위가 **아니다.**

| 내용 | 정의하는 곳 |
| --- | --- |
| 플레이어 이동·시점·상호작용 입력 | [../architecture/player-controller.md](../architecture/player-controller.md) |
| 가구 잡기·부양·발사 | [../architecture/throw-system.md](../architecture/throw-system.md) |
| 귀신의 탐지·추격·어택 규칙, 은신처 판정 | [ghost-system.md](ghost-system.md) |
| 정신력 수치·증감·디버프·UI | [sanity-system.md](sanity-system.md) |
| 청소·이사 작업(얼룩, 이동 대상 가구)의 정의와 진행도 | **미작성** — 작업 시스템 기획서 |
| 아이템·장비(레이저 장비의 획득·소지 여부 포함) | **미작성** — 아이템 기획서 |

### 2.2 표기 기준

[귀신 시스템 기획서 §2.2](ghost-system.md)와 동일한 기준을 쓴다.

| **[TBD]** | 미정 | **임의로 확정하지 않는다.** 사용자에게 질문한다 |

수치의 최종 권위는 코드 상수가 아니라 설정 에셋에 있다 → [CLAUDE.md §3.4](../../CLAUDE.md)

> 기획이 완료됐다는 뜻이 아니다. `[확정]` 항목도 스킬 전체 설계가 마무리되면 바뀔 수 있다.

### 2.3 시스템 개요 [확정]

- 두더지 스킬은 **모든 플레이어 캐릭터가 지니는 고유 스킬**이다.
- 스테이지 내에서 **생존 중인 모든 플레이어 캐릭터**가 사용할 수 있다.
- 두더지 스킬은 **총 2개**로 구성된다.

| 스킬 | 한 줄 정의 | 상세 |
| --- | --- | --- |
| **탐지** | 레이저 장비로 일정 시간 동안 모든 얼룩과 이동해야 하는 가구를 확인한다 | [§4](#4-탐지-스킬) |
| **굴착** | 일정 시간 땅을 파고 들어가 몸을 숨기고, 종료 시 공중으로 높게 튀어오른다 | [§5](#5-굴착-스킬) |

### 2.4 기획 의도

> **기획 의도**
> - 플레이에 필요한 스킬을 **'두더지'의 특성**을 반영해 기획하여, '두더지 외계인'이라는
>   플레이어 캐릭터의 매력을 살린다.
> - **탐지** — 가구 이동과 청소가 필요한 곳을 시각적으로 피드백하여, 플레이어가 작업을
>   오래 헤매지 않도록 한다.
> - **굴착** — 귀신의 어택에 플레이어가 대응할 수 있게 하여, 일방적으로 공격당한다는
>   불합리함을 줄이고 스킬을 활용한 전략적·피지컬적 회피를 가능하게 한다.

## 3. 스킬 공통 규칙

### 3.1 사용 자격 [확정]

- 스테이지 내에서 **생존 중인** 모든 플레이어 캐릭터가 사용할 수 있다.
- 플레이어 캐릭터가 **사망 상태일 때는 모든 두더지 스킬의 사용이 제한된다.**

사망 외에 사용이 제한되는 상태(기절·드릴 카 내부·정신력 디버프 등)는 [TBD] → MS-15.

### 3.2 사용 횟수 [확정]

- 모든 두더지 스킬은 **횟수 제한 없이 무제한으로** 사용할 수 있다.
- 소지품·자원을 소모하지 않는다.

### 3.3 재사용 대기 시간 [확정 / 수치 TBD]

- 모든 두더지 스킬은 **사용 종료 후** 재사용 대기 시간을 거친다.
  대기는 사용 **시작**이 아니라 **종료** 시점부터 센다.
- 재사용 대기 시간의 **수치**는 스킬별로 [TBD] → MS-3.
- 두 스킬이 대기 시간을 공유하는지, 각각 독립인지는 [TBD] → MS-3.

### 3.4 공통 판정 조건 [TBD]

> **원문이 비어 있다.** 초안 §3-1은 "스킬 사용 시, 판정 조건은 다음과 같다."에서 끊겼다.
> 사용 가능 여부를 결정하는 공통 판정 조건은 **정의되지 않았다.** → MS-2

### 3.5 입력 [굴착 확정 / 탐지 TBD]

- **탐지**: 스킬 사용 키는 여전히 정해지지 않았다 → MS-1.
- **굴착**: 사용자 확정 R키에 `Burrow` 액션을 배정했다
  (`Assets/InputSystem_Actions.inputactions` — `Player/Burrow`, `<Keyboard>/r`). `Interact`(E)와
  물리 키가 분리되어 문 토글과 굴착이 같은 프레임에 함께 발동하지 않는다.

탐지 스킬의 키가 확정되면 [gdd.md §3.1](gdd.md) 표와 [player-controller.md](../architecture/player-controller.md)를
함께 갱신한다.

굴착은 **스킬 키를 한 번 더 누르면 즉시 종료**하므로(§5.3), 굴착 액션은 토글 입력이다
(`MoleBurrowController` — `PlayerInputReader.BurrowPressedThisFrame` 의 눌림 엣지만 본다).

### 3.6 네트워크 권위 [굴착 구현 완료 / 정식 결정 아님]

이 저장소는 **물리 상태의 권위를 서버에 두고**, 소유자 권위 예외는 플레이어 이동 하나뿐이다
→ [ADR-0008](../architecture/decisions/ADR-0008-owner-authoritative-player-movement.md) ·
[ADR-0010](../architecture/decisions/ADR-0010-server-authoritative-furniture-physics.md).

**프로토타입은 굴착을 이동 권위의 연장으로 구현했다** — `PlayerMotor.IsCrouching`과 같은
Owner-write / Everyone-read `NetworkVariable<bool>`(`MoleBurrowController.IsBurrowed`)로,
`SanityNetworkState.IsCrouching`이 이미 검증한 것과 같은 패턴이다. 서버(귀신 AI)는 이 값을
그대로 신뢰해 탐지를 건너뛴다(§9 GhostPrototypeController.TryDetectPlayer). **이것이 정식
ADR을 대체하지는 않는다** — 위 코드 패턴을 새 소유자 권위 예외로 굳히려면 여전히 ADR이
필요하다 → MS-13 잔존.

### 3.7 용어 충돌 주의

이 문서의 **탐지**는 플레이어가 쓰는 스킬 이름이다.
[ghost-system.md §8](ghost-system.md)의 **탐지**는 귀신이 플레이어를 찾는 판정이다.
**둘은 다른 시스템이다.** 코드·문서에서 혼동하지 않도록 표기한다.

| 개념 | 주체 | 문서 |
| --- | --- | --- |
| 탐지 스킬 | 플레이어 | 이 문서 §4 |
| 플레이어 탐지 | 귀신 | [ghost-system.md §8](ghost-system.md) |

## 4. 탐지 스킬

### 4.1 정의 [확정]

**레이저 장비**를 통해 **일정 시간 동안** 다음을 확인할 수 있는 능력이다.

- **옮겨야 하는 가구**
- **닦아야 하는 얼룩** (피·구정물 등)

### 4.2 지속 시간 [임시]

| 항목 | 값 |
| --- | --- |
| 표시 지속 시간 | **5초** [임시] |

> 원문 표현은 "5초 동안만 보여 주자"로, 확정 수치가 아니라 제안이다. `ScriptableObject`로 노출한다.

### 4.3 표시 방식 [TBD]

무엇을 어떻게 보여 주는지는 정해지지 않았다 → MS-4.

- 아웃라인 / 실루엣 / 하이라이트 색 중 무엇인가
- **벽 너머로 보이는가** (투시 여부)
- 사거리·시야각 제한이 있는가
- 본인에게만 보이는가, 팀 전체가 공유하는가 → MS-6

가구 아웃라인은 이미 던지기 시스템이 쓰고 있다 →
[furniture-physics.md](../architecture/furniture-physics.md). 색·우선순위 충돌을 확인해야 한다.

### 4.4 대상 정의 [TBD]

**"옮겨야 하는 가구"와 "얼룩"을 판정할 기준이 아직 없다** → MS-5.

- 청소·이사 **작업 시스템 자체가 미기획·미구현**이다. 얼룩(피·구정물)은 콘텐츠로 존재하지 않는다.
- 현재 씬의 가구는 전부 던질 수 있는 `NetworkObject`이며, 이동 대상 여부를 구분하는 데이터가 없다
  → [furniture-physics.md](../architecture/furniture-physics.md)
- 귀신 시스템은 **청소 진행도 40%**를 활동 조건으로 이미 참조한다
  → [ghost-system.md §6.2](ghost-system.md). 진행도의 정의도 같은 작업 시스템에 달려 있다.

**따라서 탐지 스킬은 작업 시스템이 기획되기 전에는 구현할 수 없다.**

## 5. 굴착 스킬

### 5.1 정의 [확정]

일정 시간 동안 캐릭터가 **땅을 파고 들어가 몸을 숨기고**, 굴착이 끝나면
**공중으로 높게 튀어오르는** 스킬이다. 어택 시간에 땅속으로 들어가 숨는 용도다.

### 5.2 은신 효과 [확정]

굴착으로 들어간 **땅속**은 귀신 시스템의 공통 은신처 중 하나이며,
**정상적으로 활성화된 동안 귀신에게 탐지·공격되지 않는다**
→ [ghost-system.md §9.5](ghost-system.md).

> 옷장·책상 밑 같은 **일반 상자 은신처는 귀신이 30% 확률로 검사**하지만,
> **땅속 은신은 검사 대상이 아니다.** 이것이 두더지 고유 능력의 차별점이다.
>
> **엎드려 침대 밑 은신**(2026-09-04 구현, [ghost-system.md §9.5](ghost-system.md))도 30% 검사를
> 안 받는다는 점은 땅속과 같으나, **들어가는 과정을 귀신이 보면 그대로 추격당하고 침대 밑에서도
> 잡힌다** — 굴착은 시전(0.3s)만 지나면 추격 중에도 안전해지는 것과 다르다. 굴착 = 스킬(쿨타임·
> 튀어오름), 엎드리기 = 자세(`Z` 토글, 쿨타임 없음).

### 5.3 지속과 종료 [확정 / 수치 임시 — 프로토타입 구현됨]

| 항목 | 값 | 코드 |
| --- | --- | --- |
| 시전 시간 (입력 → 실제로 숨음) | **0.3초** [임시 — MS-10 임의값] | `MoleBurrowSettings.EnterCastSeconds` |
| 최대 유지 시간 | **5초** [임시] | `MoleBurrowSettings.MaxBurrowDuration` |
| 재사용 대기 시간 | **3초** [임시 — MS-3 임의값] | `MoleBurrowSettings.CooldownSeconds` |

종료 방식은 2가지다.

| # | 종료 조건 | 결과 |
| --- | --- | --- |
| 1 | **스킬 키를 한 번 더 입력** | 즉시 스킬이 끝난다 |
| 2 | **최대 유지 시간(5초) 경과** | 자동으로 종료된다 |

**두 경우 모두 종료 시 튀어오른다**(§5.4). 원문은 자동 종료 연출을 "파바박하면서 튀어나온다"로 적었다
(연출 자체는 아직 없다 → §6).

시전(Entering) 중에는 아직 숨지 않은 상태라 귀신에게 **그대로 탐지된다.** 시전 중 사망하면
튀어오르지 않고 조용히 취소된다(`MoleBurrowController.Cancel`) — §3.1 "사망 시 스킬 사용 제한"의
연장. 매몰(Buried) 중 사망해도 튀어오르지 않고 즉시 종료한다.

### 5.4 튀어오름 [확정 / 수치 — 사용자 확정 + 프로토타입 구현됨 (2026-08-31)]

- 종료 시 캐릭터는 **공중으로 높게 튀어오른다.**
- 목표 기준: **2층을 바로 올라갈 수 있을 정도의 높이** [확정 — 기준만]

> **현재 맵에는 2층이 없다.** `House_01`은 단층이다 →
> [map-generation.md](../architecture/map-generation.md).
> 아래 4m는 그 기준을 실제로 환산한 값이 아니라 **사용자가 프로토타입용으로 직접 지정한 수치**다.
> 맵에 2층이 생기면 재검증이 필요하다.

| 항목 | 값 | 비고 |
| --- | --- | --- |
| 도약 높이 | **4m** [사용자 확정 — 프로토타입 값] | `MoleBurrowSettings.PopHeight` |
| 도약 속도 | 높이·중력로 역산 (`√(높이 × 2 × 중력)`) | 점프와 같은 공식 재사용. 사용자가 "임의로 설정" 허용 |
| 착지 낙하 피해·경직 | **없음** [확정] | 애초에 플레이어에 낙하 피해 시스템이 없다 |
| 도약 방향 | **수직 고정** [확정] | 발사 임펄스 자체는 수직만. 이후 공중 제어(`AirControl`)는 일반 점프와 동일하게 붙는다 |

구현: `PlayerMotor.ApplyVerticalLaunch()` — 기존 점프의 수직 속도 계산·중력 누적 코드를 그대로 재사용한다.

### 5.5 사용 중 행동 [확정 다수 — 프로토타입 구현됨 (2026-08-31) / 일부 잔존]

| 항목 | 상태 |
| --- | --- |
| 땅속 이동 | **불가** [사용자 확정] — `PlayerMotor.MovementLocked` 로 입력 기반 이동을 완전히 건너뛴다 |
| 카메라 높이 | **바닥보다 살짝 위(0.15m)로 낮아짐** [사용자 확정 — 2026-08-31 추가] — 시전 시작과 동시에 웅크리기와 같은 전환 속도로 낮아지고, 종료 시 같은 방식으로 되돌아온다. `PlayerMotor.CameraHeightOverride` → `MoleBurrowSettings.BurrowedCameraHeight` |
| 화면 비네트 | **켜짐** [사용자 확정 — 2026-08-31 추가] — 굴착 동작 중(시전~매몰) Global Volume 가중치를 올려 화면 가장자리를 어둡게 한다. 정신력 노이즈와 별도 프로필 → `MoleBurrowCameraEffect`, `PP_MoleBurrowVignette.asset` |
| 굴착 가능 위치 | **제한 없음** [사용자 확정 — MS-7 해소] — 실내 바닥 어디서나 가능하다 |
| 진입·종료 시전 시간 | **0.3초** [임시 — MS-10 임의값] |
| 시전 중 무적/취약 | **취약** — 아직 §9 탐지 대상에서 빠지지 않는다. **사용자에게 별도로 확인하지 않은 값**이므로 재검토 필요 |
| 추격·포착 중 진입 | **가능** [사용자 확정] — 진입 자체를 막지 않는다. 귀신은 다음 틱에 탐지 대상에서 빠져 §9.1 수색으로 전환된다 |

## 8. 구현 상태

**굴착 스킬은 프로토타입으로 구현되어 있다. 탐지 스킬은 여전히 코드·에셋 어디에도 없다.**
(2026-08-31 기준)

| 항목 | 상태 |
| --- | --- |
| 입력 액션 | **구현됨** — `PlayerInputReader.BurrowPressedThisFrame`, R키(굴착의 MS-1 해소) |
| 굴착 상태 머신 (시전→매몰→종료→쿨타임) | **구현됨** — `MoleBurrowController` |
| 튀어오름 | **구현됨** — `PlayerMotor.ApplyVerticalLaunch()`, 점프 공식 재사용 |
| 이동 잠금 | **구현됨** — `PlayerMotor.MovementLocked` |
| 귀신 은신 예외 | **구현됨** — `SanityNetworkState.IsBurrowed` → `GhostPrototypeController.TryDetectPlayer` |
| 매몰 중 시각적 은폐 | **구현됨(단순)** — 다른 클라이언트에게 보이는 몸(`RemoteBody`)만 비활성화 |
| 카메라 낮추기 + 화면 비네트 | **구현됨(2026-08-31)** — `PlayerMotor.CameraHeightOverride`, `MoleBurrowCameraEffect` + `PP_MoleBurrowVignette.asset`(Game 씬 Global Volume) |
| 재사용 대기 UI | 없음 (쿨타임 자체는 내부적으로 동작, 표시만 없음) |
| 탐지 스킬 전체 | 없음 |
| 자동화 테스트 | **없음** — EditMode 98건(기존)은 통과했지만 굴착 전용 테스트는 아직 없다. **수동 Play 검증 필요** |

> **버그 발견·수정(2026-08-31)** — 설치 직후엔 정상으로 보이지만 `VolumeProfile.Add<T>()`만으로는
> 컴포넌트가 디스크에 저장되지 않는다(`AssetDatabase.AddObjectToAsset` 을 별도로 불러야 서브 에셋으로
> 남는다). 이걸 빠뜨려서 **비네트 오버라이드가 하나도 저장되지 않은 채** 인스펙터에서만 잠깐 보이다
> 다음 컴파일에 사라지는 상태였다. `MoleBurrowPostProcessingSetup`·`SanityPostProcessingSetup` 둘 다
> 고치고 `ValidateInstallation()`에 `AssetDatabase.Contains()` 검사를 추가해 재발해도 설치 단계에서
> 바로 걸리게 했다. **정신력 카메라 노이즈(M8-GS-4a, 2026-08-24 완료로 기록됨)도 같은 버그였다** —
> 문서상 "완료"였지만 실제로는 비네트·필름그레인·색수차가 전혀 걸리지 않고 있었을 가능성이 높다.

**남은 것**: MS-1(탐지 키) · MS-2(공통 판정 조건 — 지금은 "생존 + 쿨타임"만 봄) · MS-3(쿨타임 최종값) ·
MS-11(어둠 노출 여부) · MS-12(가구 홀드 중 사용 가능 여부) · MS-14(잔여 — 레이저 장비 외형·재사용 대기 UI·캐릭터 애니메이션·사운드) · MS-15(사망 외 제한 상태).
탐지 스킬은 여전히 작업 시스템 기획(MS-5)이 선행되어야 한다.
