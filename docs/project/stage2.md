## 원본 배치 갱신 (2026-11-15)

사용자가 제공한 `Assets/Mesh/Stage2/소형 맵_1 가구 배치.sh3d`와
`Assets/Mesh/Stage2/map/소형 맵_1 가구 배치 (2).obj`를 기준으로 Stage2를 갱신했다.
실제 폴더 이름은 요청의 `State2`가 아니라 `Stage2`다. 삭제된 이전 OBJ에 대한 씬·가구 메시 참조를 새 OBJ로 교체했다.

- 새 OBJ의 유효 메시 **1,791개**, 약 **16.56×28.47m** 구조·가구·소품을 원본 좌표로 반영했다.
  1cm → 0.01m로 임포트하고 새 맵과 이동 가구의 Transform 스케일은 1을 유지한다.
- 사용 중인 **URP/Lit 재질 371개**에 새 `map` 폴더 텍스처와 MTL 색·투명도를 연결했다.
  참조가 없는 이전 Stage2 재질은 `.meta`와 함께 정리했다.
- 기존 반출 가구 **18개**의 프리팹·네트워크 식별자·가구 정의를 유지하고, 새 원본의 위치·방향·치수로 메시와
  후보 지점을 갱신했다. 추가 가구·소품은 고정 구조로 반영하며 반출 목표 수는 변경하지 않았다.
- 원본에서 드레스룸 가구가 뒤쪽 벽 안으로 들어간 부분, 소파와 작은 수납장이 겹친 부분은 외형 위치를 보존하고
  충돌체·배치 검사 범위만 실내 쪽으로 잘랐다. 거울 옷장과 열린 옷장의 미세한 경계 중첩도 충돌 범위에서 제거했다.
  기존 보조 외부 바닥을 2mm 내려 원본 바닥과의 겹침 렌더를 피했다.
- 기존 출입문·부활 방 양개문·정적 문 열림 보정·드릴카·스폰·청소·귀신·HUD 배선을 유지했다.

**확인 필요 — 원본 배치의 드레스룸 출입:** 새 침실 옷장 2개가 드레스룸 미닫이문 앞을 막는다.
요청한 원본 배치를 지키기 위해 옷장을 임의로 이동하지 않았다. 기존 통과 검사 경로
`(-10.3, 0.03, 0.7) → (-10.3, 0.03, -1)`는 옷장 앞 `(-10.47, 0.05, 1.02)`에서 막힌다.
드레스룸의 반출 가구 접근을 위해 원본 위치를 유지할지, 옷장 위치를 조정할지 사용자 확인이 필요하다.

이번 검증: Unity 6000.3.20f1 검증 복제본에서 컴파일 성공, `Stage2StructureTests` **5/5** 통과.
Local Host의 Stage2 흐름 **2건은 위 드레스룸 통과 검사에서 실패**했다. 따라서 이번 갱신의 전체 플레이 흐름은
통과했다고 보고하지 않는다. 아래 2026-11-09 검증 결과는 이전 원본에 대한 이력이다.

추가 진단에서 **복제본의 막힌 드레스룸 경로 한 곳만 제외**하면 같은 Local Host 흐름 **2/2**가 통과했다.
이는 외부 문·주방 통로, 가구 18개 배치/잡기, 청소, 귀신 NavMesh, 부활, 반출 포장과 정산 1/18 보존을 확인한
결과이며 드레스룸 접근 문제를 해결한 결과는 아니다. 저장소의 기존 테스트는 변경하지 않았다.
실제 밤 화면·조작감·Steam 2PC 접속은 미검증이다.

검토용으로 천장·윗층을 분리하고 조명을 밝힌 top view PNG 2장을 렌더링해 배치·원본 재질을 확인했다.
씬·관련 프리팹·재질의 끊긴 GUID/텍스처 참조, 중복 GUID/로컬 fileID와 삭제된 이전 OBJ 참조는 0건이다.
일회성 변환·검토 스크립트와 검증 복제본은 `Logs/` 안에서만 사용했다.

## 씬 흐름

`InGameLobby → Tutorial → Result → InGameLobby → Stage1 → Result → InGameLobby → Stage2`.

## 이동 가구

`Assets/Prefabs/Furniture/Stage2/`의 18개 프리팹은 원본 OBJ의 메시·재질을 사용한다.
TV장·TV·낮은 탁자·소파·안락의자·책장 2개·벽 책상·키큰 수납장·화장대·스툴·서랍장·옷장 4개·유리 탁자·주방 카트다.
같은 자리에 있던 정적 원본 부분만 씬에서 비활성화해 이중 렌더·충돌을 피한다. 붙박이 주방과 욕실은 고정이다.

기존 서버 물리·내구도·잡기/차징/발사·2인 운반·윤곽선·탐지·반출·정산·복구 경로를 사용한다.
질량/투척/내구도 설정은 대응하는 기존 가구 정의를 재사용한다. 분해 레시피는 새로 만들지 않았다.
가구는 런타임 Instantiate로 만들지 않고 씬 프리팹 인스턴스로 둔다. 기존 가구 배치기가 원본 위치의 전용 후보에 배치한다.
TV는 원본처럼 높은 위치에 있고, 스툴은 화장대 아래의 받침 관계를 명시한다.
화장대 충돌체는 상판·뒤판으로 나눠 스툴이 끼지 않게 했다.
2026-11-15 갱신에서는 거울 옷장을 포함한 가구 외형을 새 원본 위치로 돌리고, 겹침은 충돌 경계에서 보정한다.

반출 목표는 **18개 전부**다(2026-11-09 사용자 확정). 각 가구의 전용 풀/후보를 하나씩 두고 모두 목표로 지정한다.
포장 비율/시간/속도는 Stage1의 기존 설정(85%·1초·0.3m/s)을 재사용한다.

## 이전 검증 (2026-11-09)

컴파일 성공. 전체 EditMode **735/735**, 목표 18개 확정 뒤 관련 EditMode **72/72**·Local Host PlayMode **10/10** 통과(실패·스킵 0).
마지막으로 Stage2 종료 단말기 정산의 반출 **1/18** 보존을 추가한 흐름 2개도 **2/2** 통과했다.
실제 세션에서 정상 종료·전멸 후 Stage2 진입, 정산 없는 Stage1/Stage2 재시도, 18개 잡기/강제 해제,
외부 문·창고 슬라이딩 문·주방 문 통과, 청소·기본 귀신 NavMesh·부활 의식 초기화, 반출 구역 1초 포장을 확인했다.
문 자체 회전이 씬의 방향 회전을 덮는 문제는 부모 방향 앵커를 추가해 수정했고, 통과 검사를 다시 실행했다.
씬 블록 중복 ID·끊긴 로컬 참조·신규 참조 GUID 중복·에셋 meta 누락 0건. 새 프리팹 19종 해시는 고유하며 씬 배치 플래그가 꺼져 있다.
천장을 잠시 숨기고 밝힌 검토용 top view PNG를 확인했다. 실제 게임의 밤 조명·외형·조작감은 수동 확인이 필요하다.
자동 잡기 검사는 서버 API를 직접 호출하며 실제 두 번째 클라이언트 입력을 검증하지 않는다.
기존 `LiftWiringTests.cs:196`의 `NetworkObject.IsSceneObject` CS0618 경고 1종과
기존 NGO `Failed to remove InGameLobby scene handles` 로그(SF-FIX-1)는 남아 있다. 새 씬의 런타임 예외는 검사에서 수집되지 않았다.
Steam PC 2대·계정 2개 접속과 실제 조작감은 별도 수동 확인이 필요하다.

일회성 준비 코드는 결과 저장·해시 확정 후 삭제한다(ADR-0020).
