## 1. 시스템 개요

죽음 시스템은 플레이어가 귀신에게 죽었을 때 발생하는 죽음 판정, 시체 생성, 죽은 후 플레이 상태, 전멸 처리를 관리한다.

부활에 관한 세부 규칙은 [부활 시스템 기획서](revival-system.md)에서 별도로 다룬다.

## 2. 죽음 조건

플레이어는 다음 상황에서만 사망할 수 있다.

| 구분 | 조건 |
| --- | --- |
| 귀신 어택 | 귀신의 어택 중 귀신에게 붙잡혔을 때 |
| 귀신 이벤트 | 개별 귀신의 이벤트에서 사망 조건을 충족했을 때 |

귀신별 특수 사망 조건은 각 귀신 기획서에서 정의한다.

> **기존 문서와 범위 확인 필요:** [귀신 시스템 기획서 §6.3](ghost-system.md#63-초자연현상-정의-과거-저장소판)는 초자연현상 자체로는 사망하지 않는다고 적고 있다. 이 문서의 ‘귀신 이벤트’가 그 초자연현상과 같은 범주인지 확인해야 한다.

## 3. 죽음 처리

죽음 조건이 충족되면 다음 순서로 처리한다.

1. 플레이어 조작 차단
2. 죽음 애니메이션 재생
3. `Dead` 상태 전환
4. 죽은 위치에서 시체 생성
5. 귀신 추격 대상에서 제외
6. 죽은 플레이어를 관전 상태로 전환

여기서 차단하는 조작은 생존 플레이어의 조작이다. 사망 후 관전 이동과 시점 조작은 [사망 후 관전 시스템 기획서](spectator-system.md)를 따른다.

죽은 플레이어는 부활하거나 스테이지가 끝날 때까지 `Dead` 상태를 유지한다.

## 4. 죽음 연출

### 본인 화면

1. 두더지가 자신의 몸을 아래로 내려다보는 구도
2. 공중에서 두더지의 목이 졸리는 연출
3. 손과 화면이 흔들림
4. 화면 블랙아웃
5. 관전 상태로 전환

### 다른 플레이어 화면

1. 죽은 캐릭터가 공중으로 들어 올려짐
2. 바닥으로 떨어짐
3. 쓰러진 상태로 시체가 남음

## 5. 시체

플레이어가 죽으면 죽은 위치에 시체가 생성된다.

| 항목 | 규칙 |
| --- | --- |
| 생성 위치 | 플레이어가 사망한 위치 |
| 유지 시간 | 부활 또는 스테이지 종료까지 |
| 삭제 조건 | 부활 또는 스테이지 종료 |
| 귀신 반응 | 시체를 추격 대상으로 인식하지 않음 |
| 이동 | 생존 플레이어가 이동 가능 |

- 플레이어 혼자 기본 좌클릭으로 시체를 튕기면서 이동시킬 수 있다.
- 여러 플레이어가 협동하여 시체를 들어서 이동할 수도 있다.

## 6. 죽은 플레이어 상태

죽은 플레이어는 게임에서 이탈하지 않고 관전 상태로 남는다.

### 이동

- 맵 내부를 자유롭게 이동할 수 있다.
- 벽, 문, 가구 등의 물리 충돌을 받지 않는다.
- 귀신과 충돌하거나 귀신에게 공격받지 않는다.

### 상호작용

죽은 상태에서는 게임에 직접 개입할 수 없다.

- 오브젝트 상호작용 불가
- 가구 운반 불가
- 아이템 사용 불가
- 문 조작 불가
- 청소 작업 불가

### 귀신

- 죽은 플레이어는 귀신을 볼 수 있다.
- 귀신은 죽은 플레이어를 인식하지 않는다.
- 죽은 플레이어를 귀신의 추격 대상에서 제외한다.

### 음성 채팅

- 스테이지 진행 중 생존자는 생존자끼리, 사망자는 사망자끼리만 음성 채팅할 수 있다.
- 스테이지 종료 후에는 생존자와 사망자가 함께 음성 채팅할 수 있다.
- 사망자는 귀신을 볼 수 있으므로 생존자에게 귀신 위치 등의 정보를 전달할 수 없어야 한다.

스테이지 중 사망자 음성 채널의 거리·가림 정책은 [음성 채팅 시스템 기획서 §7](voice-chat-system.md#7-상태별-정책-2026-09-17-사용자-승인)를 따른다.

## 7. 죽은 후 패널티

스테이지 진행 중 사망 자체에 별도의 즉시 패널티는 없다. 생존 작업 인원은 줄어든다.

스테이지 종료 시점에 사망한 플레이어가 있으면 치료비를 청구한다.

> **치료비 = 스테이지 종료 시 사망자 수 × 1인당 치료비**

스테이지 도중 사망했더라도 종료 전에 부활했다면 치료비를 청구하지 않는다.

1인당 치료비 금액은 **TBD**이며, 추후 밸런싱으로 결정한다.

## 8. 전멸했을 경우

모든 플레이어가 동시에 `Dead` 상태이면 전멸로 판정한다.

> **전멸 조건: 생존 플레이어 수 = 0**

전원 사망 → 전멸 판정 → 스테이지 실패 → 정상 종료 정산·보상 이력 처리 → 로비 이동 순서로 진행한다. 종료·정산 규칙은 [스테이지 시스템 기획서](stage-system.md#4-정상-종료)를 따른다.

전멸 판정 이후에는 부활할 수 없다.

## 9. 플레이어 상태 전환

| 상태 | 규칙 |
| --- | --- |
| `Alive` | 정상 플레이 상태. 귀신의 추격 대상이 됨 |
| `Dead` | 생존 플레이 조작 불가, 시체 생성, 귀신 타깃에서 제외, 관전 상태, 사망자 음성 채팅 그룹으로 변경 |

부활에 성공하면 `Alive` 상태가 된다. 모든 플레이어가 `Dead` 상태가 되면 부활 시스템으로 넘어가지 않고 즉시 전멸 처리하며, 정산을 마친 뒤 로비로 돌아간다.

  `Result` 씬에서 사망자 수와 목표 가구·청소·생존 결과를 표시하고, 방장이 로비 이동을 시작한다.
  정산 이력은 현재 Steam 방의 로비 데이터에 게시한다. 치료비 단가는 **TBD**다.
- 기획 §3의 `Dead` 전환 순서와 현재 구현은 다르다. 서버의 귀신 타깃·생존 조작·RPC를
  즉시 차단하기 위해 `Dead`를 죽음 연출 시작과 동시에 확정한다. 화면 연출이 끝나면 관전에 진입한다.
- 구현·임시값·검증 범위는 [죽음 시스템 구현](../architecture/death-system.md)을 따른다.
- `Result` 씬에서는 생존자·사망자가 2D 전역 음성 채널로 합쳐진다. `Game` 중에는 두 그룹을
  분리하고, `Lobby`에서도 전원이 2D 전역 채널로 대화한다. 코드 반영 후 Unity Play 검증은 대기 중이다.
