## 2. 개요

### 2.1 문서 개요

- 스테이지에 있는 **가구의 내구도**가 무엇이고, **언제 얼마나 감소하며, 0이 되면 어떻게 되는지** 정의한다.
- 가구가 다른 오브젝트에 부딪쳤을 때의 충돌 속도 판정, 감소량 공식, 적용 대상·예외를 다룬다.
- 다음은 이 문서의 범위가 아니다.
  - 분해·조립 시 가구 내구도 값의 상속·평균 → [furniture-multidriver-system.md §5](furniture-multidriver-system.md)가 권위
  - 가구용 멀티 드라이버 **아이템** 내구도 → [furniture-multidriver-system.md §3.3](furniture-multidriver-system.md)
  - 반출·정산·승패 → [gdd.md §2](gdd.md), [map-generation.md MG-22](../architecture/map-generation.md)

### 2.2 시스템 개요

- **모든 가구**가 내구도 수치를 가진다.
- 가구가 **일정 속도 이상으로** 벽·바닥·다른 가구 등에 부딪치면 내구도가 감소한다.
  가구끼리 부딪치면 **두 가구 모두** 감소한다. 플레이어·귀신과 부딪친 것으로는 감소하지 않는다.
- 던져서 날아간 경우든 **중력으로 떨어진** 경우든 같은 규칙을 쓴다 — 부딪친 순간의 속도만 본다.
- 감소량은 **부딪친 속도에 비례**한다. 느리게 닿으면 깎이지 않고, 빠를수록 많이 깎인다.
- 내구도가 **0이 되면 가구가 사라진다.**
- 판정과 감소는 **서버(호스트)만** 한다. 모든 접속자는 같은 값을 본다.

### 2.3 기획 의도 [제안 — 사용자 확인 필요]

> **기획 의도**
> - 가구 던지기에 **비용**을 붙인다. 아무 데나 세게 던지면 옮겨야 할 가구가 망가져 사라진다.
> - 빠르지만 거친 운반(1인 투척)과 느리지만 안전한 운반(2인 고정 운반) 사이의 선택을 만든다.
> - 연쇄 충돌이 곧 연쇄 파손이 되어, 좁은 집 안에서 던질 방향을 고르게 한다.

### 2.4 구현 전 저장소 상태 (2026-09-15, 0.2 기준)

| 항목 | 상태 |

## 3. 내구도 규칙

### 3.1 사용자 요구 [확정 — 2026-09-15]

1. 가구에 **내구도**가 있다.
2. 가구가 **특정 속도 이상으로**(던짐·중력 낙하 모두) 오브젝트에 부딪치면 내구도가 감소한다.
3. 감소량은 **부딪친 속도에 비례**한다.

### 3.2 내구도 값

| 항목 | 규칙 | 상태 |
| --- | --- | --- |
| 적용 대상 | **모든 가구** — 일반 배치·랜덤 배치·방 프리셋·분해 가능 큰 가구·분해 부품 | [확정 — FD-1] |
| 붙박이·문·벽 | 내구도 없음. 붙박이(주방 카운터·위생도기 등)는 던질 수 없는 정적 구조물이라 "가구"에 넣지 않았다 | [초기 구현 승인] |
| 값 범위 | **0~100 정수.** 아이템 내구도·분해/조립 처리와 같은 형식 | [초기 구현 승인] |
| 시작 값 | 스테이지 시작 시 모든 가구 **100** (현재 구현 기본값) | [초기 구현 승인] |
| 스테이지 간 이월 | 없음. 스테이지마다 새로 시작한다 | [초기 구현 승인] |
| 최솟값 | 0 아래로 내려가지 않는다. 0이 되면 사라진다(§3.8) | [확정 — FD-10] |

### 3.3 충돌 속도 판정

- **충돌 속도**는 부딪친 순간 두 물체의 상대 속도 중 **부딪친 면에 수직인 성분**이다. [확정 — FD-3]
  - 이유: 벽이나 바닥을 따라 빠르게 **미끄러지는** 가구가 크게 깨지지 않게 한다.
  - 대안: 상대 속도의 크기 전체 — 미끄러짐도 파손으로 친다.
- **중력 낙하에 별도 규칙을 두지 않는다.** 떨어지며 붙은 속도가 곧 충돌 속도다. [확정 — §3.1 요구 2]
- **새로 닿는 순간만** 판정한다. 바닥에 놓여 있거나 벽에 붙어 계속 미는 동안에는 감소하지 않는다. [초기 구현 승인]
- **한 번의 충돌은 한 번만 깎는다.** 다리·상판 등 여러 부분이 동시에 닿거나 튕기며 연달아 닿아도,
  한 가구의 **0.2초** 안 접촉은 하나의 충돌로 보고 **가장 큰 충돌 속도 1회만** 적용한다. [초기값 승인 — FD-12]

### 3.4 감소량 공식 [초기값 승인 — FD-2·FD-4·FD-5]

```text
충돌 속도 v <  최소 속도 v_min  →  감소 없음
충돌 속도 v >= 최소 속도 v_min  →  감소량 = 내림( (v − v_min) × k × w ),  최대 상한
내구도 = max(0, 내구도 − 감소량)
```

| 값 | 의미 | 제안 초기값 | 근거 |
| --- | --- | --- | --- |
| `v_min` | 이 속도부터 깎인다 | **6 m/s** | 1m 낙하(4.4 m/s — 분해 부품 생성 높이)·1.5m 낙하(5.4 m/s)로는 깎이지 않고, heavy 1인 최소 투척(6 m/s)부터 깎이기 시작 |
| `k` | 기준 초과 1 m/s당 감소량 | **1.0** | light 1인 풀 차지 직격 1회가 약 1/4(24) |
| `w` | 무게 등급 계수 | **Light 1.0 / Heavy 1.0** | 무게 차이는 우선 반영하지 않는다 → FD-4 |
| 상한 | 1회 충돌 최대 감소량 | **50** | 물리 이상(겹친 가구 폭발 등)으로 한 번에 사라지는 것 방지 → FD-5 |

> **왜 `v`가 아니라 `(v − v_min)`에 비례하는가:** `v`에 바로 비례시키면 기준 속도를 넘는 순간
> 갑자기 6씩 깎이는 계단이 생긴다. 초과분에 비례하면 기준선 근처에서 0부터 부드럽게 늘어난다.
> 순수 비례(`감소량 = v × k`)를 원하면 FD-2에서 바꾼다.

수치는 코드 상수가 아니라 **ScriptableObject 설정 에셋**에 둔다(CLAUDE.md §3.4). 위 값은 승인된 초기값이며 `FurnitureDefinition_Light/Heavy` SO에서 조정한다.

#### 3.4.1 속도 기준표 — 현재 설정값으로 계산

근거 값: `FurnitureThrowSettings`(1인 30 · 2인 50 · 최소 차지 0.4 · heavy 1인 ×0.5 · 2인 운반 최대 15 m/s),
물리 중력 9.81 m/s²(`ProjectSettings/DynamicsManager.asset`), B안 층고 3.0m(TEMP, MG-7).

| 상황 | 충돌 속도(최대) | 제안 공식 감소량 |
| --- | ---: | ---: |
| 분해 부품·조립 완성품이 1m에서 떨어짐 | 4.4 m/s | 0 |
| 2층 높이(층고 3.0m)에서 1층으로 떨어짐 | 7.7 m/s | 1 |
| heavy 가구 1인 최소 차지 투척 | 6 m/s | 0 |
| light 가구 1인 최소 차지 투척 | 12 m/s | 6 |
| heavy 가구 1인 풀 차지 투척 | 15 m/s | 9 |
| 2인 고정 운반 중 최대 속력으로 벽에 부딪침 | 15 m/s | 9 |
| 2인 최소 차지 투척 | 20 m/s | 14 |
| light 가구 1인 풀 차지 투척 | 30 m/s | 24 (→ 약 5회째에 사라짐) |
| 2인 풀 차지 투척 | 50 m/s | 44 (→ 3회째에 사라짐) |

> 투척 행은 **발사 속도 그대로 벽에 수직으로 박힌** 최대치다. 실제로는 발사각 보정(20°~70°)과
> 비행 중 감속 때문에 부딪친 면의 수직 성분이 더 작아 감소량도 작다.
> 가구끼리 부딪치면 **두 가구가 각각** 이만큼 깎인다(§3.5).
> 투척 수치를 Steam 원격에서 재튜닝하면([gdd.md §7.2](gdd.md)) 이 표를 다시 계산한다.

### 3.5 부딪친 대상별 적용

| 부딪친 대상 | 이 가구 | 상대 | 상태 |
| --- | --- | --- | --- |
| 벽·바닥·천장·붙박이·문 | §3.4대로 감소 | — (내구도 없음) | [확정 — §3.1 요구 2] |
| 다른 가구 | §3.4대로 감소 | **상대 가구도 같은 충돌 속도로 감소** | [확정 — FD-6] |
| 플레이어 | **감소 없음** | — (플레이어 피해는 이 문서 범위 밖) | [확정 — FD-7] |
| 귀신 | **감소 없음** | — | [확정 — FD-7] |

- 가구끼리의 충돌에서 두 가구는 **같은 충돌 속도**를 쓰되, 무게 계수(`w`)·1회 판정 창(§3.3)·보호 시간(§3.7)은
  **가구마다 따로** 적용한다. 예: 보호 시간 중인 가구를 던진 가구가 맞히면 던진 가구만 깎인다. [초기 구현 승인]
- 플레이어·귀신에 맞고 튕겨 나간 가구가 이어서 벽·가구에 부딪치면, **그 충돌은 따로** §3.4로 판정한다. [초기 구현 승인]

### 3.7 감소 예외 — 배치 직후 보호 시간 [초기값 승인 — FD-12]

플레이어 행동이 아니라 **서버가 가구를 옮기거나 새로 나타나게 한 직후 1.0초** 동안은 감소하지 않는다.
보호 시간이 없으면 아래 상황에서 플레이어가 아무것도 하지 않았는데 가구가 깎이거나 사라질 수 있다.

| 상황 | 이유 |
| --- | --- |
| 세션 시작 — 서버가 가구 물리를 켜는 순간 | 살짝 겹친 가구가 서로 밀어내며 튕긴다([furniture-physics.md](../architecture/furniture-physics.md) "가구가 겹친 채로 시작하면 폭발한다") |
| 방 프리셋이 침실 슬롯으로 옮겨짐 (`RoomSlotAssigner`) | 순간이동 직후 안착 |
| 랜덤 가구 배치 (`FurnitureSpawnController`) | 순간이동 직후 안착 |
| 분해 부품 생성·조립 완성품 생성 | 1m 낙하에 더해, 부품이 서로 겹쳐 생성돼 튕긴다([furniture-multidriver.md §5](../architecture/furniture-multidriver.md)) |
| 개발용 가구 리셋 R (`FurnitureResetter`) | 순간이동 직후 안착 |

### 3.8 내구도가 0이 되면 — 사라진다 [확정 — FD-10, 2026-09-15]

> 사용자가 "**일단**" 이 안으로 정했다. 플레이테스트 후 파손 상태로 남기는 안(운반 가능 / 장애물)으로
> 바뀔 수 있으므로, 사라지는 처리는 한곳에 모아 교체하기 쉽게 구현한다.

- 충돌로 내구도가 **0이 된 즉시** 가구가 스테이지에서 사라진다. [확정]
- 사라진 가구는 **그 스테이지에서 다시 나타나지 않는다.** 개발용 리셋(R)만 예외다(§4). [초기 구현 승인]

| 항목 | 규칙 | 상태 |
| --- | --- | --- |
| 사라지는 방식 | 런타임 Despawn이 아니라 **숨기고 충돌·물리를 끈다** — 씬 배치 오브젝트 규칙([ADR-0009](../architecture/decisions/ADR-0009-scene-placed-level-objects.md)). 선례: `FurnitureDriverPoolItem.ServerDeactivate` | [확정 — 하드 룰] |
| 잡고 있던 플레이어 | 즉시 잡기가 풀린다. 발사하지 않는다 | [초기 구현 승인] |
| 위에 올려져 있던 가구 | 받침이 사라지면 물리대로 떨어진다. 이 낙하도 §3.4로 판정한다 | [초기 구현 승인] |
| 조립 영역 안에서 사라짐 | 영역 점유에서 빠진다. 조립 행동 중이었으면 "영역 밖으로 나감"과 같이 취소된다([멀티 드라이버 §4.2.1](furniture-multidriver-system.md)) | [초기 구현 승인] |
| 분해 부품이 사라짐 | 그 부품이 필요한 조립은 같은 종류 큰 가구에서 나온 다른 부품으로만 할 수 있다(멀티 드라이버 §4.3 규칙 2) | [확정 — 기존 규칙의 결과] |
| 작업 대상 가구가 사라짐 | Target Count를 채울 수 없게 될 수 있다 — 보충 여부 MG-23, 집계 MG-22 | [TBD] |
| 사라지는 연출 | 파편·사운드 등 | [TBD → FD-9] |

0에 **도달하기 전** 효과(예: 내구도 비례 보상, 50 이하 외형 변화)는 정하지 않았다 → FD-11.

### 3.9 분해·조립과의 관계 [확정 — 멀티 드라이버 기획서 §5]

이 문서는 멀티 드라이버 §5의 "분해 상태에서 작은 가구가 **손상됨**"이 무엇인지를 정의할 뿐, 값 처리 규칙은 바꾸지 않는다.

| 상황 | 처리 |
| --- | --- |
| 분해 | 모든 부품이 큰 가구의 내구도를 그대로 가진다 |
| 분해 상태에서 부품이 부딪침 | **그 부품만** §3.4대로 감소 (부품 자신의 무게 등급 적용). 0이 되면 그 부품만 사라진다 |
| 조립 | 사용한 부품 내구도의 평균(소수점 버림). 0인 부품은 이미 사라졌으므로 결과는 항상 1 이상이다 |

## 5. 기존 시스템과의 관계

| 항목 | 내용 |
| --- | --- |
| 물리 권위 | 판정·감소·사라짐은 **서버만** 한다([ADR-0010](../architecture/decisions/ADR-0010-server-authoritative-furniture-physics.md)). 클라이언트 가구는 kinematic 껍데기라 판정 주체가 될 수 없다. 값과 사라짐 상태는 서버 쓰기 `NetworkVariable`로 복제한다. 클라이언트 요청으로 내구도를 바꾸는 RPC를 두지 않는다 |
| 내구도 값 위치 | `FurnitureNetworkPhysics`의 서버 쓰기 `NetworkVariable<int>`가 단일 값이다. 드라이버 풀은 이 값을 읽고 상속한다 |
| 사라짐 구현 | 내구도 0을 파손 상태로 복제한다. 공통 코드가 렌더러·충돌·물리를 끄되 기존 풀 활성/배치 값은 보존한다. 파손 풀은 재사용·재배치를 거절하며 개발 복구만 허용한다 |
| 플레이어·귀신 구분 | 충돌 상대가 플레이어·귀신이면 판정에서 제외한다(FD-7). `GameLayers.Player/GhostPrototype` 또는 부모 `PlayerMotor/GhostPrototypeController`로 구분 |
| 계산 | 감소량 공식은 순수 함수로 분리해 EditMode로 검증한다. 선례: `Assets/Scripts/Gameplay/FurnitureDriver/FurnitureDurability.cs` |
| 복합 콜라이더 | 가구는 루트 `Rigidbody` 하나에 파츠 콜라이더가 여러 개다([furniture-physics.md](../architecture/furniture-physics.md)). 파츠마다 충돌이 따로 들어오므로 §3.3 "한 번의 충돌" 규칙이 필요하다 |
| 던지기 | 투척 규칙·수치는 바꾸지 않는다. 투척 힘을 올리면 파손도 커지므로 튜닝 시 §3.4.1을 함께 본다 |
| 맞은 가구의 상태 | "맞은 쪽을 `Launched`로 전환하지 않는다" 규칙은 그대로 둔다. 내구도 감소만 추가된다 |
| 설정 에셋 | 수치는 SO에 둔다. 기존 `FurnitureDefinition` SO에 충돌 수치·보호 시간·Held 적용을 추가한다 |
| 작업 대상·반출 | 사라진 작업 대상 가구의 집계·보충 → MG-22·MG-23 |

## 6. 수용 기준 (Unity 실행 검증 대기)

| # | 상황 | 기대 결과 |
| --- | --- | --- |
| AC-1 | 가구가 가만히 놓여 있음 | 시간이 지나도 감소하지 않는다 |
| AC-2 | 충돌 속도 `v_min` 미만 (예: 1m 낙하) | 감소하지 않는다 |
| AC-3 | 충돌 속도 `v_min` 이상 | `내림((v − v_min) × k × w)`만큼, 상한 이하로 감소한다 |
| AC-4 | 던진 가구가 벽에 박히며 여러 파츠가 동시에 닿음 | 1회만 감소한다(가장 큰 속도 기준) |
| AC-5 | 던진 가구가 놓인 가구를 맞힘 | **두 가구 모두** 감소한다 |
| AC-6 | 던진 가구가 플레이어·귀신에 맞음 | 감소하지 않는다. 튕겨서 벽에 부딪치면 그 충돌은 따로 판정한다 |
| AC-7 | 세션 시작·프리셋 이동·랜덤 배치·분해/조립·리셋 직후 1초 | 튕기거나 떨어져도 감소하지 않는다 |
| AC-8 | 내구도 3인 가구가 감소량 10 충돌 | 0이 되고 **즉시 사라진다** — 보이지 않고, 충돌하지 않고, 잡을 수 없다 |
| AC-9 | 두 명이 잡고 운반하던 가구가 0이 됨 | 두 홀더의 잡기가 풀리고 발사되지 않는다 |
| AC-10 | 사라진 분해 부품·큰 가구 | 이후 분해·조립으로 **다시 나타나지 않는다** |
| AC-11 | Host + Client 접속 | 모든 접속자가 같은 값·같은 사라짐을 본다. 클라이언트 쪽에서 값을 바꿀 수 없다 |
| AC-12 | 분해·조립 | 멀티 드라이버 §5 상속·평균이 그대로 동작한다 |
