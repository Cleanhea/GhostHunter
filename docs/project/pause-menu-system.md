### 2.3 시스템 목적

일시정지 메뉴는 **매치를 떠나는 유일한 정상 경로**다. 현재 `Game` 씬에는 매치를 벗어나는
플레이어 조작이 하나도 없다 — 세션을 끝내려면 프로세스를 죽이는 수밖에 없다.

```text
매치 중 → ESC → [계속하기 / 설정 / 타이틀로 / 종료]
                             └─ 세션 종료 → 타이틀
매치 중 → 호스트 이탈·연결 실패 → "호스트와 연결이 끊겼습니다." → 확인 → 타이틀
```

두 흐름 모두 **도착지가 타이틀(`Title` 씬)이고, 도착 전에 NGO 세션을 정리한다.**

### 2.4 기획 의도

> **기획 의도**
> - **일시정지가 아니라 "메뉴"다.** 4인 P2P 세션에서 한 명이 시간을 멈출 수 없다.
>   메뉴를 열어도 귀신은 계속 추격하고 정신력은 계속 깎인다.
> - 그래서 이 메뉴는 **위험을 감수하고 여는 것**이다. 다만 그 위험을 UI로 설명하지는 않는다 —
>   플레이어가 직접 겪어서 배우게 둔다(PM-2).
> - 연결이 끊겼을 때 **검은 화면이나 멈춘 화면으로 방치하지 않는다.** 무슨 일이 일어났는지
>   한 문장으로 알리고, **플레이어가 확인을 누른 뒤에** 되돌려 보낸다.

## 3. 진입과 종료

### 3.1 여는 키 [확정]

| 항목 | 값 |
| --- | --- |
| 키 | **ESC** |
| 대상 씬 | `Game` **만**. `Title`·`Lobby`·`Result` 에는 열리지 않는다 |
| 토글 여부 | ESC 로 열고, ESC 로 닫는다(= "계속하기"와 동일 동작) |
| 적용 대상 | **로컬 플레이어 본인만.** 호스트가 열어도 게스트의 화면은 변하지 않는다 |

**ESC 는 더 이상 커서 잠금 토글이 아니다** — §3.5 참조.

### 3.2 시간은 멈추지 않는다 [확정]

**`Time.timeScale` 을 건드리지 않는다. 항상 1이다.**

| 이유 | 내용 |
| --- | --- |
| 멀티플레이 | `timeScale` 은 로컬 값이다. 한 명이 0으로 만들어도 서버 시뮬레이션과 다른 피어는 계속 돈다 |
| 서버 권위 | 가구 물리·귀신 AI·정신력은 전부 서버가 판정한다([networking.md §1](../architecture/networking.md)). 클라이언트가 자기 시간을 멈추면 **자기 화면만 어긋난다** |
| 호스트 | 호스트가 `timeScale=0` 을 하면 **세션 전체가 멈춘다.** 한 플레이어의 메뉴 조작이 다른 셋의 게임을 정지시키는 것은 허용하지 않는다 |

따라서 메뉴가 열린 동안에도 아래는 **전부 계속 진행된다.**

| 계속 도는 것 | 근거 |
| --- | --- |
| 귀신 상태 전이·탐지·추격·어택·잡힘 | [ghost-system.md §4·§8](ghost-system.md) |
| 정신력 감소(어둠 노출·목격) | [sanity-system.md](sanity-system.md) |
| 가구 물리와 다른 플레이어의 던지기 | [../architecture/throw-system.md](../architecture/throw-system.md) |
| 굴착 스킬 유지·종료 타이머 | [mole-skill-system.md §5](mole-skill-system.md) |
| 네트워크 송수신 | — |

### 3.3 메뉴는 안전지대가 아니다 [확정]

§3.2의 직접적 귀결이다. **메뉴를 연 플레이어는 귀신에게 그대로 잡힌다.**

- **무적·보호 시간을 주지 않는다** [확정]. 그런 예외는 서버 판정에 클라이언트 UI 상태를
  끌어들이므로 [networking.md §1](../architecture/networking.md)에 어긋난다.
- **이 위험을 UI로 경고하지 않는다** [확정, PM-2] — 문구·아이콘·타이머를 두지 않는다.
  플레이어가 겪어서 배우게 둔다.

> **⚠️ §3.4와 합쳐진 결과를 인지할 것.** 메뉴 중에는 조작이 전부 잠기고(§3.4) 경고도 없으므로,
> **메뉴를 연 플레이어는 회피할 수단이 없는 채로 잡힐 수 있다.** 이것이 의도된 설계다.

### 3.4 메뉴가 열린 동안의 플레이어 조작 [확정] — 전부 잠금

**이동·시점·상호작용·던지기·스킬 입력을 전부 잠근다.**

| 잠기는 것 | 컴포넌트 |
| --- | --- |
| 이동·점프·자세(웅크리기·엎드리기) | `PlayerMotor` |
| 시점(마우스 델타 → 요·피치) | `PlayerLook` |
| 가구 조준·잡기·던지기 | `FurnitureTargeter`·`GrabController` |
| 문 상호작용(E) | `PlayerInteractor` |
| 굴착 스킬 | `MoleBurrowController` |

**MUST — 잠금은 로컬 입력 단계에서만 한다.** `PlayerMotor`·`PlayerLook` 은 소유자 권위
(**[ADR-0008](../architecture/decisions/ADR-0008-owner-authoritative-player-movement.md)**)이므로
잠금은 서버에 보고되지 않는다. **서버가 알아야 할 상태를 만들지 않는다.**

- 잠금 중에도 **캐릭터는 서버 시뮬레이션 안에 그대로 있다** — 중력·충돌·가구에 맞는 것은 계속된다.
- 이미 진행 중인 굴착은 **잠금과 무관하게 종료 타이머대로 끝난다**(§3.2).

**가구를 홀드한 채 메뉴를 열면 그 가구는 발사된다** [확정, PM-15].

| 항목 | 규칙 |
| --- | --- |
| 판정 | **마우스 좌클릭을 뗀 것과 동일하게 취급한다.** 차지량·발사각 보정 전부 평소와 같다 |
| 방향 | 메뉴를 연 **그 순간의 조준 방향** |
| 2인 홀드 | 평소의 1인 해제 정책(`launchOnFirstRelease`)을 그대로 따른다. 예외를 두지 않는다 |
| 권위 | **서버가 발사한다.** 클라이언트는 평소와 같은 해제 요청을 보낼 뿐이다 |

> **⚠️ 구현 함정.** 입력을 잠그기만 하면 발사되지 않는다 —
> `GrabController` 는 `AttackReleasedThisFrame` 을 봐야 해제 요청을 보내는데, 입력이 잠기면
> 그 프레임이 영영 오지 않아 **가구가 계속 떠 있는다.** 메뉴를 여는 쪽에서 해제를 **명시적으로
> 한 번 호출한 뒤** 잠가야 한다 → [../architecture/pause-menu.md §6.4](../architecture/pause-menu.md)

### 3.5 커서와 ESC 충돌 해소 [확정] — 해소안 A

**메뉴가 커서 잠금을 대신 관리한다.**

| 항목 | 규칙 |
| --- | --- |
| 메뉴 열림 | `Cursor.lockState = None`, `Cursor.visible = true` |
| 메뉴 닫힘 | `Cursor.lockState = Locked`, `Cursor.visible = false` |
| `PlayerLook` | **ESC 커서 토글 블록을 제거한다.** `PlayerLook` 은 더 이상 커서를 직접 다루지 않는다 |
| 예외 | 스폰/디스폰 시의 초기 잠금·해제는 `PlayerLook` 이 그대로 유지한다 |

**대가로 "메뉴 없이 커서만 푸는" 개발 편의가 사라진다** — 에디터에서는 메뉴를 열면 커서가 풀리고,
개발 HUD(Tab)·튜닝 창(F2)은 자기 커서 처리를 그대로 쓴다.

### 3.6 열기 제한 [확정] — 없다

**어떤 상태에서도 메뉴를 열 수 있다** [확정, PM-10]. 아래 중 무엇도 진입을 막지 않는다.

| 상태 | 메뉴 열기 |
| --- | --- |
| 사망 | 허용 |
| 귀신 경고·어택 중, 추격당하는 중 | 허용 |
| 굴착(땅속) 중 | 허용 |
| 가구 홀드 중 | 허용 — 가구는 발사된다(§3.4) |

§3.3이 "메뉴는 안전지대가 아니다"를 이미 감수하므로, 여는 것 자체를 막을 이유가 없다.
**추격 도중 메뉴를 열어 조작을 잃고 잡히는 것은 플레이어의 선택이다.**

## 4. 메뉴 구성

### 4.1 항목과 순서 [확정]

**4개, 이 순서로 고정한다.**

| # | 항목 | 한 줄 정의 | 상태 |
| --- | --- | --- | --- |
| 1 | **계속하기** | 메뉴를 닫고 플레이로 돌아간다 | [확정] |
| 2 | **설정** | **이번 범위에서는 stub** | [확정] — 내용은 **[TBD] PM-6** |
| 3 | **타이틀로** | 세션을 정리하고 `Title` 씬으로 돌아간다 | [확정] |
| 4 | **종료** | 확인 대화상자를 거쳐 게임을 끝낸다 | [확정] |

### 4.2 계속하기 [확정]

- 메뉴를 닫는다. ESC 를 다시 누른 것과 같다.
- 커서를 다시 잠그고(§3.5) 플레이어 입력 잠금을 푼다(§3.4).
- **네트워크에 아무것도 보내지 않는다.**

### 4.3 설정 [확정 — stub] / 내용 [TBD] PM-6

**이번 범위는 stub 이다.** 버튼은 4항목 순서를 지키려고 자리에 있지만, 누르면 설정 화면이
열리지 않는다. `Title` 화면과 같은 수준(`"설정은 아직 미구현입니다."`)으로 처리한다.

> **현재 사실:** 저장소에 설정 시스템이 없다. `Title` 의 설정 버튼은
> `MainMenuController.HandleSettingsClicked()` 에서 **상태 문구만 출력**한다.
> 저장(영속화) 방식도 미정이다 → [../architecture/overview.md §10](../architecture/overview.md).

설정 시스템을 만들 때 정할 것(PM-6): 항목(감도·음량·해상도·언어), 저장 방식,
`Title` 설정과 **같은 화면을 공유하는지**.

### 4.4 타이틀로 [확정]

| 항목 | 값 |
| --- | --- |
| 도착지 | **`Title` 씬. `Result` 를 거치지 않는다** [확정, PM-11] |
| 경유 | 씬 전환은 MUST `ISceneFlow.Load(SceneId.Title)` — `SceneManager` 직접 호출 금지 |
| 순서 | **세션 종료 → 씬 전환** [확정] → [networking.md §3.6.1](../architecture/networking.md) |
| 확인 대화상자 | **없다.** 확인을 거치는 것은 "종료"뿐이다(§4.5) |

**누가 눌렀느냐에 따라 파급이 다르다.**

| 누른 사람 | NGO 세션 | Steam 로비 | 다른 플레이어 |
| --- | --- | --- | --- |
| **호스트** [확정, PM-4] | 종료 | 호스트는 나간다 | **게스트 전원 강제 종료** — 각자 §5의 끊김 흐름을 탄다 |
| **게스트** [확정, PM-5] | 자기 연결만 끊는다 | **로비에는 남는다** | 영향 없음. 매치는 계속된다 |

> **PM-4 — 호스트 마이그레이션은 하지 않는다.** 호스트가 나가면 세션이 끝난다
> ([networking.md §2.4](../architecture/networking.md)). 게스트에게는 §5의 "호스트와 연결이
> 끊겼습니다." 가 그대로 뜬다 — 정상 종료와 비정상 종료를 구분하지 않는다(PM-9).
>
> **PM-5 — 게스트는 Steam 로비 멤버로 남는다.** 즉 `ISteamLobbyService.LeaveLobby()` 를 부르지
> 않는다. **현재 `ConnectionManager.Disconnect()` 는 로비 퇴장까지 함께 하므로 분리가 필요하다**
> → [../architecture/pause-menu.md §3.1](../architecture/pause-menu.md).

#### 로비 복귀 [확정] PM-14

**로비에 남은 게스트가 매치로 돌아갈 진입점을 `Title` 화면에 둔다.**

| 항목 | 규칙 |
| --- | --- |
| 위치 | `Title` 화면 |
| 표시 조건 | **Steam 로비에 아직 속해 있을 때만** 보인다. 로비가 없으면 숨긴다 |
| 동작 | `Lobby` 씬으로 이동한다 |
| 재접속 | 호스트가 아직 매치 중이면 **자동으로 다시 접속된다** — `LobbyController` 가 로비의 게임 시작 신호를 보고 이미 그렇게 동작한다 |

> 즉 새로 만들 것은 **진입점 하나**이고, 재접속 로직은 이미 있다
> → [../architecture/pause-menu.md §11](../architecture/pause-menu.md).

### 4.5 종료 [확정]

**확인 대화상자를 거친다** [확정, PM-7]. 즉시 종료하지 않는다.

```text
"종료" 클릭 → [정말 종료하시겠습니까?  확인 / 취소] → 확인 → 세션 정리 → 앱 종료
```

| 항목 | 값 |
| --- | --- |
| 확인 대화상자 | **필수.** "취소"는 메뉴로 돌아간다 |
| 세션 정리 | **"타이틀로"와 같은 절차를 밟는다** [확정, PM-13] — 세션 종료 후 앱을 닫는다 |
| 호스트가 누르면 | 호스트 이탈이므로 게스트 전원이 §5의 끊김 흐름을 탄다(PM-4와 동일) |
| 에디터 | `#if UNITY_EDITOR` → `EditorApplication.ExitPlaymode()`, 빌드 → `Application.Quit()` [확정] |

> 에디터 분기는 `Title` 의 종료 버튼이 이미 쓰는 방식과 같다. 없으면 에디터에서 플레이 모드가
> 안 꺼져 검증이 불가능하다.

## 5. 호스트 연결 끊김 처리

### 5.1 확정된 것

| 항목 | 값 |
| --- | --- |
| 문구 | **"호스트와 연결이 끊겼습니다."** |
| 표시 형태 | **모달** — 뒤쪽 조작을 막는다 [확정, PM-8] |
| 이동 방식 | **확인 버튼을 눌러야 나간다.** 자동 이동·타이머 없음 [확정, PM-8] |
| 도착지 | 메인메뉴(`Title` 씬). `Result` 를 거치지 않는다 |
| 대상 | **게스트만.** 호스트 자신은 이 흐름을 타지 않는다(§5.4) |
| 정리 | 확인 전에 NGO 세션을 정리한다. 세션은 이미 죽어 있으므로 "계속하기"는 성립하지 않는다 |

### 5.2 흐름

```text
[매치 중] ── 호스트 이탈 / 타임아웃 / 트랜스포트 실패 / 강퇴 ──▶ 세션 종료 감지
        ──▶ 모달: "호스트와 연결이 끊겼습니다."  [확인]
        ──▶ (플레이어가 확인을 누를 때까지 대기 — 자동 이동 없음)
        ──▶ ISceneFlow.Load(Title)
```

- 일시정지 메뉴가 열려 있는 중에 끊기면 **모달이 메뉴를 덮는다.** 메뉴로 돌아갈 수 없다.
- 확인을 누르지 않고 방치해도 아무 일도 일어나지 않는다. 게임은 이미 끝났다.

### 5.3 사유를 구분하지 않는다 [확정] PM-9

**아래 4가지 모두 같은 문구를 쓴다.**

| 사유 | 문구 |
| --- | --- |
| 호스트가 정상 종료("타이틀로"·"종료") | **"호스트와 연결이 끊겼습니다."** |
| 타임아웃 | 〃 |
| 트랜스포트 실패(Steam·SDR 릴레이) | 〃 |
| 강퇴 / 접속 거부 | 〃 |

> 문구가 하나면 구현·번역·검증이 모두 단순해진다. NGO 의 `DisconnectReason` 은 **콘솔 로그에만**
> 남기고 UI 에는 노출하지 않는다.

### 5.4 호스트 자신은 이 흐름을 타지 않는다 [확정]

호스트에게 연결 끊김은 "게스트가 나갔다"는 뜻이다. 호스트가
"호스트와 연결이 끊겼습니다."를 보는 일은 **없어야 한다.**

### 5.5 재접속은 제공하지 않는다 [확정]

재접속·호스트 마이그레이션은 [overview.md §4](overview.md)에서 **범위 제외**다.
끊김 모달에 "재접속" 버튼을 두지 않는다. 다시 하려면 타이틀에서 방을 새로 만들거나 참가한다.

## 6. 다른 시스템과 겹치는 지점

| 항목 | 내용 | 상태 |
| --- | --- | --- |
| **ESC 커서 토글** | `PlayerLook` 의 ESC 블록을 **제거**하고 메뉴가 커서를 관리한다 | ✅ 해결(PM-3, 해소안 A) → §3.5 |
| **가구 홀드 중 메뉴 열기** | **발사된다** — 좌클릭을 뗀 것과 같은 판정. 잠그기 전에 해제를 명시 호출해야 한다 | ✅ 해결(PM-15) → §3.4 |
| **개발 HUD** | 접속 HUD 는 **Tab**, 밸런스 튜닝 창은 **F2**(`ConnectionHud`). ESC 와 겹치지 않지만, HUD 가 열린 채 메뉴를 열면 IMGUI 창과 Canvas UI 가 겹친다 | 낮은 우선순위 |
| **`UI/Cancel` 액션** | `UI` 맵에 `Cancel` 이 `*/{Cancel}` 사용처로 이미 있다(키보드 ESC 대응). 여는 입력·닫는 입력을 어느 액션으로 받는지는 구현 문서가 정한다 | → [../architecture/pause-menu.md §6](../architecture/pause-menu.md) |
| **귀신 어택** | 메뉴 중에도 어택·잡힘이 계속되고, 조작이 잠겨 회피할 수 없다. **추격 중에도 메뉴를 열 수 있다** | ✅ 의도된 설계(§3.3·§3.6) |
| **굴착 스킬** | 굴착 중 메뉴를 열어도 종료 타이머는 계속 돈다. 잠금은 새 입력만 막는다 | ✅ 해결(§3.4) |
| **`Result` 씬** | 거치지 않는다 | ✅ 해결(PM-11) |
| **Steam 로비** | 게스트는 로비에 남고 호스트는 나간다. `Title` 의 로비 복귀 진입점으로 되돌아온다 | ✅ 해결(PM-4·PM-5·PM-14) |
