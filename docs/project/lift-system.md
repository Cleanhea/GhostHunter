## 2. 시스템 개요 (원문)

- 2층, 3층 등 고층의 외벽 또는 발코니에서 가구를 1층으로 운반할 수 있는 기계 장치다.
  → 가구 운반 루트를 다양화하고, 한 번에 여러 가구를 옮길 수 있게 해 작업의 지루함을 보완한다.
- 리프트 본체에 있는 버튼을 눌러 기계를 작동한다.
- 레퍼런스: 휴먼 폴 플랫 「수행」 맵의 리프트 — https://youtu.be/K4NDuUuUY6E?t=49

## 3. 규칙

### 3.1 원문 규칙과 구현

| # | 원문 규칙 | 구현 |
| --- | --- | --- |
| LF-1 | 리프트는 '상승 버튼'과 '하강 버튼'으로 이루어진다. 용도에 맞는 버튼을 눌러 올리고 내린다 | 버튼 방향 2종(`LiftDirection`). 본체 바닥판(③)과 승강 발판 위 버튼판(②)에 같은 상승·하강 버튼이 하나씩 있다 |
| LF-2 | 각 버튼은 **1회 입력되면 건물의 한 층 높이**를 이동하는 것을 기본으로 한다. 층 높이마다 **정지 포인트**를 지정하는 방법으로 구현한다 | 정지 포인트 = 맨 아래에서 0, 1×, 2×… 층 높이(`LiftSettings`). 입력 방향의 **가장 가까운** 정지 포인트로 간다 |
| LF-3 | 리프트가 **이동 중에는 버튼이 입력되어도 무시**한다 | 서버가 이동 중 입력을 버린다. 같은 방향이든 반대 방향이든 목표를 바꾸지 않는다 |
| LF-4 | 이동해야 하는 동선이 **물리적으로 막혀 있으면** 충돌이 발생한 지점에서 이동이 멈추고 **종료**된다 | 서버가 이동 경로를 매 프레임 훑어 막히면 그 앞에서 멈추고 이동을 끝낸다 → [architecture §4](../architecture/lift-system.md) |
| LF-5 | 막혀 중간에 선 뒤에는 한 층을 **제자리에서** 다시 가는 것이 아니라, **입력된 방향의 가장 가까운 정지 포인트**에서 멈춘다 | LF-2의 규칙이 그대로 적용된다. 정지 포인트에 서 있으면 인접한 다음 정지 포인트, 중간에 서 있으면 그 방향의 가장 가까운 정지 포인트 |

### 3.2 버튼 입력 — 원문의 두 서술이 어긋난다

원문 §2-1은 버튼을 **"던지기 상호작용"** 으로 누른다고 하고, §2-3(규칙)은 **"우클릭"** 으로 상호작용한다고 한다.

> **미결정 (LF-Q1):** 버튼을 무엇으로 누르는가.
> **임시 구현 [TEMP]:** 규칙 절(§2-3)을 따라 **우클릭 한 번**(누르는 순간)으로 구현했다. 입력 액션은 기존 `Player/UseDriver`(마우스 우클릭)를 공유하며 드릴(가구용 멀티 드라이버)을
> 들고 있지 않아도 된다. 조준선이 버튼에 2.5m 안으로 닿아야 하고, 서버는 플레이어와 같은 방향 버튼 사이 거리 3.5m 이내·생존 중인지 다시 검사한다.
> "던지기"가 가구를 버튼에 던져 맞히는 것이라면 구현이 달라지므로 기획자 확인이 필요하다.

## 4. 크기와 외형

### 4.1 구성 요소 (원문)

원문 레퍼런스 그림의 번호를 그대로 쓴다.

| 번호 | 구성 요소 | 구현 |
| --- | --- | --- |
| ① | 상하로 이동하는 **승강 발판** | 키네마틱 판 `Platform/Deck` |
| ② | 이동하는 바닥(발판)에 설치된 **버튼판** | 발판에 붙어 같이 오르내리는 `DeckPanel` + 버튼 2개 |
| ③ | 리프트 본체 바닥에 고정된 **버튼판** | 본체에 붙은 `BasePanel` + 버튼 2개 |
| ④ | **바퀴가 달린 하부 본체** | 동적 Rigidbody `Chassis` + 바퀴 4개(보이는 장식) |

"리프트 바닥에 바퀴를 달아 움직일 수 있도록 할 예정"이라는 원문 메모가 ④의 근거다.

### 4.2 프로토타입 치수 (원문)

크기는 맵과 리프트 외형에 따라 레벨 디자인 단계에서 조정한다. **프로토타입 단계는 아래대로 구현한다.**

- ① 승강 발판은 **최대 3m 높이**까지 올라간다 → `LiftSettings_Default` 층 높이 3m, 정지 포인트 2개.
- ① 승강 발판은 **3 × 2m**, 테두리에 별도 가드 없음 → `Deck` 3.0 × 0.08 × 2.0m.
- 리프트는 플레이어의 '던지기'로 위치를 이동할 수 있다.
  - 플레이어가 **하부 본체를 조준하고 던지기 입력**을 쓰면 본체에 **수평 방향**의 힘이 가해져 움직인다.
  - 이때 리프트는 **공중에 뜨지 않으며 뒤집히지도 않는다.**

### 4.3 구현 치수 [TEMP]

원문에 없는 외형 수치는 레퍼런스 그림의 비율로 정한 임시값이다.

| 부분 | 치수(m) | 비고 |
| --- | --- | --- |
| 하부 본체 `Chassis` | 3.8 × 0.16 × 2.2 | 지면에서 0.16m. 발판이 맨 아래일 때 윗면이 지면에서 약 0.24m — CharacterController `stepOffset` 0.3m 안이라 걸어 올라탄다 |
| 승강 발판 `Deck` | 3.0 × 0.08 × 2.0 | 맨 아래에서 본체 윗면에 얹힌다 |
| 기둥 `Post` | 0.12 × 5.0 × 0.12 | 2개. **건물 쪽으로 붙이는 가장자리(로컬 −Z)는 통째로 비우려고** 반대쪽(로컬 +Z) 두 모서리에만 둔다. 높이 5.0m는 최대 3.57m 이동에 더해 가구를 든 채 서도 머리 위로 지나가는 높이 |
| 버튼판 | 0.34 × 1.0 × 0.12 | 본체판은 본체 오른쪽 가장자리, 발판판은 발판 오른쪽 뒤쪽 |
| 버튼 | 0.16 × 0.16 × 0.05 | 상승 연노랑, 하강 주황 — 색 외에 방향 표시(삼각형)는 아직 없다 |

레퍼런스의 큰 프레임(보라색 문틀)은 만들지 않았다. 외형은 아트 단계에서 바꾼다.

## 5. 원문에 없어서 구현자가 정한 것 [TEMP]

| # | 항목 | 임시 구현 | 확인 필요 |
| --- | --- | --- | --- |
| LF-6 | 이동 속도 | 최대 1.5m/s, 가속 2m/s²(`LiftSettings`). 출발·정지 때 부드럽게 가감속 | 속도·체감 |
| LF-7 | 본체 밀기 | **1인**만 가능. 좌클릭 홀드(차지)·떼면 수평으로 민다. **2인 잡기·부양은 막는다**(공중에 뜨지 않는다는 원문 규칙). 발사 속도는 가구 정의 `launchSpeedScale` 0.5 배율 — 최대 차지(1초) 7.5m/s에 **약 3.8m** 미끄러지고, 살짝 눌러 1.1m/s에 약 0.2m(PlayMode 실측, 바닥 마찰 0.1·감쇠 1.2) | 밀리는 거리·세기 |
| LF-8 | 본체 회전 | 회전을 모두 고정한다(뒤집히지 않음). 밀어도 제자리에서 돌지 않고 평행 이동만 한다 | 방향 전환이 필요한가 |
| LF-9 | 탑승 | 승강 발판 위의 플레이어는 발판이 움직인 만큼 같이 옮겨진다. 발판에 얹힌 가구는 물리로 같이 올라간다 | 가구가 미끄러지는 정도 |
| LF-10 | 막힘 판정 범위 | 발판 판 모양을 이동 방향으로 훑는다. **발판에 얹힌 짐과 플레이어는 막힘이 아니다**(같이 움직임). 천장·벽·발판 위 높이를 넘는 장애물은 판정하지 않는다 | 짐이 천장에 끼는 경우 |
| LF-11 | 사용 조건 | 사망자는 못 누른다(문과 같은 규칙). 호스트 이전 시 리프트는 맨 아래로 돌아간다 | |
| LF-12 | 층 높이가 다른 맵 | 맵별 `LiftSettings` 에셋을 따로 둔다 — 한 종류 = 한 프리팹이라 인스턴스에서 치수를 바꾸지 않는다 | |

## 6. 맵 배치 (Tutorial · Stage1)

사용자 요청(2026-11-06): "맵에 우선 튜토리얼, 1스테이지 배치". 두 맵 모두 **2층에서 앞마당(1층)** 으로 가구를 내리는 용도다.

| 맵 | 위치 | 층 높이 | 맵을 고친 곳 |
| --- | --- | --- | --- |
| Tutorial | 모텔 발코니 앞(+Z) 남서쪽, 월드 (−5.125, 0.03, 2.75). 발판 윗면이 맨 위에서 발코니 바닥(3.57m)보다 약 0.27m 높다. 버튼판이 앞마당 쪽(+Z)을 본다 | **3.57m** (`LiftSettings_Tutorial` — 발코니 높이. 프로토타입 3m로는 발코니에 닿지 않는다) | 앞쪽 난간 `Balcony_Railing` 한 덩어리를 끄고, 리프트 구간(x −6.5~−3.75)만 비운 임시 난간 조각(`Lift_BalconyRailPatch`)을 세웠다. 난간 외형이 원본과 다르다 |
| Stage1 | 집 남쪽 앞마당, 월드 (61.67, 0, −13.22), Y 180° — 2층 가족실 남쪽 창 자리 바로 밖. 버튼판이 마당(−Z) 쪽을 본다 | **3.0m** (`LiftSettings_Default`) | 가족실 남쪽 창 5조각을 끄고, 2층 외벽 `Outer_South`·방 벽 `FamilyRoom/Wall_South`에 폭 2.0m·높이 2.5m 개구부를 냈다(각각 3조각으로 나눔, 위는 상인방) |

> **미결정 (LF-Q2):** Tutorial 난간 개구부와 Stage1 외벽 개구부는 리프트를 쓸 수 있게 하려고 **구현자가 맵을 임의로 고친 것**이다. 외형·위치는 레벨 디자인이 확정한다.
> 되돌리려면 Tutorial은 `Balcony_Railing` 활성화 + `Lift_BalconyRailPatch` 삭제, Stage1은 `Outer_South`·`Wall_South` 조각 복원이다.

## 7. 다른 시스템과의 관계

| 시스템 | 관계 |
| --- | --- |
| 가구 던지기 | 본체 밀기는 가구 던지기 파이프라인(타겟팅·차지·`FurnitureGrabTarget`)을 그대로 쓴다. 가구 정의 `FurnitureDefinition_Lift`가 홀더 1명·수평 발사·속도 배율을 정한다 → [throw-system.md](../architecture/throw-system.md) |
| 반출·정산 | 리프트는 반출 대상 가구가 아니다(`RandomFurnitureItem` 없음). 발판에 가구를 실어 내린 뒤 드릴카 반출 구역으로 옮기는 기존 흐름은 그대로다 → [stage-system.md](stage-system.md) |
| 귀신 | 귀신은 작은 소품(Light 등급)만 흔든다. 리프트는 Heavy 등급이라 대상이 아니다 |
| 호스트 이전 | 복구 스냅샷에 리프트 높이를 넣지 않았다. 호스트가 바뀌면 맨 아래로 돌아간다 [TEMP] |
