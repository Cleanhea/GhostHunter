## 2. 개요

### 2.1 문서 개요

- 플레이어끼리 **마이크로 말할 때 상대에게 얼마나 크게 들리는가**를 정의한다.
- 거리 감쇠 공식, 벽 가림 감쇠, 층 차이 차단, 캡처·전송·재생 경로, 서버의 역할을 다룬다.
- 다음은 이 문서의 범위가 아니다.
  - 게임 SFX·BGM·발소리 등 **비음성 오디오** → 별도(미작성). 귀신의 소리 탐지는 [ghost-system.md §8.3](ghost-system.md)이 권위
  - 텍스트 채팅·이모트·핑
  - 무전기/스피릿박스 같은 **아이템 기반 원거리 통신** → VC-12
  - 음성 녹음 저장·신고·모더레이션 → VC-16

### 2.2 시스템 개요

- 플레이어의 마이크 음성은 **그 플레이어의 입 위치에서 나오는 3D 소리**로 다른 플레이어에게 들린다.
- **수평(XZ) 거리**만으로 크기를 정한다. 가까울수록 크고, **10m를 넘으면 들리지 않는다.**
- **사이에 벽이 있으면 확실하게 줄어든다.** 단순히 켜고 끄는 것이 아니라, 막힌 정도에 비례해
  **음량이 줄고 동시에 고음이 깎여(로우패스) 먹먹해진다.** 모퉁이를 돌 때 끊기지 않고 부드럽게 변한다.
- **층이 다를 정도로 높이가 벌어지면 들리지 않는다.**
- **기본은 오픈 마이크다.** 말하면 자동으로 송신되고, 설정에서 푸시 투 토크로 바꿀 수 있으며 `M`으로 완전히 끌 수 있다.
- 판정 중 **누구에게 보낼지는 서버(호스트)가** 정하고, **최종 음량·가림 계산은 듣는 쪽 클라이언트가** 한다(§5.3).

### 2.3 기획 의도 [제안]

> - 팀이 **흩어지면 고립된다.** 혼자 2층에 올라가면 아래층 비명이 안 들린다 — 공포 협동물의 기본 압력.
> - 벽 너머의 **먹먹한 목소리**가 위치 정보를 준다. "어디야?"를 소리만으로 되묻게 만든다.
> - 가구 운반은 2인 협업이 필요하므로(투척·멀티 드라이버), 근접 대화 가능 범위가 곧 **협업 가능 범위**다.

## 4. 들리는 조건 — 감쇠 알고리즘

모든 계산은 **듣는 쪽(리스너) 클라이언트에서** 수행한다(서버 컬링은 §5.3).

기호:

```
L = 리스너 귀 위치(AudioListener transform.position)
S = 말하는 사람 입 위치(원격 플레이어 머리 본/카메라 피벗)
d  = |(S.x - L.x, S.z - L.z)|      ← 수평 거리 (VC-A)
dy = |S.y - L.y|                   ← 수직 거리
```

### 4.1 수평 거리 감쇠 `g_xz`

역거리 법칙(거리 2배 → 약 -6dB)에 **가장자리 페이드**를 곱해 10m에서 정확히 0이 되게 만든다.
역거리 법칙만 쓰면 10m에서 0이 아니라 0.15쯤 남아 "뚝" 끊기고, 선형 감쇠만 쓰면
가까운 거리에서 크기 변화가 밋밋하다. 둘을 곱해서 해결한다.

```
smoothstep01(t) = t*t*(3 - 2*t)            // t는 [0,1]로 clamp

rolloff(d) = (Dmin / max(d, Dmin))^k
fade(d)    = 1                                                   , d <= Dfade
           = 1 - smoothstep01((d - Dfade) / (Dmax - Dfade))      , Dfade < d < Dmax
           = 0                                                   , d >= Dmax

g_xz = rolloff(d) * fade(d)
```

제안값 `Dmin = 1.5m`, `Dfade = 7.0m`, `Dmax = 10.0m`, `k = 0.9` 기준 결과:

| d | 1.5m 이하 | 3m | 5m | 7m | 8.5m | 9.5m | 10m |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `g_xz` | 1.00 | 0.54 | 0.34 | 0.25 | 0.10 | 0.02 | 0.00 |
| dB | 0 | -5.4 | -9.3 | -12.0 | -20 | -34 | -∞ |

- `Dmin`은 **0 나눗셈 방지 + 얼굴을 맞대도 음량이 폭발하지 않게** 하는 하한이다.
- `k`를 낮추면 중거리가 커지고(수다 떨기 쉬움), 높이면 가까이 붙어야 한다. 밸런스 손잡이는 `k`다.

### 4.2 수직 차단 `g_y` — "층이 다르면 안 들린다" [확정 — VC-5]

**층 인덱스를 쓰지 않는다.** 이유: 현재 코드에 `Floor` 개념이 없고(§2.4), 계단 한가운데 있는
플레이어는 어느 층에도 속하지 않아 판정이 모호해진다. 대신 **수직 거리 자체**로 자른다.

```
g_y = 1                                                      , dy <= Ynear
    = 1 - smoothstep01((dy - Ynear) / (Ycut - Ynear))         , Ynear < dy < Ycut
    = 0                                                      , dy >= Ycut
```

제안값 `Ynear = 1.2m`, `Ycut = 2.6m`.

- `Ycut`은 **반드시 층고보다 작아야** 위/아래 층이 확실히 잘린다. 층고는 현재 `[TEMP] 3.0m`이므로
  **`Ycut = 층고 - 0.4m`** 로 연동한다. [MG-7](../architecture/map-generation.md)에서 층고가 확정되면 같이 갱신한다.
- `Ynear = 1.2m`는 **웅크리기·엎드리기·굴착으로 카메라 높이가 내려가도**(`PlayerMotor.CameraLocalHeight`)
  같은 층 안에서는 감쇠가 걸리지 않게 하는 여유다.

**계단은 예외 처리 없이 자동으로 풀린다.** 층고 `[TEMP] 3.0m` 기준으로 실제 값을 넣어 보면 이렇다.

| 두 사람의 위치 | ΔY | `g_y` | 결과 |
| --- | --- | --- | --- |
| 같은 층, 서서 ↔ 웅크림/엎드림 | 0 ~ 0.8m | 1.00 | 그대로 들린다 |
| **계단 중턱 ↔ 아래층 바닥** | **1.5m** | **0.89** | **들린다** |
| **계단 중턱 ↔ 위층 바닥** | **1.5m** | **0.89** | **들린다** |
| 계단 맨 위 ↔ 계단 맨 아래 | 3.0m | 0.00 | 안 들린다 |
| 1층 ↔ 2층, 수직으로 겹친 위치 | 3.0m | 0.00 | 안 들린다 (VC-D) |

> **0.1 정정.** 0.1은 "계단 중턱에서 아래층과 대화가 끊긴다"고 적었으나 **틀렸다.**
> 계단 중턱에 선 사람의 귀는 아래층 사람보다 딱 **반 층(1.5m)** 높고, 이는 `Ycut` 2.6m **안**이다.
> 끊기는 것은 **온전한 한 층 차이뿐**이며 이것이 곧 VC-D의 요구다. **계단 예외 볼륨은 만들지 않는다.**

**남은 손실은 오픈 보이드 하나뿐이고, 지금은 발생하지 않는다.**
2층 갤러리 홀 난간에서 1층 중앙 홀을 내려다보는 경우 ΔY = 3.0m라 서로 보여도 안 들린다.
그런데 **현재 보이드는 solid floor `[TEMP]`로 막혀 있다**([MG-16 미결](../architecture/map-generation.md)).
즉 보이드를 실제로 뚫기로 결정하기 전까지 이 손실은 존재하지 않는다.

**대신 예외용 훅만 미리 뚫어 둔다.** 나중에 보이드·취기 구멍 같은 수직 연결 공간이 생기면,
두 사람이 같은 연결 공간 안에 있을 때만 수직 컷을 면제한다.

```csharp
// v0.1 구현은 항상 false 를 넘긴다. 수직 연결 볼륨이 생기면 그때 채운다.
float gY = VoiceAttenuation.Vertical(dy, settings, verticalLinkShared: false);
```

층 인덱스(`FloorIndex`) 방식은 **채택하지 않는다.** 맵에 `Floor`가 생기더라도, 계단·보이드처럼
"두 층에 걸친 위치"를 표현하려면 결국 예외 목록이 또 필요해서 \|ΔY\| 컷보다 나을 게 없다.

### 4.3 벽 가림 `g_occ` — 레이캐스트 + 로우패스

**두 단계로 자연스러움을 만든다. 음량만 줄이면 "멀리 있는 소리"가 되고, 고음을 깎아야 "벽 너머 소리"가 된다.**

**① 막힌 정도 측정 — 다중 레이캐스트**

리스너 귀 → 화자 입으로 **3개의 선**을 쏜다. 가운데 1개 + 시선축에 수직인 좌우 `±0.6m` 오프셋 2개.
1개만 쏘면 문틀 모서리 하나에 전체 판정이 튀어 모퉁이에서 소리가 깜빡인다.

```
for each ray r in {center, left, right}:
    n_r = Physics.RaycastNonAlloc(origin_r, dir_r, hits, dist_r,
                                  GameLayers.VoiceOccluderMask,
                                  QueryTriggerInteraction.Ignore) 로 얻은 히트 수
    occ_r = max(OccFloor, WallFactor ^ min(n_r, MaxWalls))

occ_target = (occ_center * 2 + occ_left + occ_right) / 4      // 가운데 레이에 2배 가중
```

제안값 `WallFactor = 0.32`, `MaxWalls = 3`, `OccFloor = 0.04`.

| 가로막은 콜라이더 수 | 0 | 1 | 2 | 3 이상 |
| --- | --- | --- | --- | --- |
| `occ` | 1.00 | 0.32 | 0.10 | 0.04 (하한) |
| dB | 0 | **-10** | -20 | -28 |

벽 한 장에 -10dB는 "확실히 줄었지만 뭐라 하는지는 들린다"(VC-C) 수준이다.

**② 마스크 — 새 레이어를 만들지 않는다 [확정 — VC-6]**

벽·바닥은 `Default` 레이어에 있고, 플레이어는 `Player`, 가구는 `Furniture`, 귀신은 `GhostPrototype`으로
이미 분리돼 있다. 따라서 **제외 마스크**로 충분하고 `ProjectSettings` 변경(사용자 승인 필요 항목)이 필요 없다.

```csharp
// GameLayers 에 추가 — 기존 NonGhostPrototypeRaycastMask 와 같은 방식
VoiceOccluderMask = Physics.DefaultRaycastLayers
                    & ~PlayerMask & ~GhostPrototypeMask & ~FurnitureMask;
```

- **가구를 오클루더에서 뺀다 [확정]** — 움직이는 `Rigidbody`가 시야를 스칠 때마다 음량이 깜빡이고,
  실제로 소파 한 개가 목소리를 -10dB 깎지도 않는다. 던지기 게임이라 가구가 늘 날아다닌다는 점이 결정적이다.
- **`ProjectSettings/TagManager.asset`을 건드리지 않는다** — 레이어 신설은 사용자 확인 대상(CLAUDE.md §3.3·§9)인데,
  제외 마스크로 같은 결과가 나오므로 그 승인 자체가 필요 없다.
- **문은 자동으로 처리된다.** 열린 문짝은 콜라이더째 개구부 밖으로 회전하므로 레이가 그냥 통과한다.
  별도 분기가 필요 없다. 다만 문틀·프레임이 개구부를 덮고 있지 않은지 첫 구현에서 확인한다(AC-7).

**③ 로우패스 — 먹먹함**

```
t_occ  = 1 - occ_target                                  // 0 = 트임, 1 = 완전히 막힘
cutoff_target = lerp(CutoffOpen, CutoffBlocked, t_occ)   // 22000Hz → 750Hz
```

`AudioLowPassFilter`를 음성 `AudioSource`에 붙이고 `cutoffFrequency`를 이 값으로 민다.

**④ 갱신 주기**

레이캐스트는 **10Hz(0.1초)**, 화자별로 프레임을 **분산(stagger)** 해서 같은 프레임에 몰리지 않게 한다.
최대 3명 × 3레이 × 10Hz = **초당 90회** — 귀신 시야 판정보다 가볍다. 사이 프레임은 §4.4 평활이 메운다.

### 4.4 시간 평활 (필수)

거리·가림 값을 그대로 쓰면 코너를 돌 때 지퍼 노이즈와 "툭" 끊김이 난다. **모든 최종 값은 지수 평활**을 거친다.

```
x ← x + (x_target - x) * (1 - exp(-Δt / τ))
```

제안값 `τ_gain = 0.12s`, `τ_cutoff = 0.18s`. (`exp` 형태를 쓰는 이유: 프레임레이트가 달라도
같은 시간 상수를 유지한다. `Lerp(x, target, 0.1f)`는 프레임레이트에 따라 속도가 변한다.)

### 4.5 최종 음량

```
volume = g_xz * g_y * g_occ_smoothed * MasterVoiceVolume * PerPlayerVolume
if (volume < 0.001) → AudioSource 정지 (CPU 절약)
```

## 5. 캡처 · 전송 · 재생

### 5.1 캡처와 코덱 [확정: Steam Voice — VC-1]

| 안 | 내용 | 장점 | 단점 |
| --- | --- | --- | --- |
| **A. Steam Voice (권장)** | `SteamUser.VoiceRecord` + `ReadVoiceData(Stream)`로 **이미 압축된** 프레임을 받고, 듣는 쪽에서 `DecompressVoice`로 PCM 복원 | 번들된 Facepunch 2.5.2에 포함 — **패키지 추가 없음**. 코덱·노이즈 억제·장치 관리를 Steam이 처리. 초당 1.6~8KB로 매우 저렴 | Steam 클라이언트 필수. **입력 장치 선택이 게임 안에 없다**(Steam 설정을 따름). `Steamworks` 참조는 `Systems/Steam`에만 허용(하드 룰) → §6 추상화 필요 |
| B. Unity `Microphone` + 별도 코덱 | `Microphone.Start` → PCM → Opus(Concentus 등) 인코딩 | Steam 비의존, 장치 선택 자유 | **패키지 추가 = 사용자 승인 필요(§9)**. 순수 C# Opus는 CPU를 먹고, 무압축 PCM은 24kHz 16bit 기준 **48KB/s**로 호스트 업로드를 태운다 |

**A로 확정됐다(VC-1).** 결정적 이유 하나 더 — 로컬 개발 경로(`TransportMode.Local`, UTP)에서도
**Steam 클라이언트는 어차피 켜져 있다**(에디터 플레이 조건, [steam.md](../architecture/steam.md)).
즉 **캡처·코덱은 Steam, 전송은 NGO**로 나누면 Local 2인 테스트에서도 음성이 그대로 동작한다.
Steam P2P 채널로 음성을 보내면 이 경로가 깨진다.

**확정과 함께 받아들이는 제약 3가지**

1. **게임 안에 입력 장치 선택이 없다.** 마이크 장치·입력 볼륨은 Steam 설정(친구 → 음성)을 따른다.
   게임 옵션에는 **"Steam 음성 설정 열기" 버튼**만 두는 것을 제안한다(VC-11).
2. **Steam이 없으면 음성이 없다.** Local 모드로 개발할 때도 Steam 클라이언트가 꺼져 있으면 음성은 비활성이다
   → 그래서 개발용 가짜 마이크(VC-18)가 선택이 아니라 **필수**다.
3. **macOS 폐기 API 주의.** Facepunch 2.5.2 맥 번들은 Valve가 폐기한 API 49개가 빠져 있다(CLAUDE.md §4).
   음성 경로에서 쓰는 `VoiceRecord`·`ReadVoiceData`·`DecompressVoice`·`SampleRate`가 그 목록에 없는지
   **Mac 실기에서 먼저 확인한다.** 빠져 있으면 맥에서만 `EntryPointNotFoundException`이 난다 → AC-15.

### 5.2 패킷 규격 [제안]

```
송신 20Hz (50ms마다 1패킷) · 페이로드 상한 512B · 초과 시 드롭
```

- NGO 신뢰 전송은 재전송 때문에 늦은 음성 패킷을 되살린다 — **쓸모없는 지연**이다.
  → **`RpcDelivery.Unreliable`** 을 쓴다. 단 MTU(약 1200B) 안에 들어가야 한다.
- 매 프레임 RPC 금지 규칙([networking.md §3.2](../architecture/networking.md))의 예외가 아니다 —
  프레임이 아니라 **고정 20Hz**이고, 서버 컬링으로 수신자를 줄인다. 이 근거를 코드 주석에 남긴다.
- **화자 식별자를 패킷에 넣지 않는다.** 음성 컴포넌트를 플레이어 프리팹의 `NetworkBehaviour`로 두면
  `NetworkObject`가 곧 화자다. 위조 여지가 줄고 페이로드도 아낀다.
- `byte[]`는 관례상 금지(§3.2)이자 매초 GC 쓰레기가 된다. **`NativeArray<byte>`(Allocator.Temp)** 를 쓴다.

```csharp
// Gameplay/Voice/PlayerVoiceEmitter.cs (설계 스케치 — 구현 시 확정)
[Rpc(SendTo.Server, InvokePermission = RpcInvokePermission.Owner, Delivery = RpcDelivery.Unreliable)]
private void SubmitVoiceRpc(NativeArray<byte> frame, RpcParams p = default) { /* §5.3 */ }

[Rpc(SendTo.SpecifiedInParams, Delivery = RpcDelivery.Unreliable)]
private void PlayVoiceRpc(NativeArray<byte> frame, RpcParams p) { /* §5.4 */ }
```

### 5.3 서버의 역할 — 중계와 컬링

**서버는 음성을 해독하지 않는다.** 압축된 바이트를 그대로 넘긴다(호스트 CPU 절약).
서버가 하는 일은 셋이다.

1. **검증** — 길이 상한, **전송률 상한(30패킷/초 초과 시 드롭)**, 화자 생존·정책(§7) 확인.
   클라이언트가 보낸 값을 그대로 믿지 않는다([networking.md §1.3](../architecture/networking.md)).
2. **컬링** — 서버가 가진 위치로 **들을 자격이 있는 클라이언트만** 골라 `RpcTarget.Group`으로 보낸다.
   ```
   audible(listener) = dXZ <= Dmax + ServerCullMarginXZ  &&  dy <= Ycut + ServerCullMarginY
   ```
   **여유(margin)를 두는 이유**: 컬링을 정확히 10m에서 하면 페이드가 끝나기 전에 패킷이 끊겨 "툭" 소리가 난다.
   12m까지 보내 두고 **실제 0은 클라이언트의 §4.1이 만든다.**
   컬링에 **가림(벽)은 넣지 않는다** — 서버가 화자×청자마다 레이캐스트를 돌리면 호스트가 부담을 다 진다.
3. **자기 자신 제외** — 화자에게 자기 목소리를 되돌려보내지 않는다.

> **치팅 범위** — 컬링이 12m이므로, 변조된 클라이언트는 **12m 이내에서 벽을 무시하고 들을 수 있다.**
> 완전 차단은 서버가 프레임별로 디코드·믹싱해야 가능한데(호스트 리슨 서버에는 과하다), 이미
> 호스트 치팅을 감수한 구조([ADR-0001](../architecture/decisions/ADR-0001-steam-p2p-facepunch-transport.md))와
> 같은 수준의 비용으로 본다. 승인 필요 → VC-13.

### 5.4 재생 — 지터 버퍼 [제안]

```
수신 패킷 → DecompressVoice → PCM(16bit mono) → 링 버퍼 → AudioClip(stream) PCMReaderCallback → AudioSource
```

- 네트워크 패킷은 균등하게 도착하지 않는다(SDR 릴레이 경유, [networking.md §4](../architecture/networking.md)).
  **지터 버퍼 목표 80ms**(최소 40 / 최대 200). 초과분은 오래된 것부터 버리고, 부족하면 무음을 채운다.
- `PCMReaderCallback`은 **오디오 스레드**에서 돈다. 링 버퍼는 락 없이 읽고 쓸 수 있어야 하고,
  콜백 안에서 Unity API를 부르지 않는다. 여기서 실수하면 **소리가 아니라 에디터가 멈춘다.**
- **말이 끊긴 뒤** 200ms 동안 패킷이 없으면 `AudioSource.Stop()` + 버퍼 비움.

### 5.5 대역폭 예산 (4인 기준)

패킷당 페이로드 평균 120B + 오버헤드 약 40B = 160B, 20Hz → **화자 1명당 약 3.2 KB/s**.

| 경로 | 최악(4인 전원이 동시에 말하고 전원이 서로 가청) |
| --- | --- |
| 게스트 업로드 | 3.2 KB/s |
| 게스트 다운로드 | 9.6 KB/s |
| **호스트 업로드** | 자기 음성 3명분(9.6) + 게스트 3명 음성 중계(3명 × 2명 = 6스트림 = 19.2) ≈ **29 KB/s (232 kbps)** |

가구 물리 `NetworkTransform` 트래픽과 **합산**된다. 호스트는 가정용 회선이다
([networking.md §4](../architecture/networking.md)). 컬링이 걸리면 실제 값은 이보다 훨씬 낮다.
**Network Profiler로 실측한 뒤 20Hz를 유지할지 결정한다** → VC-14.

## 8. 입력 — 말하는 방법 [확정: 둘 다 구현, 기본 오픈 마이크 — VC-3]

| 모드 | 동작 | 기본값 |
| --- | --- | --- |
| **오픈 마이크(VAD)** | 음성이 감지되면 자동 송신. 손을 안 쓰므로 가구를 함께 나르면서 말할 수 있다 | **기본** |
| 푸시 투 토크 | `V`를 누르고 있는 동안만 송신 | 설정에서 전환 |
| 마이크 끄기 | `M` 토글 — **캡처 자체를 정지**한다(확실한 오프) | 켜짐 |

입력은 `Player/Voice`(`<Keyboard>/v`)와 `Player/VoiceMute`(`<Keyboard>/m`) 액션을 신설한다.

> **기본값이 오픈 마이크라서 VAD 품질이 곧 체감 품질이 된다.** PTT는 사람이 게이트 역할을 하지만,
> 오픈 마이크는 코드가 그 판단을 대신한다. 단순 임계값 하나로 자르면 **말끝이 잘리고
> 키보드 소리마다 열린다.** 그래서 §8.1이 필요하다.

### 8.1 VAD — 음성 감지 게이트 [제안] → VC-21

**이력(hysteresis) + 행오버 + 선행 버퍼**, 세 가지를 같이 쓴다.

```
20ms 프레임마다:
    rms  = sqrt(mean(sample^2))
    dBFS = 20 * log10(max(rms, 1e-6))

    닫힘 상태: dBFS > OpenThreshold        → 연다
    열림 상태: dBFS < CloseThreshold 가 HangoverMs 동안 이어지면 → 닫는다
```

제안값 `OpenThreshold = -42 dBFS`, `CloseThreshold = -48 dBFS`, `HangoverMs = 350`, `PreRollMs = 150`.

| 장치 | 무엇을 막는가 |
| --- | --- |
| **6dB 이력**(열림 -42 / 닫힘 -48) | 임계선 근처에서 게이트가 초당 수십 번 떨리는 것(chattering) |
| **행오버 350ms** | 문장 중간의 숨·쉼에 게이트가 닫혀 **말끝이 뚝 잘리는 것** |
| **선행 버퍼 150ms** | 게이트가 열리기 직전의 오디오를 함께 보낸다. 없으면 **첫 음절이 날아간다** |

- 임계값은 마이크·환경마다 다르므로 **설정에서 조절 가능해야 한다**(VC-11).
- 게이트 판정은 **로컬에서만** 한다. 닫혀 있는 동안의 오디오는 네트워크로 나가지 않는다.

### 8.2 캡처는 계속 돌리고, 송신만 게이트한다

`SteamUser.VoiceRecord`를 말할 때마다 켜고 끄면 **장치 기동 지연(수십~100ms)이 첫 음절을 먹는다.**
그래서 음성 기능이 켜져 있는 동안 **녹음은 계속 돌리고**, VAD/PTT는 "서버로 보낼지"만 정한다.

- 게이트가 닫혀 있으면 프레임은 **로컬에서 버려진다.** 네트워크로 나가지 않는다.
- **확실히 끄고 싶을 때는 `M`** — 이때는 `VoiceRecord` 자체를 정지해 마이크를 놓는다.
  오픈 마이크가 기본값이므로 **이 키가 눈에 띄어야 한다**(HUD 상시 표시, VC-11).

### 8.3 입력 잠금 관계

기존 3중 잠금(메뉴 > 굴착 > 휠, [player-controller.md](../architecture/player-controller.md))에
음성을 **넣지 않는다.** 말하기는 어떤 상태에서도 막히지 않아야 한다(§7).
퀵슬롯 휠이 열린 동안에도, 굴착 중에도, ESC 메뉴 중에도 말할 수 있다.

## 10. 검증

### 10.1 수용 기준 (AC)

| # | 상황 | 기대 동작 |
| --- | --- | --- |
| AC-1 | 같은 방, 가림 없음, 2m | 또렷하게 들린다. 방향(좌/우)이 구분된다 |
| AC-2 | 같은 층, 일직선, 9m → 11m로 걸어서 이동 | 점점 작아지다 **끊김 없이** 0이 된다. "툭" 소리 없음 |
| AC-3 | 같은 방 12m (Dmax 초과) | 들리지 않는다 |
| AC-4 | 벽 하나를 사이에 두고 3m | 들리되 **확실히 작고 먹먹하다**(약 -10dB + 로우패스) |
| AC-5 | 벽 3장 너머 5m | 거의 들리지 않는다(하한 0.04) |
| AC-6 | 벽 뒤에서 문간으로 걸어 나옴 | 음량·먹먹함이 **부드럽게** 트인다. 깜빡임 없음 |
| AC-7 | 문이 열린 상태로 문틀을 통과해 대화 | 가림이 걸리지 않는다(레이가 개구부를 통과) |
| AC-8 | 1층 ↔ 2층, 수직으로 겹친 위치 | 들리지 않는다 (VC-D) |
| AC-9 | 계단 중턱 ↔ 아래층 바닥 | **들린다**(ΔY 1.5m → `g_y` 0.89). 0.1의 "끊긴다"는 서술은 오류였다 → §4.2 |
| AC-10 | 4인 동시 발화 | 음성이 밀려 끊기지 않는다. Network Profiler로 대역폭 실측 |
| AC-11 | 화자가 사망 | 생존자에게 즉시 끊기고, 다른 사망자에게는 계속 들린다 (§7) |
| AC-12 | 화자가 접속 종료 | 재생이 정지하고 버퍼·`AudioSource`가 정리된다(`OnNetworkDespawn`) |
| AC-13 | Steam 미실행 상태로 Local Host 실행 | 음성만 비활성, 나머지 게임은 정상 |
| AC-14 | 변조 클라이언트가 초당 200패킷 전송 | 서버가 30/s 초과분을 드롭하고 로그를 남긴다 |
| AC-15 | **macOS에서 음성 송수신** | `EntryPointNotFoundException` 없이 동작한다. 폐기 API 49개에 음성 API가 포함되지 않았음을 실기로 확인 (§5.1) |
| AC-16 | **오픈 마이크로 한 문장 말하기** | 첫 음절이 잘리지 않고(선행 버퍼), 문장 중간 숨에 끊기지 않으며(행오버), 말이 끝나면 350ms 안에 닫힌다 |
| AC-17 | 오픈 마이크 상태로 키보드 타자·마우스 클릭만 | 게이트가 열리지 않는다(-42dBFS 미만). 열린다면 임계값을 조정한다 → VC-21 |
| AC-18 | `M`으로 마이크 끄기 | 캡처가 정지하고 HUD에 꺼짐이 표시된다. 다시 켜면 1초 안에 송신이 재개된다 |

### 10.2 테스트 전략

| 층 | 방법 |
| --- | --- |
| EditMode | **`VoiceAttenuation` 순수 함수**(§4.1·4.2·4.3 합성, 경계값 0/Dmax/Ycut), 지터 버퍼 오버런·언더런, 컬링 판정 |
| PlayMode | `NetworkManager` 코드 구동 + **가짜 캡처 소스**로 프레임 왕복, 컬링으로 수신자가 정확한지 |
| 수동 | Local 2프로세스 → Steam 2PC |

> **여기에 실질적 장애물이 있다** → VC-18.
> ① **한 PC에서 두 인스턴스가 같은 마이크를 잡을 수 없다.** 두 번째 캡처가 실패하거나 하울링이 난다.
> ② 자동화 테스트는 Steam에 의존하면 안 된다([networking.md §6](../architecture/networking.md)).
> **대책: `IVoiceCaptureService`의 개발용 구현체**(사인파 또는 WAV 루프백)를 F1 HUD로 켠다.
> 마이크 없이 혼자서 감쇠·가림·컬링을 전부 검증할 수 있고, CI에서도 돈다. **이것을 먼저 만든다.**
