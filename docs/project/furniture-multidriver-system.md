## 2. 개요

### 2.1 문서 개요

- 게임 내 스테이지에서 플레이어가 사용하는 아이템인 **가구용 멀티 드라이버**의 정의와 기본 규칙을 설명한다.
- 아이템의 사용 조건, 가구 분해·조립의 조건, 사용 시 행동과 가구 변화, 운반 후 조립 조건을 정의한다.
- 아이템의 외형과 사용 연출, 가구 분해·조립 연출을 설명한다.
- 원문의 기획 의도 표시(초록색)는 저장소 반영 시 `> **기획 의도:**` 블록으로 바꿨다.

### 2.2 시스템 개요

- 가구용 멀티 드라이버는 **튜토리얼 스테이지 이후 자동으로 해금**되며, 스테이지 내에서 **생존 중인 모든 플레이어**가 획득·사용할 수 있다.
- 기능은 두 가지다.
  - **가구 분해** — 분해 가능한 가구에 포인터를 맞추고 우클릭을 **누르고 있으면** 3초간 행동이 진행되며 가구를 분해한다.
  - **가구 조립** — 조립 영역 안에 올바른 가구를 모두 위치시킨 뒤 우클릭을 **누르고 있으면** 3초간 행동이 진행되며 가구를 조립한다.
- **재사용 대기시간은 없다.**
- **1회 사용마다 내구도가 감소**하며, 내구도 ≤ 15가 되면 행동 시간이 9초로 늘어난다. 수리로 내구도를 회복한다.

### 2.3 기획 의도

> **기획 의도**
> - 문이나 복도의 간격보다 큰 가구를 어색함 없는 방법으로 옮길 수 있게 한다.
> - 아이템 내구도 관리를 통해 스테이지 시작 전 장비 상태를 점검하고 수리 여부를 판단하는 장비 관리 요소를 제공한다.
> - 분해·조립에 일정 시간이 걸리게 해서, 귀신의 위협이 없는 시점을 고르거나 다른 플레이어의 보호를 받으며 작업하도록 유도한다.

## 3. 아이템 규격

### 3.1 사용 조건 [확정]

아래 조건을 **모두** 충족해야 사용할 수 있다.

1. 플레이어가 가구용 멀티 드라이버를 **손에 장착한 상태**로 가구에 우클릭할 때
2. 우클릭한 가구가 **분해 또는 조립이 가능한 가구**일 때

### 3.2 행동 시간과 중단 [확정]

아이템은 사용 시 플레이어가 해당 가구에 매달리는 **행동 시간**을 가진다.

| 사용 시작 시점의 내구도 | 행동 시간 |
| --- | --- |
| > 15 | **3초** |
| ≤ 15 | **9초** |

- 행동 시간 판정은 **아이템 사용을 시작한 시점의 내구도 값**으로 한다(행동 중 내구도가 바뀌어도 이미 시작한 행동의 길이는 변하지 않는다).
- **우클릭을 행동 시간이 끝날 때까지 누르고 있어야** 행동이 완료된다(1.1 수정, 2026-09-13).
  한 번 눌렀다 떼는 것만으로는 진행되지 않는다.
- 행동 시간 도중 아래 중 하나가 일어나면 **즉시 중단되고 처음부터 다시** 사용해야 한다.
  1. 플레이어가 **이동**하거나 **스킬을 사용**함
  2. 플레이어가 **귀신에게 공격당함**
  3. 플레이어가 **우클릭을 뗌** (1.1 추가)

### 3.3 아이템 내구도 [확정]

- 내구도는 아이템의 상태를 뜻하는 수치로 **100~0 사이의 정수**이며 **%** 로 표시한다.
- **1회 사용마다 5 감소**한다.
  - **사용을 성공적으로 완료한 경우에만** 감소한다(중단되면 감소하지 않는다).
  - 감소 타이밍은 **사용 완료 이후**다.
  - 내구도가 0이면 더 이상 감소하지 않는다.
- 내구도는 스테이지 시작 전 **상점에서 돈을 지불해 수리**한다.
  - 상점 UI와 수리 가격은 이 문서의 범위가 아니다 → **MD-4**.

## 4. 기능

### 4.1 가구 분해 [확정]

- 가구 분해는 **큰 가구 1개를 작은 가구 여러 개로 변환**하는 기능이다.
- 분해 가능한 큰 가구에 아이템을 사용해 실행한다.
- 분해에 성공하면 **큰 가구는 스테이지에서 삭제되고 작은 가구 여러 개가 생성**된다.
- 이렇게 생성된 작은 가구는 **조립 과정을 거치지 않으면 어떤 방법으로도 짐칸에 보관할 수 없다.**

### 4.2 가구 조립 [확정]

- 가구 조립은 **작은 가구 여러 개를 큰 가구 1개로 변환**하는 기능이다.
- 드릴 카 앞에 위치한 **조립 영역**에 작은 가구를 모두 올바르게 위치시킨 뒤, 나타나는 **큰 가구의 실루엣에 아이템을 사용**해 실행한다.
- 조립에 성공하면 **작은 가구들은 전부 삭제되고 큰 가구가 생성**된다.

#### 4.2.1 조립 영역 점유 판정

작은 가구가 조립 영역 안에 있다고 인정하려면 **두 조건을 모두** 만족해야 한다.

1. 작은 가구가 **조립 영역 안에 위치**할 것
2. 작은 가구가 **바닥에 놓인 상태**일 것

조립 도중 아래 중 하나가 일어나면 **즉시 조립이 취소**된다.

1. 가구가 영역 밖으로 나감
2. 가구가 플레이어에게 잡힘
3. **다른 가구가 조립 영역 안에 들어옴**

### 4.3 조립 성립 규칙 [확정]

**규칙 1 — 다른 큰 가구의 부품이 섞이면 조립할 수 없다.**

조립 영역 안에 서로 다른 큰 가구를 분해해서 나온 작은 가구들이 함께 있으면, 특정 큰 가구를 구성하는
부품이 모두 있더라도 조립할 수 없다.

- 예: 더블 침대 분해 부품 `[A, B, C]`, 옷장 분해 부품 `[X, Y, Z]`
  → A·B·C가 모두 있어도 X가 함께 있으면 더블 침대를 조립할 수 **없다**(실루엣이 붉은색).
- **부품 개수가 초과**되어도 마찬가지로 조립할 수 없다(예: C가 2개).

![조립 성립·불성립 판정](../images/furniture-multidriver-assembly-rules.jpg)

**규칙 2 — 같은 종류의 큰 가구에서 나온 부품은 서로 구분하지 않는다.**

하나의 스테이지에 동일한 큰 가구가 여러 개 있을 때, 같은 종류의 큰 가구를 분해해서 나온 작은 가구는
**모두 동일한 것으로 판단**한다.

- 예: `더블 침대A`와 `더블 침대B`를 각각 분해해 나온 매트리스는 `매트리스A`/`매트리스B`로 구분하지 않고
  동일한 `매트리스`로 본다.
  → 더블 침대A에서 나온 매트리스·침대 헤드 + 더블 침대B에서 나온 침대 다리로 더블 침대 1개를 조립할 수 있다.

![같은 종류 부품의 호환](../images/furniture-multidriver-part-interchange.jpg)

## 5. 가구의 내구도 처리 [확정]

가구를 분해·조립할 때 **가구의** 내구도 값을 처리하는 방법이다(아이템 내구도 §3.3과 별개다).

| 상황 | 처리 | 예시 |
| --- | --- | --- |
| 가구 분해 시 | 큰 가구의 내구도 값을 **모든 작은 가구가 동일하게** 가진다 | 내구도 60인 큰 가구를 3개로 분해 → 각 부품의 내구도는 모두 60 |
| 분해 상태에서 작은 가구가 손상됨 | **손상된 가구의 내구도만** 감소 | — |
| 가구 조립 시 | 조립에 사용된 작은 가구들의 내구도 **평균값** | 60·60·30 → 완성 가구는 50 (소수점 이하 표시하지 않음) |

> **이관(2026-09-15):** 가구 내구도가 **언제 얼마나** 깎이는지(충돌 속도 비례), 0이 되면 어떻게 되는지는
> [가구 내구도 시스템 기획서](furniture-durability-system.md)가 권위다. 위 표의 "손상됨"은 그 문서 §3.3~§3.4의 충돌 감소를 뜻한다 → MD-6.
>
> **갱신(2026-09-16):** 내구도가 0이 되어도 **가구는 사라지지 않는다**(FD-10 재확정). 따라서
> 내구도 0인 부품도 그대로 조립에 쓰이고, **완성 가구의 내구도는 0을 포함한 평균**이다 —
> 0·0·30이면 완성품은 10, 전부 0이면 0이다. 위 표의 평균 규칙은 그대로이고 "0인 부품은 이미
> 사라져서 결과가 1 이상"이라는 전제만 없어졌다.

## 6. 연출

### 6.1 행동 시간 UI [확정 — 1.1 수정 2026-09-13]

- 아이템을 사용해 행동을 수행하는 동안 **행동 진행도**를 표시한다.
- 화면 **중앙(조준점 주위)**에 **원형 게이지**가 팝업된다. 우클릭을 누르고 있는 동안 게이지가
  12시 방향부터 시계 방향으로 일정하게 채워지고, 행동 시간이 끝나면 한 바퀴가 다 찬다.
  - 게이지 아래에 진행 중인 행동을 표시한다 — **"분해 중"** / **"조립 중"**.
- 행동이 완료되면 UI가 사라진다.
- 행동이 중단되면(§3.2 — 우클릭을 뗌 포함) 게이지 채움이 그 자리에서 멈추고, UI가 **좌우로 두 번
  흔들리며** 문구를 출력한 뒤 사라진다.
  - 분해를 시도했다면 **"분해 실패"**, 조립을 시도했다면 **"조립 실패"**.
- 1.0의 "중앙 하단 로딩바가 감소"(레퍼런스: 월드 오브 워크래프트 `행동 시전` 바)는 1.1에서 이
  원형 게이지로 대체했다.

### 6.2 가구 분해 연출 [확정]

**플레이어 애니메이션** — 드라이버를 가구 방향으로 향하게 잡고 **손목을 돌리는 애니메이션을 행동 시간 종료까지 반복**한다.

**가구 연출**

1. 행동이 완료되면 기존 큰 가구가 사라진다.
2. 그 자리에 분해된 작은 가구들이 **공중 1m에서 생성되어 바닥으로 떨어진다.**

### 6.3 가구 조립 연출 [확정]

**플레이어 애니메이션** — §6.2와 동일하다.

**가구 연출**

1. 행동이 완료되면 기존 작은 가구들이 사라진다.
2. **조립 영역 중앙**에 큰 가구가 **공중 1m에서 생성되어 바닥으로 떨어진다.**

### 6.4 조립 영역 실루엣 [확정]

1. 조립 영역에 작은 가구를 두면, 영역 가운데에 **그 부품의 원형이었던 큰 가구의 실루엣**이 표시된다.
   - 예: 매트리스·침대 헤드·침대 다리 중 하나만 두어도 더블 침대 실루엣이 뜬다.
   - 이때 실루엣은 **흰색 `#FFFFFF`, 투명도 50**.
2. 올바른 부품을 모두 위치시키면 실루엣이 **초록색 `#78C664`** 로 변한다(투명도 유지).
3. 실루엣이 초록색인 상태에서 실루엣에 포인터를 맞추고 우클릭을 누르고 있으면 조립이 진행된다(§3.2).

**예외** — 조립 영역에 서로 다른 큰 가구의 부품이 섞였거나 부품 개수가 초과되면(§4.3 규칙 1)
실루엣을 **붉은색 `#D66565`** 로 표시한다(투명도 유지).

| 실루엣 색 | 의미 |
| --- | --- |
| 흰색 `#FFFFFF` (투명도 50) | 부품이 일부만 놓임 — 아직 조립 불가 |
| 초록색 `#78C664` | 조립 가능 — 우클릭을 누르고 있으면 조립 실행 |
| 붉은색 `#D66565` | 다른 가구 혼입 또는 부품 개수 초과 — 조립 불가 |

## 7. 기존 시스템과의 관계 (2026-09-12 구현 반영 갱신)

| 항목 | 구현 상태 |
| --- | --- |
| 아이템 장착 | **완료.** 퀵슬롯 1번 슬롯에 드라이버 배정(`QuickSlotItemDefinition.IsDriver`), `PlayerCleaningController`(대걸레)와 동일한 EquipSlot → RequestEquipRpc → ConfirmEquipRpc 경로 재사용 → **MD-5 확정** |
| 우클릭 입력 | **완료.** `Player` 맵에 `UseDriver` 액션 신설(마우스 우클릭). 사망 중에만 도는 `SpectateNext`와 별개 액션이라 충돌하지 않는다. **1.1(2026-09-13):** 누른 순간 행동을 시작하고, 누르고 있는 상태(`UseDriverHeld`)가 행동 시간 끝까지 유지돼야 완료된다 |
| 행동 중단 | **완료.** 굴착과 반대로 **취소 판정**(잠금 아님) — 매 프레임 이동 입력·**우클릭 뗌**·스킬 입력·생존 상태를 확인해 취소한다 → **MD-11 확정**(이동 입력 ≠ 0만 트리거, 시점 회전·웅크리기·점프 미포함) |
| 행동 시간 UI | **완료(2026-09-13, 1.1).** `FurnitureDriverActionHud` — 화면 중앙 원형 게이지·"분해 중/조립 중"·중단 시 멈춤+좌우 2회 흔들림+"분해 실패/조립 실패". 수치·색·문구는 `FurnitureDriverUiSettings_Default` |
| 귀신 공격 취소 | **완료(단순화).** 이 프로토타입은 공격 성립 = 즉시 사망(`GhostPrototypeController.TryCatch` → `SanityNetworkState.ServerMarkDead`)이라, 별도 이벤트 없이 매 틱 생존 게이팅이 곧 취소 조건이다 → **MD-12 확정**("어택 성립 시점") |
| 가구 잡기·던지기 | **완료.** 분해 부품·재조립 대상 큰 가구 모두 기존 `FurnitureGrabTarget`·`FurnitureNetworkPhysics`·`FurnitureLauncher`·`FurnitureOutline`을 그대로 붙여 기존 가구와 완전히 동일하게 취급한다 → **MD-10 확정** |
| 런타임 스폰 여부 | **ADR-0009 준수, 새 ADR 불필요.** `RandomFurnitureItem`(청소·랜덤 가구)과 같은 "씬 배치 풀 + 서버 활성/비활성 토글" 패턴(`FurnitureDriverPoolItem`)을 그대로 따른다 — `NetworkObject.Spawn`을 쓰지 않는다 |
| 조립 영역 | **완료(임시).** 기존 `DrillCarSafeZone_Temp` 자리에 트리거 좌표만 재사용 → **MD-2 확정**. 정식 드릴 카가 생기면 위치·크기를 다시 잡는다 |
| 짐칸·반출 | 범위 밖 유지 — **MD-3 그대로 TBD**(MG-22 대기) |
| 작업 대상 가구 | **완료.** 분해 가능 6종·부품 구성 확정 → **MD-1 확정**(§8 표). 다만 식탁·선반 2종은 현재 라이브 `House_01/PhysicsFurniture`가 비어 있어 실제 분해 대상이 없다(레벨 배치 대기) |
| 네트워크 권위 | **완료.** 분해·조립 실행은 서버 RPC 완료 시점에만 일어나고, 매번 최신 상태를 다시 확인한다(동시 시도는 재검증으로 자연히 거절됨) → **MD-9 확정**(별도 락 불필요, §8 참고) |

| MD-5 | 아이템 획득·장착 경로 | **확정(2026-09-12).** 퀵슬롯 1번 슬롯 전용(대걸레와 동일 패턴) |
