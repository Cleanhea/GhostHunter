# 사망 후 관전 시스템 기획서

> 작성일: 2026-09-12. 근거: 사용자의 사망 후 특수능력 제한·자유시점·플레이어 관전 요청.
> **핵심 요구 확정 + SP-1~SP-4 조작·전환 정책 확정(2026-09-12) / 코드 구현 완료, Host/Client Play 검증 대기.**
> 이 문서는 사망 이후 관전 규칙의 SSOT다. 기존 사망 판정과 정신력 규칙은 각 시스템 문서를 따른다.

## 1. 목적과 범위

사망한 플레이어는 특수능력을 사용할 수 없으며, 아래 두 관전 모드로 진행 중인 게임을 볼 수 있다.

| 모드 | 확정된 동작 |
| --- | --- |
| **자유시점** | 맵의 벽·바닥·천장·문·가구를 통과하며 전후·좌우·상하 모든 방향으로 자유롭게 이동하고 시점을 회전한다. 충돌이나 중력 때문에 이동이 막히거나 떨어지지 않는다 |
| **플레이어 관전** | 특정 키 입력으로 생존 플레이어의 1인칭 시점으로 이동해 그 플레이어의 위치와 보는 방향을 따라간다. 단순히 해당 위치로 한 번 이동하는 기능이 아니다 |

사망자에게 두 모드 사이의 전환 수단을 제공한다. 플레이어 관전 대상은 **접속 중이며 스폰된 생존 플레이어**다.
자기 자신·다른 사망자·연결 종료 또는 디스폰된 플레이어는 대상이 아니다.
게임플레이 관전이며, 생존자의 캐릭터를 대신 조작하는 기능은 포함하지 않는다.

## 2. 사망과 다른 시스템의 관계

- **사망 중 특수능력 사용 불가**는 두 모드에 공통으로 적용한다. 현재 탐지(Q)·굴착(T)을 포함한다.
- 사망 판정은 기존 서버의 `SanityNetworkState.ServerMarkDead()`를 유지한다.
  `HasSanity`는 현재 코드에서 생존 여부를 뜻한다. 정신력이 **0이어도 살아 있을 수 있으므로** 수치 0을 사망으로 해석하지 않는다.
- 사망자의 정신력 UI `-%`, 팀 평균 제외, 정신력 디버프 종료는 [정신력 기획서](sanity-system.md)를 따른다.
- 한 명이 사망해도 귀신 어택은 계속된다 → [귀신 기획서 §11.2](ghost-system.md#112-플레이어-사망-확정).
- 퀵슬롯은 기존 [퀵슬롯 기획서 §4](quick-slot-system.md#4-동작-규격-구현-범위)에서도 생존자만 열도록 정의됐다.
  사망 시 열려 있던 휠은 선택을 확정하지 않고 닫아야 한다. **현재 코드에는 이 생존 검사가 빠져 있다.**
- 사망 후에도 ESC 메뉴를 열 수 있다. 메뉴가 열리면 관전 이동·시점 조작·모드/대상 전환 입력도 잠근다.
  게임 시간은 계속 흐른다 → [일시정지 기획서](pause-menu-system.md). 메뉴 중 사망해도 메뉴를 강제로 닫지 않는다.
- 진행 중인 스킬 취소, 가구 홀드 해제, 일반 상호작용의 상세 차단 범위는 §5 SP-2에서 확인한다.

이번 요청은 관전 기능이다. 시체 오브젝트 생성·시체 목격 연결·부활 메커니즘·전원 사망 시 승패 판정·
결과 씬 전환·음성 채팅 규칙은 새로 결정하거나 구현하지 않는다. 특히 **생존 관전 대상 0명**과
**패배 확정**은 별개다. 승패는 [GDD §2](gdd.md#2-승리--패배-조건)의 TBD로 남긴다.

## 3. 구현 시 지켜야 할 경계

아래는 확정 요구를 구현할 때 필요한 제약이다. 실제 컴포넌트 설계·배선은 구현 작업에서 기록한다.

1. 관전 카메라는 사망한 캐릭터의 네트워크 위치와 분리한다. 자유비행이나 대상 전환으로 플레이어
   루트·콜라이더를 이동시키거나, 관전 위치가 상호작용·귀신 탐지용 플레이어 위치가 되어서는 안 된다.
2. 로컬 소유자만 관전 입력·카메라를 제어한다. 관전자가 생존자의 트랜스폼·입력·소유권을 변경하지 않는다.
3. 생존자의 눈높이와 상하·좌우 시선을 따라간다. 피치는 `PlayerLook.Pitch`로 복제했다(원래 로컬 전용).
   웅크리기·엎드리기·굴착의 카메라 높이는 `PlayerMotor.CameraLocalHeight` 복제로 함께 반영한다.
   시선 데이터는 시각 표현용이며 서버 판정 권위를 부여하지 않는다.
4. 카메라/AudioListener 활성화를 일관되게 관리한다. 기존 생존자 카메라와 관전 카메라가 중복 출력되거나
   원격 플레이어의 AudioListener가 함께 켜지지 않아야 한다. 관전 대상 몸체가 눈앞을 가리면 관전자 화면에서만 처리한다.
5. 사망·모드 전환·ESC·굴착 종료·휠 닫힘 순서가 바뀌어도 잠금이 풀려 특수능력이 다시 실행되면 안 된다.
   입력 잠금 해제 자체가 누적된 클릭·점프·스킬 입력을 실행하는 일도 막는다.
6. 사망 통지를 구독한다면 초기 스폰 시 이미 죽어 있는 상태도 적용하고, 디스폰·씬 종료 시 구독과 로컬 카메라를 정리한다.
   디버그 `ServerRevive()`·스테이지 리셋으로 생존이 복구되면 기존 카메라·조작으로 돌아가야 한다.
   관전 카메라 위치로 캐릭터를 부활시키지 않는다. 새 부활 게임 규칙을 추가한다는 뜻은 아니다.

플레이어 관전의 확정 범위는 **카메라 위치·방향 추종**이다. 대상의 개인 탐지 결과·전체 HUD·
정신력 화면 효과·개인 오디오까지 복제하는 기능은 이번 요청에서 확정되지 않았다.
탐지 결과가 시전자 로컬 전용이라는 기존 규칙을 임의로 변경하지 않는다.

## 4. 구현 현황 (2026-09-12 — 코드 반영, Host/Client Play 미검증)

이 표는 §3 경계·§5 결정에 따라 실제로 추가·수정한 코드다. `Gameplay/` 경로는 `Assets/Scripts/` 아래다.
카메라의 현재 구조는 [player-controller.md](../architecture/player-controller.md)를 참고한다.
Unity EditMode(211건)·PlayMode(12건) 테스트는 통과했다 — **Host/Client 수동 Play 검증은 아직이다.**

| 항목 | 구현 내용 |
| --- | --- |
| 사망 통지 | `SanityNetworkState`에 `public event Action<bool> AliveStateChanged` 추가. `ILocalPlayerContext`에도 자신을 등록해 `Sanity` 참조로 조회 가능 |
| 자유시점·관전 전환 | `Gameplay/Player/SpectatorController.cs`(신규) — 사망한 네트워크 루트와 분리된 전용 `SpectatorCamera`(Camera+AudioListener, 기본 비활성)로 자유비행·생존자 추종·모드 전환·대상 순회를 담당 |
| 대상 순회 순수 로직 | `Gameplay/Player/SpectatorTargetSelector.cs`(신규, Unity API 비의존) — EditMode에서 순수 테스트 |
| 원격 플레이어 시점 | `PlayerLook.Pitch`, `PlayerMotor.CameraLocalHeight`를 각각 `NetworkVariable`로 복제(Owner 쓰기 + Everyone 읽기, ADR-0008 이동 권위 예외의 연장) — `SpectatorController`가 대상의 루트 위치 + 이 두 값으로 눈높이·yaw·pitch를 재현 |
| 입력 잠금 | `PlayerInputReader`에 4번째 잠금 `SetDeathInputLocked` 추가. 우선순위 **메뉴 &gt; 사망 &gt; 굴착 &gt; 휠** — 사망이 굴착·휠보다 위라 같은 프레임에 굴착이 자기 잠금을 풀어도 생존 조작이 되살아나지 않는다. 새 관전 입력 액션 3개(SpectateDescend=Ctrl, SpectateToggleMode=V, SpectateNext=우클릭)는 `SpectatorSetup` 도구가 확인한다 |
| 스킬 사용 제한 | `DetectionSkillController`·`MoleBurrowController`는 기존 `HasSanity` 검사를 그대로 쓴다(수정 없음) — 이미 §5 SP-2 정책과 일치했다 |
| 탐지 중 사망 | `DetectionSkillSettings.CancelOnDeath = true` **확정**(MS-20 해소, 코드 변경 없음 — 태그만 제거) |
| 굴착 중 사망 | 기존 취소/무발사 종료 경로 유지(수정 없음). 잠금 해제 순서 경합은 위 사망 잠금 우선순위로 별도 방어 |
| 문·가구 사용 | `GrabController`의 잡기·조준·해제 RPC, `DoorInteractable.RequestToggleServerRpc`에 서버 측 생존 검사 추가. 귀신 전용 `DoorInteractable.ServerForceOpen/Close/Toggle`은 검사하지 않음(플레이어 요청이 아님) |
| 가구 놓기 | `GrabController`가 자신의 `SanityNetworkState.AliveStateChanged`를 구독해, 사망 시 들고 있던 가구를 `FurnitureGrabTarget.ServerForceRelease(forced: true)`로 발사 없이 놓는다 |
| 퀵슬롯 | `ILocalPlayerContext.Sanity` 추가, `QuickSlotWheelUi.CanOpen`이 생존을 검사 → [quick-slot.md §5](../architecture/quick-slot.md) |
| 플레이어 조회 | 기존 `ISanityTeamService.CopyPlayerStates`를 그대로 재사용(새 전역 명부 없음) |

Player 프리팹 배선(`SpectatorCamera` 자식, `SpectatorController` 컴포넌트, `SpectatorSettings_Default.asset`)은
Unity MCP로 `Assets/Scripts/Editor/SpectatorSetup.cs`(멱등)를 실행해 완료·검증했다.

## 5. 결정 사항 (2026-09-12 사용자 확정)

| # | 결정할 내용 | 확정 내용 |
| --- | --- | --- |
| SP-1 | 사망 직후 기본 모드, 조작키, 대상 사망·이탈 및 대상 0명 처리 | **확정.** 사망 직후 자유시점 시작. 조작키: WASD 이동·Space 상승·Ctrl 하강·마우스 회전(자유시점), V 모드 전환, 좌/우 클릭 이전/다음 생존자. 관전 대상이 무효(사망·연결 종료·디스폰)가 되면 다음 생존자로 자동 전환, 생존자가 0명이면 자유시점으로 전환 |
| SP-2 | 사망 순간 이미 켠 능력·홀드 정리, 일반 상호작용 차단 | **확정.** 탐지·굴착은 즉시 취소(`DetectionSkillSettings.CancelOnDeath = true` 확정, MS-20 해소). 가구는 발사 힘 없이 사망자의 홀드만 해제(`FurnitureGrabTarget.ServerForceRelease(forced: true)` 경로 사용). 문·가구·아이템 상호작용은 사망 중 전면 금지. 퀵슬롯은 기존 규칙대로 사망 시 선택 취소 후 닫힘·재개방 금지 |
| SP-3 | 자유비행 속도·가속/빠른 이동 여부·이동 감도 | **확정.** 고정 속도(가속·부스트 키 없음). 정확한 수치는 사용자가 확정하지 않았으므로 구현 시 `ScriptableObject` 튜닝 값으로 관리하고 문서·커밋에 "확정값"으로 기록하지 않는다 |
| SP-4 | 최초 관전 대상 선택 순서, 자유시점으로 돌아올 위치·방향 | **확정.** 생존자 목록(서비스가 반환하는 순서)대로 순회. 자유시점으로 복귀하면 마지막으로 보고 있던 위치·방향을 유지. 사망 직후 첫 진입은 사망 순간의 시점(위치·방향)에서 자유시점 시작 |

게임패드 바인딩·관전 HUD의 최종 디자인은 별도 확정 전까지 추가 범위를 약속하지 않는다.
벽 통과 자체는 확정이지만 맵 외곽/월드 높이 제한은 요청에 없으므로 별도 경계를 임의로 추가하지 않는다.
SP-3의 구체적 속도·감도 수치는 위 확정 범위에 포함되지 않는다 — SO 기본값은 구현자 임시값이며 밸런스 확정이 아니다.
