# 부활 시스템 기획서

> 원문: 사용자 제공 기획(2026-09-30). 아래 §1~§9 는 원문 규칙, §10 은 원문에 없어 **사용자에게 물어 정한 것**,
> §11 은 구현에서 정한 임시 값이다. 구현 구조는 코드 주석(`Gameplay/Revival/RevivalRitual.cs`)을 따른다.

## 1. 개요

사망한 플레이어의 시체를 소환진에 배치하고 촛불 5개를 점화해 부활시킨다.

- 촛불 5개를 모두 성공적으로 점화 → 정상 부활 / 1개 이상 실패 → 폐급 두더지 부활
- 부활 횟수 제한 없음(촛불 구매 비용으로 간접 제한), 한 번에 1명만

진행: 시체 이동 → 소환진 배치 → 촛불 5개 배치 → 촛불 점화 → 결과 판정 → 부활

## 2. 부활 조건

| 항목 | 조건 |
| --- | --- |
| 사망자 | 부활 가능한 사망 플레이어 존재(전멸 뒤에는 부활 없음 — death-system.md §8) |
| 시체 | 소환진 중앙에 **1구만** |
| 촛불 | 소환진에 5개 모두 배치 |
| 진행 인원 | 생존 플레이어 최소 1명 |

위 조건이 모두 충족돼야 점화를 시작할 수 있다.

## 3. 소환진

| 항목 | 규칙 |
| --- | --- |
| 개수 | 맵당 1개 |
| 위치 | 스테이지마다 **방 하나를 무작위**로 골라 **의식 방**으로 만든다 |
| 의식 방 (2026-09-30) | 방을 **싹 비운다** — 랜덤 가구·얼룩을 배치하지 않고, 고정 가구는 숨겨 치운다. 가운데 바닥에 빛나는 **마법진**(오망성), 오망성 꼭짓점마다 **촛대 5개** |
| 부활 위치 | 소환진 중앙 |

## 4. 촛불

- 상점 구매형 소모품. 부활 1회당 5개, 재사용 불가.
- 상점 품목 **촛대(5개 세트) $25** = 팀 촛불 재고 +5 → [stage-system.md §2.2](stage-system.md).

## 5~6. 의식 진행·타이밍 미니게임

1. 시체를 소환진 중앙에, 촛불 5개를 소환진에 놓는다.
2. 놓인 촛불마다 타이밍 미니게임으로 불을 붙인다. 순서 자유, 혼자 또는 여럿이 나눠서.
3. 의식 중에도 귀신에게 공격받을 수 있다.
4. **실패한 촛불도 일단 정상적으로 켜진다** — 즉시 알리면 중도 포기하므로. 5개가 다 켜지면 최종 판정.
5. 실패 촛불은 불이 약해 **판정 시작 1초 뒤 꺼진다**. 1개라도 있으면 폐급 부활.

## 7. 중단·초기화

| 중단 조건 | 처리 |
| --- | --- |
| 플레이어가 의식 진행을 중단 (§10 정의) | 진행도 초기화 |
| 귀신이 소환진 방의 문을 엶 | 촛불 전체 즉시 소등 + 진행도 초기화 |

- 초기화: 켜진 촛불은 모두 꺼지고 타이밍 결과는 삭제. **배치된 시체·촛불은 그대로**, 점화부터 다시.
- 마지막 촛불이 켜져 **최종 판정이 시작된 뒤에는 중단되지 않는다.**

## 8. 결과·완료

| 결과 | 조건 | 확률 |
| --- | --- | --- |
| 정상 부활 | 실패 촛불 0개 | — |
| 폐급 두더지 | 실패 촛불 1개 이상 | 98% |
| 개좃같은 폐급 두더지 | 실패 촛불 1개 이상 | 2% |

소환진 중앙에서 부활, 즉시 조작 가능, **3초 보호**(죽지 않음), 사망 전 아이템 유지, 시체 사라짐, 귀신 추격 대상 복귀.
폐급 상태는 **스테이지 종료까지** 유지(다시 죽었다 정상 부활해도 풀리지 않음 — 구현 해석).

## 9. 폐급 두더지 종류

| 종류 | 확률 | 구현 (2026-09-30) |
| --- | --- | --- |
| 한 명을 졸졸 따라다니는 두더지 | 98% 중 1/4 | **표시만** |
| 갑자기 소리지르는 두더지 | 98% 중 1/4 | **표시만** (음원 필요) |
| 키가 반대로 눌리는 두더지 | 98% 중 1/4 | 이동 키 반대 |
| 목소리가 변조되는 두더지 | 98% 중 1/4 | **표시만** (음성 파이프라인 작업 필요) |
| 개좃같은 폐급 두더지 | 2% | 20초 간격, 3초 동안 이동 입력이 무작위 방향으로 덮어써짐 |

## 11. 구현에서 정한 임시 값 [TEMP] — `RevivalRitualSettings_Default.asset`

| 값 | 임시 | 비고 |
| --- | --- | --- |
| 의식 방 후보 | **문이 있고 가로·세로 4.1m 이상**인 방 (Stage1 19곳) | 귀신 문 열기 초기화(§7)가 성립하고 마법진·촛대가 들어가도록. 작은 욕실·비밀창고·현관 제외 |
| 방 비우기 | 씬 가구 스폰·방 프리셋 이동이 끝난 뒤, 그 방을 제외해도 작업 가구 전체를 배치할 수 있는 후보 중 무작위로 고른다. 랜덤 가구·일반/고정 얼룩 후보에서 그 방을 뺀다. 가구 배치 뒤 방 안의 남은 가구를 모두 치운다 — 랜덤 가구는 보관 위치로, 분해 풀 가구는 비활성화(조립이 다시 꺼내 쓸 수 있다), 나머지는 `FurnitureNetworkPhysics.ServerStow`(모든 피어에서 숨김·충돌·물리 끔, 스테이지 동안 유지) | 제외 조건을 해제하는 재시도는 금지. 작업 대상 가구 수량을 줄이지 않으며, 비울 수 있는 후보가 없으면 오류를 남기고 의식을 배치하지 않는다(2026-10-04 수정) |

### 11.1 방 선택·배치 순서 (2026-10-04 수정)

1. `FurnitureSpawnController`가 씬 스폰·프리셋 이동을 기다리고 배치 시드를 정한 뒤 서버 이벤트 `ServerPreparingLayout`을 호출한다.
2. `RevivalRitual`은 무작위 순서의 방 후보를 같은 시드로 미리 검증한다. 해당 방을 제외하고도 전체 가구 계획이 성립하는 첫 후보를 가구·청소 서비스의 제외 영역으로 등록한다.
3. 가구 생성기는 제외 조건을 유지하며 전체 배치를 완료한다. 청소 서비스는 고정 지점도 같은 제외 조건을 적용하고, 제외된 고정 얼룩은 남은 일반 후보로 채운다.
4. 서버가 의식 방에 남은 가구를 정리한 뒤 방 중앙 바닥의 소환진 위치·방 번호를 복제한다. 각 피어가 그 위치에 마법진과 촛대 5개를 만든다.

검증(2026-10-04): 기존 구현에서 회귀 테스트 3개 실패를 재현한 뒤 수정본에서 통과했다.
Unity 컴파일·관련 EditMode 28/28·PlayMode 7/7 통과(실패·스킵 0).
실제 Stage1 로컬 Host 자동 흐름에서도 작업 가구 16개 유지·의식 방의 가구/얼룩 없음·마법진과 촛대 5개를 확인했다.
원격 Host/Client 화면·상호작용 실기는 확인 필요.

## 12. 미결정

- 따라다니기·소리지르기·목소리 변조 효과의 세부(누구를 따라가나, 얼마나 자주·크게 소리지르나, 변조 방식).
- 소환진·촛불 모델·연출·효과음(지금은 붉은 원판·원기둥·점광원).
- 호스트 이전 시 의식 진행·의식 방 복원(지금은 복원하지 않는다 — 놓인 촛불은 재고에서 이미 빠졌고, 새 호스트는 의식 방을 다시 고르며 보관한 가구는 스냅샷에 없어 다시 나타난다).
- 폐급을 다른 플레이어가 알아볼 표시(지금은 부활 공지 한 줄과 본인 화면 문구뿐).
