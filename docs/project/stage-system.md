## 1. 범위와 용어

스테이지는 한 판의 플레이이다. 인게임 로비에서 출발해 맵을 플레이하고, 정상 종료 시 정산을 거쳐 현재 접속한 플레이어와 **인게임 로비**로 돌아간다. 정산은 목표 달성률과 생존 상태를 평가해 보상과 이력을 처리하는 단계다.

### 1.1 일반 로비와 인게임 로비 (2026-09-28 사용자 결정)

| 구분 | 역할 | 흐름 |
| --- | --- | --- |
| **일반 로비** | 방 만들기·방 코드·초대·준비·게임 시작. 처음 한 번만 거친다 | 일반 로비 → 인게임 로비 |
| **인게임 로비** | 스테이지 사이에 머무는 **캐릭터가 돌아다니는 공간**. 상점, 방의 정산 이력, 다음 스테이지 출발 | 인게임 로비 → 인게임(스테이지) → 정산 → 인게임 로비 → … |

- 세션은 일반 로비의 게임 시작에서 한 번 열리고, 인게임 로비와 스테이지를 오가는 동안 유지된다 → [ADR-0018](../architecture/decisions/ADR-0018-persistent-session-in-game-lobby.md).
- **인게임 로비부터 새 플레이어의 참가를 막는다**(초대·방 코드·Steam 로비). 참가는 일반 로비에서만 된다.
- 인게임 로비의 **상점과 스테이지 출발은 방장만** 조작한다. 나머지는 잔액·보유를 보고 관람한다. 조작은 방 안의 단말기에서 E.
- 현재 인게임 로비는 회색 박스 단칸방이다. 아트·배치는 추후 씬 작업 대상이다.
- 인게임 로비의 "스테이지 출발"은 **`Stage1`** 을 올린다(2026-09-28). Stage1 에는 B안 집(가구 랜덤 배치)·임시 드릴카 안전 구역·
  가구 조립 영역·정신력 UI 가 있고, **귀신·청소는 아직 없다.** 기존 Game 씬은 `ProtoTypeGame` 으로 이름을 바꿔 프로토타입 검증용으로 남긴다
  → [ADR-0019](../architecture/decisions/ADR-0019-stage1-scene-split.md).

이 문서는 스테이지의 시작·종료·정산·세션 이탈 규칙을 정의한다. 보상 단가와 상세 정산 UI는 밸런스 설계 후 확정한다. 현재 구현 범위에서는 가구·청소·생존 결과와 정산 이력을 **방이 유지되는 동안만** 보관하며, 게임 재실행 후 보존과 금전 지급은 하지 않는다.

## 2. 로비와 시작

- 한 방의 최대 인원은 4명이다. **2명 이상** 참가하고 방장 외 전원이 준비했을 때만 방장의 시작 버튼을 활성화한다.
- 로비에서는 모든 플레이어가 음성으로 대화할 수 있다.
- 현재 사용 가능한 맵·난이도는 **원룸·보통 한 가지씩**이다. 다른 선택지는 대응 에셋·규칙이 준비된 뒤 연다.
- 상점은 **인게임 로비에서 방장만** 구매한다(2026-09-28 변경 — 이전: 일반 로비에서 모든 플레이어). 구매한 아이템은 개인 소유가 아닌 공동 자산이다. 임시 상점의 시작 자금은 **600**, Temp1·2·3 가격은 각각 **100·200·300**이다. 임시 아이템의 게임 효과는 아직 정의되지 않았다.
- 시작 시 로딩 화면을 표시하고 선택한 맵·난이도를 적용한다. 보유 아이템을 드릴카 선반에 배치한다. 로드가 끝나면 모두 드릴카 내부에서 시작한다.
- 현행 스테이지 씬(Stage1·ProtoTypeGame)에서는 임시 드릴카 구역과 조립 작업 구역을 네 시작 지점 근처로 런타임에 옮기고, 네 지점을 모두 감싸도록 안전 구역을 확장한다. 드릴카 모델과 최종 배치는 추후 씬 작업 대상이다.
- 로딩 중 게임 내 나가기·취소 기능은 제공하지 않는다.
- **인게임 로비로 넘어간 뒤에는(스테이지 진행 중 포함) 초대, 방 코드, Steam 로비를 통한 중도 참가를 모두 막는다.**

### 로딩 중 접속 이탈

| 남은 인원 | 처리 |
| --- | --- |
| 0명 | 방 데이터를 삭제한다. |
| 1명 | 로딩을 중단하고 남은 플레이어를 타이틀로 이동한 뒤 방을 삭제한다. `참여 인원이 부족하여 시작이 취소되었습니다`를 표시한다. |
| 2명 이상 | 로딩을 계속한다. 방장이 이탈했다면 남은 플레이어 중 **무작위**로 새 호스트를 선정한다. |

## 3. 스테이지 진행 중 접속 이탈

- 접속을 종료한 플레이어는 현재 스테이지의 참여자·팀 정신력 계산에서 제외한다.
- 한 명만 남아도 스테이지를 계속할 수 있다.
- 호스트가 연결 끊김 또는 `타이틀로 나가기`로 이탈하면 남은 플레이어 중 **무작위**로 새 호스트를 선정해 진행 중인 스테이지를 이어 간다. 나간 호스트만 타이틀로 이동한다.
- 호스트 외 플레이어의 `타이틀로 나가기`도 해당 플레이어만 이탈한다.
- 남은 접속 인원이 0명이면 비정상 종료한다.
- 이전 중 스테이지의 작업 진행도, 가구·얼룩·아이템·플레이어 상태, 결과 데이터가 유실되지 않아야 한다. 선택된 방식과 검증 상태는 [ADR-0017](../architecture/decisions/ADR-0017-host-migration.md)에 기록한다.

## 4. 정상 종료

정상 종료는 드릴카 종료 버튼 사용 또는 생존 플레이어 수가 0명이 되었을 때 발생한다. 정상 종료에서는 정산을 진행하고 보상 이력을 저장한다. **전멸은 스테이지 실패 판정이지만 정산 대상이다.** 남은 접속자가 0명인 경우에는 §5의 비정상 종료가 우선한다.

### 4.1 드릴카 종료 버튼

- 스테이지가 시작된 뒤 생존 플레이어는 언제든 사용할 수 있다.
- 상호작용한 플레이어에게 종료 확인 UI를 띄운다. 그 UI에서 `종료`를 선택하면 스테이지가 종료된다.
- 종료 시 드릴카 내부에 있는 생존 플레이어만 생존자로 집계한다. 밖에 남은 생존 플레이어는 정산에서 `실종된 플레이어`로 처리한다.

### 4.2 생존 플레이어 수 0명

- 접속한 플레이어 전원이 죽거나, 일부가 접속을 종료해 남은 생존 플레이어가 0명이 되면 즉시 스테이지 실패로 판정하고 정산한다.
- 전멸 확정 후에는 부활할 수 없다.

## 5. 비정상 종료와 메뉴

- 비정상 종료에는 정산과 보상 이력 저장이 없다. 스테이지에서 사용한 공동 아이템은 복구한다.
- 접속자가 전부 나가면 비정상 종료한다.
- 방장의 ESC 메뉴에 `스테이지 나가기` 버튼을 둔다. 선택하면 현재 스테이지를 비정상 종료하고 **접속 중인 전원을 인게임 로비**로 이동한다. 세션과 방·로비 멤버십은 유지한다.
- `타이틀로 나가기`는 누른 플레이어만 방과 스테이지를 떠난다. 방장이 눌러도 남은 플레이어는 §3에 따라 호스트를 이전해 스테이지를 계속한다.

## 6. 정산

- 정상 종료 후 `Result` 단계에서 **드릴카 반출 구역에서 완료 처리한 목표 가구 수**, 얼룩 청소 완료율, 생존 플레이어 수를 표시하고 현재 방의 정산 이력에 기록한다. 드릴카 안에 있다는 사실만으로 가구 반출 완료가 되지는 않는다. 반출 완료된 가구는 잡고 있던 플레이어의 손에서 풀리고 맵에서 사라진다(보관 위치로 치움, 정산 집계용 완료 기록은 유지 — 2026-09-28). 상세 보상 금액·공식·UI는 밸런스 설계 후 확정한다. 이번 구현에서는 금전을 지급하지 않는다.
- 정산 기록은 Steam 로비 데이터에 판별 가능한 순번으로 게시해 방에 남은 다른 플레이어가 결과 화면에서 다시 읽을 수 있다. 방이 사라지면 이력도 사라진다.
- 스테이지 종료 시 사망자로 남은 플레이어 수를 치료비 산정용으로 기록한다. 1인당 금액은 [죽음 시스템 기획서](death-system.md)에서 `TBD`이며, 이번 구현에서는 차감하지 않는다.
- 정산 UI 조작 권한은 방장에게만 있다. 정산을 마치면 접속 중인 플레이어와 함께 **인게임 로비**로 돌아간다(세션 유지).
- `Result`에서는 생존·사망 음성 그룹을 합쳐 전원이 대화할 수 있다.

## 7. 구현 상태와 수용 기준

이 문서의 규칙은 확정된 **목표 동작**이다. 2026-09-27 현재 코드에는 2명 이상 시작 검사, 로딩·진행 중 로비 참가 닫기, 로비·정산 공용 음성, 종료 확인 UI, 가구·청소·생존 정산과 Steam 로비 데이터에 게시하는 현재 방의 이력, `스테이지 나가기`, 임시 공동 상점과 드릴카 선반 표시가 반영되었다. 진행 중 Steam 복제본 배포·무작위 새 호스트의 NGO 재시작·주요 상태 복원 코드도 추가했다. **실제 Steam 다중 PC 이전 검증과 직전 변경 커밋 확인은 남아 있다.** Temp 아이템은 사용 효과가 없어 구매·선반 보유만 구현한다. 코드 반영만으로 실기 검증 완료로 간주하지 않는다.

**2026-09-28 인게임 로비(§1.1):** 세션 유지형 인게임 로비 씬·전환(`IStageSessionFlow`)·방장 전용 상점 이동을 코드와 씬
(`InGameLobby.unity`, Build Settings·SceneNameSO 등록 완료)으로 반영했다. 씬을 만든 설치 도구는 삭제했다(ADR-0020). 한 PC Local Host 로 전 흐름을 자동 검증했고, 게스트 동기화·Steam 다인은 미검증.

**2026-09-28 Stage1(§1.1):** 스테이지 출발 대상을 `Stage1` 로 바꿨다. `Game.unity` 를
`ProtoTypeGame.unity` 로 바꾸고 Stage1 을 만들어 Build Settings·SceneNameSO 에 등록했다(당시 설치 도구로 실행, 도구는 ADR-0020으로 삭제). 검증용 복제 프로젝트에서
인게임 로비 ⇄ Stage1 흐름을 자동 검증했고, 에디터 Local Host 로 Stage1 진입·B안 가구 배치를 확인했다. 게스트·Steam 다인은 미검증.
Stage1 에는 청소·귀신이 없어 호스트 이전 스냅샷이 찍히지 않는다(ADR-0017 후속).

- 방장 혼자서는 시작할 수 없고, 2~4명에서 게스트 전원이 준비해야 시작한다.
- 로비 전원이 대화하며, 진행 중 생존·사망 그룹은 분리되고, `Result`에서 다시 합쳐진다.
- 시작 후 새 플레이어는 초대·방 코드·Steam 로비 경로 어느 쪽으로도 들어오지 못한다.
- 호스트 이탈 후 남은 인원 중 무작위로 선출된 호스트가 동일한 스테이지 상태를 이어 간다.
- 정상 종료만 보상·이력을 남기고, 비정상 종료는 사용 아이템을 복구한다.
- 방장의 `스테이지 나가기`는 전원을 인게임 로비로 보내고, `타이틀로 나가기`는 해당 플레이어만 나가게 한다.
