## 1. 범위와 용어

스테이지는 한 판의 플레이이다. 세션은 인게임 로비(드릴카 상점)에서 열리고, 인게임 로비에서 출발해(첫 출발은 Tutorial) 맵을 플레이하며, 정상 종료 시 정산을 거쳐 현재 접속한 플레이어와 **인게임 로비**로 돌아간다. 정산은 목표 달성률과 생존 상태를 평가해 보상과 이력을 처리하는 단계다.

### 1.1 일반 로비와 인게임 로비 (2026-09-28 사용자 결정)

| 구분 | 역할 | 흐름 |
| --- | --- | --- |
| **일반 로비** | 방 만들기·방 코드·초대·준비·게임 시작. 처음 한 번만 거친다 | 일반 로비 → 인게임 로비 → Tutorial |
| **인게임 로비** | 스테이지 사이에 머무는 **캐릭터가 돌아다니는 공간**. 상점, 방의 정산 이력, 다음 스테이지 출발 | 인게임 로비 → 인게임(스테이지) → 정산 → 인게임 로비 → … |

- 세션은 일반 로비의 게임 시작에서 한 번 열리고, 인게임 로비와 스테이지를 오가는 동안 유지된다 → [ADR-0018](../architecture/decisions/ADR-0018-persistent-session-in-game-lobby.md).
- **Tutorial 시작부터 새 플레이어의 참가를 막는다**(초대·방 코드·Steam 로비). 참가는 일반 로비에서만 된다.
- 인게임 로비의 **상점과 스테이지 출발은 방장만** 조작한다. 나머지는 잔액·보유를 보고 관람한다. 조작은 방 안의 단말기에서 E.
- 현재 인게임 로비는 회색 박스 단칸방이다. 아트·배치는 추후 씬 작업 대상이다.
- Tutorial 정산 뒤 인게임 로비의 "스테이지 출발"은 **`Stage1`** 을 올린다(2026-10-02). Stage1 에는 B안 집(가구 랜덤 배치)·드릴카(모델, §2.1)·
  가구 조립 영역·정신력 UI·귀신·청소·부활 의식이 있다(현재 씬 기준). 기존 Game 씬은 `ProtoTypeGame` 으로 이름을 바꿔 프로토타입 검증용으로 남긴다
  → [ADR-0019](../architecture/decisions/ADR-0019-stage1-scene-split.md).

이 문서는 스테이지의 시작·종료·정산·세션 이탈 규칙을 정의한다. 보상 단가와 상세 정산 UI는 밸런스 설계 후 확정한다. 현재 구현 범위에서는 가구·청소·생존 결과와 정산 이력을 **방이 유지되는 동안만** 보관하며, 게임 재실행 후 보존과 금전 지급은 하지 않는다.

### 1.2 첫 스테이지 Tutorial (2026-10-02)

일반 로비 게임 시작과 Local Host는 InGameLobby(드릴카 상점)로 진입하고, 첫 출발이 Tutorial이다(2026-10-03). 정상 종료/전멸 → Result → InGameLobby → 다음 출발 Stage1.
정산 없는 ESC 이탈은 Tutorial 재시도이며 Title/Lobby 복귀 시 첫 스테이지 상태를 초기화한다.
기존 종료 단말기·정산·세션 유지 규칙을 사용한다. 전용 과제나 자동 클리어 조건은 추가하지 않았다.
맵 재질·현재 크기·앞쪽 드릴카·Stage1 조명 참조 배치와 검증은 [tutorial-stage.md](tutorial-stage.md)에 기록한다.

## 2. 로비와 시작

- 한 방의 최대 인원은 4명이다. **2명 이상** 참가하고 방장 외 전원이 준비했을 때만 방장의 시작 버튼을 활성화한다.
- 로비에서는 모든 플레이어가 음성으로 대화할 수 있다.
- 현재 사용 가능한 맵·난이도는 **원룸·보통 한 가지씩**이다. 다른 선택지는 대응 에셋·규칙이 준비된 뒤 연다.
- 상점은 **인게임 로비에서 방장만** 구매한다(2026-09-28 변경 — 이전: 일반 로비에서 모든 플레이어). 돈은 팀 공동 잔액 하나다. 품목·가격·수리는 §2.2(2026-09-29 — 이전 임시 상점: 시작 600, Temp1·2·3 = 100·200·300).
- 시작 시 로딩 화면을 표시하고 선택한 맵·난이도를 적용한다. 보유 아이템을 드릴카 선반에 배치한다. 로드가 끝나면 모두 드릴카 내부에서 시작한다.
- **Stage1** 은 드릴카 모델과 조립 작업 구역을 씬에 고정 배치한다(§2.1, 2026-09-29). 시작 지점은 아직 앞마당이다 — "모두 드릴카 내부에서 시작"은 미반영.
- **ProtoTypeGame** 은 모델 없이 임시 드릴카 상자와 조립 작업 구역을 네 시작 지점 뒤로 런타임에 옮기고, 네 지점 폭만큼 안전 구역을 넓힌다.
- 로딩 중 게임 내 나가기·취소 기능은 제공하지 않는다.
- **Tutorial 게임 시작 뒤에는(인게임 로비·스테이지 진행 중 포함) 초대, 방 코드, Steam 로비를 통한 중도 참가를 모두 막는다.**

### 2.1 드릴카 (Stage1, 2026-09-29)

모델 `Assets/Mesh/DrillCar/DrillCar.fbx`, 프리팹 `Assets/Prefabs/Map/DrillCar.prefab`. 프리팹 원점은 궤도 바닥(지면)이고
드릴이 +Z, 뒷문·램프가 -Z 다. Stage1 에는 **램프가 집(+Z)을 보도록 180° 돌려** 세웠다.

> **2026-10-04 1.4배 확대(사용자 요청 "드릴카 너무 좁다"):** 임포트 배율만 바꾸고(트랜스폼 스케일 1 규칙), 실내 상자·조명·단말기·선반 앵커·현황판을 같은 비율로 옮겼다. **램프 끝이 같은 자리에 오도록 차를 뒤로 1.86m 뺐다** — Stage1 (67.67, −0.54, −28.83), Tutorial (0, 0, 14.86). 그래서 앞의 반출 구역·조립 영역과 Tutorial 모텔 계단 사이 배치는 그대로다. 검증: `DrillCarZoneLayoutTests` (커진 차체가 장애물과 겹치지 않고 실내 폭 3.6m 이상·차체와 같은 비율), Tutorial 씬 렌더로 실내·현황판 위치 육안 확인.

> **2026-10-04 (사용자 요청 "가구 반출 구역·조립 존을 드릴카 내부가 아니라 외부로"):** 반출 구역을 실내에서 빼고, 조립 영역도
> 램프 끝에 붙어 있던 자리에서 옮겨 **둘 다 드릴카 밖 땅**에 둔다. **같은 날 후속 요청 "설치 장소 및 반출장소 형광으로 빛나는 거 드릴카 오른쪽으로":**
> 두 구역을 차체 오른쪽 **로컬 +X**에 앞뒤로 나눠 배치한다(조립은 램프 쪽, 반출은 드릴 쪽). 램프 앞 통로는 비운다. 좁은 뒷문·램프로 가구를
> 들고 올라갈 필요가 없다. 실내는 안전 구역(라이터 충전, 종료 시 생존 집계)으로만 남는다. **헤드라이트는 2026-10-29부터 자동 충전되지 않고**
> 실내 오른쪽 벽 앞 **배터리 팩**에 E를 홀드해 충전한다 → [headlamp-system.md §8](headlamp-system.md).

**가구 포장 처리 (2026-11-03, 사용자 기획 "2-2. 가구 포장 처리")** — 목표 가구는 구역에 **위치만 들어온다고** 반출되지 않고, 서버가 아래 조건을 **끊김 없이 1초** 확인하면 포장(= 반출 완료)한다. 판정은 `FurnitureDeliveryTracker`(서버 FixedUpdate)이고 계산은 `FurniturePackingRule`, 수치는 `FurnitureSpawnSettings`(`PlanB`·`Tutorial` 에셋 모두 같은 값)에 있다.

  인게임 로비 ⇄ 스테이지 동안 유지되며, 게임을 끄면 사라진다. 판 보상은 두 경우 모두 `SceneFlowController.RecordStageSettlement` 가
  서버에서 판마다 한 번 준다.
- 나무·철 드라이버의 성능 차이는 아직 없다(같은 행동 시간·내구도 감소) — 차이가 정해지면 `FurnitureDriverSettings` 에 등급별 값을 둔다.

**상점 계산 공통화(2026-11-02, 리팩토링 3단계):** `StageShopRules.TryPurchase`·`TryRepair`가 구매·수리
조건을 확인하고 다음 잔액·촛불·장비를 계산한다. 규칙에서 거절하면 입력 상태를 보존한다.
Steam과 Local은 같은 계산을 사용하며 각 경로의 참가자 검사·저장·전송·성공 알림을 유지한다.
기존 품목·가격·내구도·권한·보상·로비 데이터/메시지 형식은 바꾸지 않았다 → [steam.md](../architecture/steam.md).

**상점 UI 목록(2026-10-05, SHOP-FIX-1):** `InGameLobbyPanel`은 상점을 그리기 전에 참가자를 UI 전용 목록에 복사하고
그 목록을 순회한다. 구매·수리 성공 시 `StageShopService`가 원본 참가자 목록을 다시 구성해도 진행 중인 UI 순회를
무효화하지 않는다. UI 목록은 재사용하며 다음 그리기 때 최신 참가자를 반영한다.
검증: Unity 컴파일·상점 EditMode 10/10·로비 PlayMode 5/5 통과(실패·스킵 0). 회귀 검사는 실제 로컬 호스트에서
UI 스냅샷을 순회하며 철제 드라이버·라이터 구매, 내구도 저장·수리, 서비스 목록 재조회를 실행해 순회 완료·잔액·장비를 확인한다.
실제 IMGUI 버튼 클릭과 원격 Steam 다인 화면은 확인 필요.

**개발 튜닝(2026-10-05 사용자 요청):** F2 `튜닝 · 밸런스 값` 창의 `공동 자금 · 현재 돈`에 실제 공동 잔액을 표시한다.
호스트는 0 이상의 정수를 입력하고 `적용`하거나 `− / +`로 $1씩 조절한다. 필터에서 `돈`·`잔액`·`money`로 찾을 수 있다.
`IStageShopService.TrySetBalanceForDebug`가 권한과 음수를 검사하며, Steam은 방장이 기존 `gh_shop_state`를 갱신하고
Local은 호스트가 기존 NGO 이름 메시지로 상태를 보낸다. 실제 상점 구매에 반영되고 촛불 재고·보유 장비는 보존한다.
게스트는 잔액을 보기만 한다. 현재 세션 잔액은 SO가 아니므로 설정의 `전체 되돌리기` 대상과 디스크 저장 대상이 아니다.
정수 최대 경계의 판 보상은 `int.MaxValue`에서 포화시켜 음수 오버플로를 막는다. 시작 자금·가격·판 보상 단가는 기존 값이다.
검증: Unity 컴파일·상점 EditMode 10/10·관련 PlayMode 12/12(음수/세션 전 변경 거절, 실제 구매, 장비·재고 보존,
최대값 보상, 스테이지 왕복) 통과. 실제 F2 입력 화면·원격 Steam 다인 복제는 확인 필요.

### 로딩 중 접속 이탈

| 남은 인원 | 처리 |
| --- | --- |
| 0명 | 방 데이터를 삭제한다. |
| 1명 | 로딩을 중단하고 남은 플레이어를 타이틀로 이동한 뒤 방을 삭제한다. `참여 인원이 부족하여 시작이 취소되었습니다`를 표시한다. |
| 2명 이상 | 로딩을 계속한다. 방장이 이탈했다면 남은 플레이어 중 **무작위**로 새 호스트를 선정한다. |

## 3. 스테이지 진행 중 접속 이탈

- 접속을 종료한 플레이어는 현재 스테이지의 참여자·팀 정신력 계산에서 제외한다.
- 한 명만 남아도 스테이지를 계속할 수 있다.
- 호스트가 연결 끊김 또는 `타이틀로 나가기`로 이탈하면 남은 플레이어 중 **무작위**로 새 호스트를 선정해 진행 중인 스테이지를 이어 간다. 나간 호스트만 타이틀로 이동한다.
- 호스트 외 플레이어의 `타이틀로 나가기`도 해당 플레이어만 이탈한다.
- 남은 접속 인원이 0명이면 비정상 종료한다.
- 이전 중 스테이지의 작업 진행도, 가구·얼룩·아이템·플레이어 상태, 결과 데이터가 유실되지 않아야 한다. 선택된 방식과 검증 상태는 [ADR-0017](../architecture/decisions/ADR-0017-host-migration.md)에 기록한다.

## 4. 정상 종료

정상 종료는 드릴카 종료 버튼 사용 또는 생존 플레이어 수가 0명이 되었을 때 발생한다. 정상 종료에서는 정산을 진행하고 보상 이력을 저장한다. **전멸은 스테이지 실패 판정이지만 정산 대상이다.** 남은 접속자가 0명인 경우에는 §5의 비정상 종료가 우선한다.

### 4.1 드릴카 종료 버튼

- 스테이지가 시작된 뒤 생존 플레이어는 언제든 사용할 수 있다.
- 상호작용한 플레이어에게 종료 확인 UI를 띄운다. 그 UI에서 `종료`를 선택하면 스테이지가 종료된다.
- 종료 시 드릴카 내부에 있는 생존 플레이어만 생존자로 집계한다. 밖에 남은 생존 플레이어는 정산에서 `실종된 플레이어`로 처리한다.

**입력 구현 보정(2026-10-04):** Input System 전용 설정에서 런타임 `OnGUI` 입력 이벤트를 받을 수 없어,
종료 확인창의 `종료`·`취소`와 정산 화면의 로비 복귀는 `Mouse.current`의 누름/놓음을 읽는다.
그리는 버튼과 동일한 화면 Rect 안에서 눌렀다가 놓았을 때만 실행하며, 밖으로 드래그해 놓으면 실행하지 않는다.
표시와 에디터 IMGUI 입력 경로는 유지한다. 종료는 기존 소유자 RPC와 서버의 생존·거리·드릴카 내부 검증을 통과해야 한다.
정산 후 복귀는 기존 `IStageSessionFlow`의 서버 권위를 사용한다.

### 4.2 생존 플레이어 수 0명

- 접속한 플레이어 전원이 죽거나, 일부가 접속을 종료해 남은 생존 플레이어가 0명이 되면 즉시 스테이지 실패로 판정하고 정산한다.
- 전멸 확정 후에는 부활할 수 없다.

## 5. 비정상 종료와 메뉴

- 비정상 종료에는 정산과 보상 이력 저장이 없다. 스테이지에서 사용한 공동 아이템은 복구한다.
- 접속자가 전부 나가면 비정상 종료한다.
- 방장의 ESC 메뉴에 `스테이지 나가기` 버튼을 둔다. 선택하면 현재 스테이지를 비정상 종료하고 **접속 중인 전원을 인게임 로비**로 이동한다. 세션과 방·로비 멤버십은 유지한다.
- `타이틀로 나가기`는 누른 플레이어만 방과 스테이지를 떠난다. 방장이 눌러도 남은 플레이어는 §3에 따라 호스트를 이전해 스테이지를 계속한다.

## 6. 정산

- 정상 종료 후 `Result` 단계에서 **드릴카 반출 구역에서 완료 처리한 목표 가구 수**, 얼룩 청소 완료율, 생존 플레이어 수를 표시하고 현재 방의 정산 이력에 기록한다. 드릴카 안에 있다는 사실만으로 가구 반출 완료가 되지는 않는다. 반출 완료된 가구는 잡고 있던 플레이어의 손에서 풀리고 맵에서 사라진다(보관 위치로 치움, 정산 집계용 완료 기록은 유지 — 2026-09-28). §2.2의 **판당 기본 보상 $50는 전멸 포함 서버가 한 번 공동 잔액에 지급**한다. 작업 성과에 따른 추가 보상 금액·공식·UI는 밸런스 설계 후 확정한다.
- 정산 기록은 Steam 로비 데이터에 판별 가능한 순번으로 게시해 방에 남은 다른 플레이어가 결과 화면에서 다시 읽을 수 있다. 방이 사라지면 이력도 사라진다.
- 스테이지 종료 시 사망자로 남은 플레이어 수를 치료비 산정용으로 기록한다. 1인당 금액은 [죽음 시스템 기획서](death-system.md)에서 `TBD`이며, 이번 구현에서는 차감하지 않는다.
- 정산 UI 조작 권한은 방장에게만 있다. 정산을 마치면 접속 중인 플레이어와 함께 **인게임 로비**로 돌아간다(세션 유지).
- `Result`에서는 생존·사망 음성 그룹을 합쳐 전원이 대화할 수 있다.

**정산 낙하 보정(2026-10-05, SF-FIX-3):** 스테이지의 플레이어는 정산 음성을 위해 유지하지만 스테이지 바닥은
언로드된다. `PlayerMotor`는 로딩·`Result` 동안 이동과 중력을 멈추고 수직 속도를 초기화한다. `ResultCamera`는
단색 배경만 그려 유지된 캐릭터가 정산 UI 뒤에 나타나지 않게 한다. 로비 복귀는 기존 서버 권위의 디스폰·재스폰을
사용하며 새 플레이어는 이동·중력을 다시 적용한다. 수정 전 PlayMode에서 정산 진입 후 낙하를 재현했다.
검증: Unity 컴파일·EditMode 38/38(`InGameLobbyTests`·`ProjectWiringTests`)·PlayMode 8/8
(`InGameLobbyFlowTests`·`DeathSystemFlowTests`) 통과, 실패·스킵 0. 로딩·정산 위치 유지, 정산 플레이어·세션 보존,
정산 카메라의 단색 배경·월드 렌더링 제외, 정상 종료·전멸, 로비 복귀 후 중력 재개를 확인했다.
실제 사용자 화면·원격 Steam 다인 실기는 확인 필요.

## 7. 구현 상태와 수용 기준

**2026-11-03 리팩토링 6단계:** `SceneTransitionOperations`로 씬 실행/이벤트 대기/입력 복원을,
`StageSettlementHistory`로 방 이력·중복 방지·게시 재시도를 분리했다. 서버 권위·씬 전환/재스폰 순서·기본 보상·
치료비 미정·복구 형식은 유지한다. 정산 UI의 미정 문구는 기본 보상과 구분해 "추가 보상"으로 보정했다.
전체 EditMode **597/597**·PlayMode **171/171** 통과, C# 오류·경고 0. 실제 Steam 다인과 기존 SF-FIX-1은 남아 있다 →
[overview.md §5.2](../architecture/overview.md#52-씬-전환과-정산-이력-2026-11-03), [testing.md](../workflow/testing.md).

이 문서의 규칙은 확정된 **목표 동작**이다. 2026-09-27 현재 코드에는 2명 이상 시작 검사, 로딩·진행 중 로비 참가 닫기, 로비·정산 공용 음성, 종료 확인 UI, 가구·청소·생존 정산과 Steam 로비 데이터에 게시하는 현재 방의 이력, `스테이지 나가기`, 임시 공동 상점과 드릴카 선반 표시가 반영되었다. 진행 중 Steam 복제본 배포·무작위 새 호스트의 NGO 재시작·주요 상태 복원 코드도 추가했다. **실제 Steam 다중 PC 이전 검증과 직전 변경 커밋 확인은 남아 있다.** Temp 아이템은 사용 효과가 없어 구매·선반 보유만 구현한다. 코드 반영만으로 실기 검증 완료로 간주하지 않는다.

**2026-09-28 인게임 로비(§1.1):** 세션 유지형 인게임 로비 씬·전환(`IStageSessionFlow`)·방장 전용 상점 이동을 코드와 씬
(`InGameLobby.unity`, Build Settings·SceneNameSO 등록 완료)으로 반영했다. 씬을 만든 설치 도구는 삭제했다(ADR-0020). 한 PC Local Host 로 전 흐름을 자동 검증했고, 게스트 동기화·Steam 다인은 미검증.

**2026-09-28 Stage1(§1.1):** 스테이지 출발 대상을 `Stage1` 로 바꿨다. `Game.unity` 를
`ProtoTypeGame.unity` 로 바꾸고 Stage1 을 만들어 Build Settings·SceneNameSO 에 등록했다(당시 설치 도구로 실행, 도구는 ADR-0020으로 삭제). 검증용 복제 프로젝트에서
인게임 로비 ⇄ Stage1 흐름을 자동 검증했고, 에디터 Local Host 로 Stage1 진입·B안 가구 배치를 확인했다. 게스트·Steam 다인은 미검증.
당시 Stage1에는 청소·귀신이 없었다. 현재 씬에는 청소·귀신·부활 의식이 포함된다. Steam 호스트 이전 실기 검증은 별도다.

- 방장 혼자서는 시작할 수 없고, 2~4명에서 게스트 전원이 준비해야 시작한다.
- 로비 전원이 대화하며, 진행 중 생존·사망 그룹은 분리되고, `Result`에서 다시 합쳐진다.
- 시작 후 새 플레이어는 초대·방 코드·Steam 로비 경로 어느 쪽으로도 들어오지 못한다.
- 호스트 이탈 후 남은 인원 중 무작위로 선출된 호스트가 동일한 스테이지 상태를 이어 간다.
- 정상 종료만 보상·이력을 남기고, 비정상 종료는 사용 아이템을 복구한다.
- 방장의 `스테이지 나가기`는 전원을 인게임 로비로 보내고, `타이틀로 나가기`는 해당 플레이어만 나가게 한다.
