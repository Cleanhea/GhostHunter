## 2. 시스템 개요 (원문)

- 스테이지 안의 **특정 가구와 상호작용해 귀중품을 찾아 훔치는** 시스템이다.
  - 훔칠 수 있는 귀중품에 포인터를 두고 **E 키**를 누르면 그 귀중품을 훔친다.
- 귀중품을 훔치면 **귀중품 가치만큼 추가 수입**이 생기고 **정신력이 회복**된다(§2.1).
- 도둑질 시스템의 핵심인 **"귀중품을 숨기는 기믹"은 추후 레벨 디자인 문서에서** 설명한다(원문). 아직 그 문서는 없다 → TH-Q4.
- 레퍼런스: 크라임 씬 클리너 — https://youtu.be/8Lphv5oimXc?si=1YbKMv99WNT0OoeF&t=9

### 2.1 가치별 정신력 회복량

원문은 「정신력 시스템 기획서」 목차 3-2-1의 금액표를 인용한다. 이 저장소에서 그 표는 **[sanity-system.md §4.1](sanity-system.md) 한 곳**에서
관리한다(값 동일, 중복 금지 규칙). 요지는 다음과 같다.

- 귀중품이나 돈을 얻으면 **얻은 사람의** 정신력이 즉시 오르고, 오르는 양은 금액($2·$3·$5·$10)에 따른다.
- **이 4종이 전체 금액 체계이고, 표에 없는 금액은 정신력이 오르지 않는다**(사용자 확정 2026-10-29).
- 회복은 **훔친 개인에게만** 적용한다(공동 잔액과 별개, 같은 확정).

### 4.1 훔치기 전 — 귀중품에 포인터를 두었을 때 "E 훔치기"

![E 훔치기 안내 배치 1920×1080](../images/theft-steal-prompt-layout.png)

| 항목 | 값 |
| --- | --- |
| 문구 | `E 훔치기` — `E`는 키캡 모양 상자, 그 오른쪽에 "훔치기" |
| 기준 해상도 | 1920 × 1080, 원점은 화면 왼쪽 위 (0, 0) |
| 위치 | 우측 하단. 패널 왼쪽 위 **(1410, 869)**, 중심 **(1476, 894)** |
| 크기 | **132 × 50 px** (패널 외곽, 그림자 제외) |
| 여백 | 오른쪽 **378 px**, 아래 **161 px** |
| 폰트 | Noto Sans KR Bold |

> 이미지 안의 주석 그대로: "게임 UI의 확정 규격이 아니라, 현재 생성 이미지의 위치·크기를 환산한 값". 즉 근사값이다.
> 치수는 서로 맞는다(1410 + 132 + 378 = 1920, 869 + 50 + 161 = 1080).

### 4.2 도둑질 중 — 귀중품 가격 "+ n$"

![+ n$ 가격 표시](../images/theft-price-popup.png)

![+ n$ 가격 표시 위치 치수](../images/theft-price-popup-px.png)

| 항목 | 값 |
| --- | --- |
| 문구 | `+ n$` (n = 귀중품 가격). 예시 이미지는 `+ 20$` — §6-1 참고 |
| 위치 | **화면 가로 중앙**, 세로 중앙선에서 아래로 **61px**(원문 주석) |
| 색 | **`#54d6ad`** |
| 폰트 | Noto Sans KR Bold |
| 표시 시점 | 도둑질 애니메이션이 진행되는 동안(TH-3). 사라지는 시점은 원문에 없다 → TH-Q5 |

> **61px의 기준 해상도는 원문에 없다.** 첨부 이미지(4000 × 2250)를 재 보면 중앙선에서 글자 위쪽까지가 화면 높이의 약 8~9%로,
> 1080p로 환산하면 약 90~100px이다. 어느 쪽이 의도인지 확인이 필요하다 → TH-Q7.

### 4.3 도둑질 후 — 정신력 회복 효과(화면 테두리)

![정신력 회복 효과 — 화면 테두리 빛](../images/theft-sanity-recovery-border.png)

| 항목 | 값 |
| --- | --- |
| 효과 | 화면 **테두리가 2초간 밝아진다** |
| 색 | **`#c2fcf3`** |
| 시점 | 훔치는 순간, "+ n$" 표시와 동시(TH-4) |
| 구현 방식 | **포스트프로세싱**(사용자 지정, 2026-11-12) |

> **구현 메모 (2026-11-12 확인).** 정신력 20 이하의 카메라 테두리 노이즈는 이미 Global Volume으로 구현돼 있다
> (`SanityCameraNoise`, 비네트+필름 그레인+색수차 → [architecture/sanity-system.md §6](../architecture/sanity-system.md)).
> 그런데 **URP 기본 Vignette는 화면색에 비네트 색을 곱하는 방식**이라(`Common.hlsl` `ApplyVignette`:
> `input * lerp(color, 1, vfactor)`) 테두리를 **어둡게만** 할 수 있고 `#c2fcf3`처럼 **밝게 빛나게는 못 한다.**
> 밝은 테두리는 Full Screen Pass Renderer Feature(전용 셰이더) 같은 별도 포스트프로세싱 경로가 필요하다. 어느 방식을 쓸지는 구현할 때 정한다.
> 2초 안의 밝기 변화(켜지고 꺼지는 곡선)와 낮은 정신력 노이즈와 겹칠 때의 처리는 원문에 없다 → TH-Q6.

## 5. 기존 시스템과의 연결 (2026-11-12 저장소 확인 · 같은 날 구현)

구현 세부는 [architecture/theft-system.md](../architecture/theft-system.md). 아래 "지금 상태"는 구현 전 조사 기록이고, 오른쪽 칸이 구현된 처리다.

| 대상 | 구현 전 상태 | 구현된 처리 |
| --- | --- | --- |
| 정신력 | `SanityNetworkState.ServerApplyValuableFound(int dollars)`와 금액표(`SanitySystemSettings._valuableRewards`)는 구현돼 있고 **호출부가 없다** → [sanity-system.md §4.1](sanity-system.md), [architecture/sanity-system.md](../architecture/sanity-system.md) | `PlayerTheft`가 서버에서 도둑질을 확정한 뒤 **훔친 플레이어의 상태**에 호출한다(가격이 표의 4종뿐이라 늘 오른다) |
| 돈 | 돈은 **팀 공동 잔액 하나**다. 판 보상은 정산 이력을 로비에 게시할 때 한 번 더한다 → [stage-system.md §2.2](stage-system.md) | 서버가 도둑질을 확정하는 순간 공동 잔액에 **즉시** 더한다. 사망·실종·전멸이어도 되돌리지 않는다. 판 동안 훔친 금액을 서버가 따로 모아 `Result` 정산에 별도 항목으로 표시한다([stage-system.md §6](stage-system.md)의 Result 항목에 추가). 잔액에는 이미 더해졌으므로 정산 때 다시 더하지 않는다 |
| E 상호작용 | E 입력은 `PlayerInteractor`가 받는다(문·드릴카 선반·리프트 버튼·촛대·종료 단말기). 기존 안내 문구는 임시 IMGUI로 **화면 가운데 근처**에 뜬다(문은 조준점 바로 아래 — `CrosshairUI`, 나머지는 화면 높이 62% — `PlayerInteractor.OnGUI`) | E 입력은 `PlayerInteractor`가 그대로 받아 `PlayerTheft`로 넘긴다. "E 훔치기"는 원문대로 **우측 하단**(`TheftHud`, uGUI)이라 기존 안내와 위치가 다르다 → TH-Q8 |
| 네트워크 권위 | 서버 권위([networking.md](../architecture/networking.md)). 클라이언트는 의도만 RPC로 보낸다 | 클라이언트는 "훔치기" 의도만 보내고, 서버가 대상·거리·상태를 검증해 확정한다. 확정되면 귀중품을 없애고 모든 피어에 반영한다. 여럿이 동시에 누르면 서버가 판단해 한 명만 인정한다(TH-Q3 확정). 돈·정신력 변경은 서버에서만 한다 |
| 폰트 | **Noto Sans KR Bold 폰트 에셋이 저장소에 없다**(2026-11-12 검색). 지금 HUD는 IMGUI와 기본 폰트다 | **[TEMP]** 기본 폰트 굵게로 그린다. Noto Sans KR Bold(라이선스 OFL)를 들여오면 `TheftHud`에 넣는다 |
| 맵·가구 | 귀중품 배치와 숨김 기믹은 레벨 디자인 문서를 기다린다. 침실 가구는 서버가 `Room_Presets`를 `RoomSlots`로 옮겨 채운다 → [map-generation.md](../architecture/map-generation.md) | 귀중품이 든 가구를 옮기거나 던지거나 분해할 때의 처리가 필요하다 → TH-Q4 |
| 귀신 | [ghost-base.md §4](ghost-base.md)의 설계 맥락표에 "상호작용 재물 탐색·절도"(행동·학습 목표)와 "재물 파손으로 인한 보상 손실"(귀신 개입 문제)이 있다 | 재물 파손 규칙은 도둑질 원문에 없다 → TH-Q9 |

## 6. 원문 정합성 메모

1. **예시 가격 `+ 20$`는 정신력 금액표(2·3·5·10$)에 없다.** 예시 이미지가 다른 게임 화면이라 생긴 값으로 보이지만, 정신력 문서는
   "표가 전체 금액 체계"라고 확정했다. 귀중품 가격이 이 4종뿐인지 확인이 필요하다 → TH-Q1.
2. 예시 이미지 ②·③ 오른쪽 아래의 안내 문구 **"E 훔치다"는 다른 게임의 UI**다. 규칙(TH-1)과 배치 이미지 ④는 **"E 훔치기"** 라서 이쪽을 따른다.
3. 원문이 인용한 「정신력 시스템 기획서」 목차 3-2-1은 이 저장소의 [sanity-system.md §4.1](sanity-system.md)이고 수치가 같다.
4. "+ n$" 위치의 61px는 기준 해상도가 적혀 있지 않다(§4.2) → TH-Q7.
